# 주간 업데이트 런북 — 살아 있는 책 유지하기

목표 요구사항: "클로드 코드 최신 업데이트 내용과 변경 내용을 반영, 일주일
간격으로 될 수 있도록 구성." 이 폴더가 그 구성이다.

두 권을 매주 최신 Claude Code에 맞춘다. 사실의 단일 출처는 저장소의
`manuals/manifest.json`(주간 갱신되는 가이드북 자산)과 최근 글이다. 책은 그
자산의 변경분을 따라가기만 하면 된다.

## 주기

- **매주 1회**(월요일 권장). 소요 15~40분.
- 새 manifest 버전이 없으면 그 주는 "변경 없음"만 기록하고 끝낸다.

## 절차 (사람 또는 Claude 세션이 수행)

1. **신버전 감지**
   - `bash books/weekly/update-runbook.sh` 실행.
   - 스크립트가 현재 manifest 버전과 책의 "기준 버전"을 비교해, 바뀌었으면
     `books/weekly/pending/` 에 그 주의 작업 파일을 만든다.

2. **변경분 추출(diff)**
   - 이전 기준 버전 대비 새로 생기거나 바뀐 섹션을 추린다.
   - 신규 기능(예: 새 슬래시 명령, 새 도구, 도입 시점 표기가 붙은 항목)에
     특히 주목.

3. **영향 장 매핑**
   - 각 outline.md의 "원천 자산 매핑"으로 어느 장이 영향받는지 찾는다.
   - 초급(Vol.1)은 안정된 기본만 반영 — 실험적/고급 신기능은 보통 Vol.2로.
   - 신기능이 중·고급이면 Vol.2의 해당 부에 반영하거나 4-4류 '최신' 장에 추가.

4. **본문 반영 (스킬 사용)**
   - 새 절이 필요하면 `outline-planner` 절차로 자리부터 잡는다.
   - 초안 작성 후 `humanizer`로 문체 교정 + 사실 보존 체크.

5. **버전 배지 갱신**
   - 두 outline.md와 각 manuscript 서문의 "기준 버전 vYYYY.WW"를 새 값으로.

6. **이력 기록**
   - `books/progress/04-changelog.md`에 무엇을 왜 바꿨는지 요약.
   - 완료한 주차 작업 파일을 `pending/` → `done/`으로 이동.

7. **커밋·푸시**
   - `docs(books): 주간 반영 vYYYY.WW` 형식으로 커밋.

## 자동화 옵션

세 가지 중 환경에 맞게 고른다.

- **A. Claude Code `/loop`** (세션 상주 시): `/loop 7d "books/weekly/README.md
  절차대로 이번 주 반영을 수행하라"` — 가장 손이 덜 간다.
- **B. cron / CI**: 매주 월요일 이 런북을 수행하는 잡 등록. 저장소가 이미
  주간 커밋 리듬(`Update: ...`)을 가지므로 동일 파이프라인에 끼우기 좋다.
- **C. 수동**: 매주 위 7단계를 직접. 스크립트가 1·5·6을 거든다.

> 이 원격 환경은 일시적이라, **갱신을 굴리는 주체는 커밋된 이 런북·스크립트**다.
> 세션이 바뀌어도 절차가 저장소에 남아 누구든(사람·Claude) 이어서 한다.

## 디렉터리

```
weekly/
├─ README.md            ← 이 파일(절차)
├─ update-runbook.sh    ← 감지·스캐폴드 보조 스크립트
├─ pending/             ← 처리 대기 중인 주차 작업
└─ done/                ← 완료된 주차 기록(감사 추적)
```
