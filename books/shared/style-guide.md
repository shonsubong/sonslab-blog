# 스타일 가이드 (Humanizer 기준)

두 권의 모든 원고가 한 사람의 목소리로 읽히게 하는 규칙. `humanizer` 스킬의
'제거 대상'을 프로젝트 표기로 고정한 것이다. 충돌 시 **정확성 > 자연스러움 >
일관성** 순으로 판단한다.

## 1. 목소리

- **저자는 한 사람.** 독자에게 직접 말한다("~해 보자", "막히면 이렇게").
  "우리는/여러분께서는"의 막연한 복수는 피한다.
- **자신 있게 단정.** "~할 수 있을 것 같습니다" → "~된다". 단서는 진짜
  필요할 때만.
- **존댓말 기조, 군더더기 없는 해요체.** 초급(1권)은 다정하게, 중·고급(2권)은
  담백하게. 단, 두 권 모두 같은 사람이 쓴 느낌은 유지.

## 2. 금지·주의 표현

| 쓰지 말 것 | 대신 |
|------------|------|
| ~에 있어서, ~을 통하여 | ~에서, ~로 |
| ~라고 할 수 있습니다 | ~다 (단정) |
| ~하는 것이 중요합니다 | 왜 중요한지를 보여라 |
| 강력한, 혁신적인, 손쉽게 | 구체적 수치·예시로 |
| 단 몇 번의 클릭만으로 | 실제 명령/단계로 |
| 살펴보겠습니다(문단마다) | 예고 없이 바로 본론 |
| 즉,/다시 말해/결론적으로 (남발) | 한 번만, 꼭 필요할 때 |

## 3. 리듬

- 긴 문장 뒤 짧은 문장으로 끊는다.
- 한 문단은 3~5문장. 개념 하나당 한 문단.
- 불릿 어미를 통째로 똑같이 맞추지 않는다(기계 느낌 방지).

## 4. 기술 표기

- 제품/기능명은 영문 원형 유지: Claude Code, MCP, CLAUDE.md, Hooks, Skills,
  Subagents, Agent SDK, Plan 모드, Worktree.
- 명령·코드·파일명은 백틱: `claude`, `/goal`, `git commit`.
- 한글 조사와 영문 사이는 자연스럽게: "MCP를", "CLAUDE.md에".
- 용어 한·영 표기는 `glossary.md`를 단일 출처로 따른다.

## 5. 코드·실습 블록 규칙

- 코드 블록 안 텍스트는 Humanizer 교정 대상에서 **제외**(원문 보존).
- 실습은 [무엇을 할지 → 입력할 명령/프롬프트 → 기대 결과 → 막히면] 순서.
- 버전 의존 기능에는 "(vYYYY.WW 기준)" 또는 도입 시점 표기.
