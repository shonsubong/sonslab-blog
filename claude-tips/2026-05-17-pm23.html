/mcp 한 줄로 지금 붙어 있는 MCP 서버와 도구를 한눈에 본다

한 줄 요약

여러 MCP 서버를 동시에 붙여 쓸 때, 지금 어떤 서버가 살아 있고 어떤 도구가 노출됐는지 가장 빠르게 확인하는 슬래시 명령이다. "분명 연결했는데 도구를 못 찾는다" 싶을 때 가장 먼저 두드려야 할 곳이다.

상황

GitHub·Slack·Sentry·사내용 등 MCP 서버를 두세 개 이상 등록해 두고 작업하다 보면 "왜 그 도구를 못 부르지" 하는 순간이 자주 온다. 원인은 보통 단순하다. 서버 프로세스가 시작 단계에서 죽었거나, 전역 settings와 프로젝트 .mcp.json이 충돌하면서 한쪽이 가려졌거나, 도구 이름이 내가 기억하는 것과 미세하게 다르거나. 추측으로 시간을 태우지 말고 한 줄로 상태부터 본다.

방법

세션 안에서 /mcp만 친다.

> /mcp

화면에는 현재 등록된 MCP 서버 목록과 각 서버의 연결 상태(connected · failed · loading), 그리고 노출 중인 도구 수가 줄지어 표시된다. 서버를 하나 골라 들어가면 그 서버가 광고하는 도구 이름과 인수 스키마까지 펼쳐 볼 수 있다. 실패 상태라면 마지막 오류 메시지를 같이 보여주기 때문에 환경변수 누락이나 토큰 만료 같은 흔한 원인을 자리에서 잡아낸다.

설정 자체는 다른 곳에서 한다. 전역은 ~/.claude/settings.json, 프로젝트 단위는 저장소 루트의 .mcp.json, 또는 CLI 서브명령 claude mcp add <이름> <명령>이다. /mcp는 그 결과만 들여다보는 진단창이라고 생각하면 된다.

주의·한계

연결된 서버와 도구가 많을수록 시스템 프롬프트가 길어져 컨텍스트를 갉아먹는다. 한 프로젝트에서 정말 자주 쓰는 서버만 켜두고, 가끔 쓰는 것은 필요할 때만 붙이는 편이 토큰 측면에서도 응답 품질 측면에서도 이득이다. 또 /mcp 화면은 호출 시점의 스냅샷이라 서버가 도중에 죽거나 재연결되면 다시 명령을 입력해야 최신 상태가 보인다. 끝으로, 회사 자산이 묶인 MCP는 사내망에서만 접근 가능한 경우가 있으니 집에서 띄울 때는 개인용 토큰·개인 워크스페이스 기준으로 등록해 둔다.
