Stop hook — 다 됐다는 말 뒤에서 테스트를 돌려 아니면 되돌려보낸다

심야 팁 2026년 07월 11일 (토) · 23:44 · 3분 읽기
목차
  • 설정
  • 무한 루프가 진짜 위험하다

"수정 완료했습니다. 테스트도 통과할 겁니다." 이 문장을 몇 번 믿었다가 몇 번 데였다. 통과할 거라는 말은 통과했다는 말이 아니다. 결국 매번 내가 손으로 pytest를 치고, 빨간 줄을 복사해서 다시 붙여넣는 왕복이 반복된다.

이 왕복을 없애는 자리가 Stop hook이다. Claude가 한 턴을 마치고 입력창을 나에게 돌려주기 직전에 스크립트를 실행할 수 있고, 그 스크립트가 {"decision": "block", "reason": "..."}을 내보내면 대화가 끝나지 않고 그 이유가 Claude에게 전달된다. 테스트가 깨졌다는 사실을 내가 알려주는 대신, 훅이 알려주는 것이다.

설정

.claude/settings.json:

{
  "hooks": {
    "Stop": [
      { "hooks": [{ "type": "command", "command": ".claude/hooks/verify.sh" }] }
    ]
  }
}

.claude/hooks/verify.sh:

#!/usr/bin/env bash
input=$(cat)

# 훅 때문에 이미 한 번 되돌아온 턴이면 다시 막지 않는다
if [ "$(jq -r '.stop_hook_active' <<< "$input")" = "true" ]; then
  exit 0
fi

if out=$(pytest -q 2>&1); then
  exit 0
fi

jq -n --arg r "테스트가 실패했다. 아래를 고치고 다시 확인한다:
$out" '{decision: "block", reason: $r}'

훅 입력은 stdin으로 들어오는 JSON이고, session_id·transcript_path 같은 공통 필드와 함께 stop_hook_active, last_assistant_message가 담긴다.

무한 루프가 진짜 위험하다

Stop hook은 스스로를 다시 부를 수 있는 유일한 종류의 훅이다. 막았다 → Claude가 고친다 → 다시 끝낸다 → 훅이 또 돈다. 고쳐지지 않는 실패가 하나라도 있으면 이 고리가 끝없이 돈다. 위 스크립트의 stop_hook_active 검사가 그 안전핀이고, 이걸 빼면 토큰이 밤새 소모될 수 있다. 한 번만 되돌려보내고, 그래도 실패하면 사람에게 넘긴다.

전체 테스트를 붙이면 턴마다 수십 초씩 붙는다. 문서만 고친 턴에도 똑같이 돈다. 변경 파일을 보고 관련 테스트만 고르거나, 린트·타입 검사처럼 몇 초 안에 끝나는 검사부터 붙이는 편이 낫다. 실패 출력을 통째로 reason에 넣으면 컨텍스트가 순식간에 불어나므로 마지막 30줄 정도로 잘라 넘긴다.

서브에이전트에도 같은 걸 걸 수 있다. 서브에이전트 정의 안에 쓴 Stop 훅은 SubagentStop으로 자동 변환된다. 조사·리서치용 에이전트에는 굳이 필요 없지만, 코드를 고치는 에이전트라면 메인 대화로 돌아오기 전에 한 번 걸러주는 값이 있다.

막지 않고 정보만 전달하고 싶을 때는 decision 대신 hookSpecificOutput.additionalContext를 쓴다. 대화는 정상적으로 끝나되 Claude가 그 내용을 알게 된다. 실패를 막는 쪽과 알려만 주는 쪽, 어느 쪽이 맞는지는 프로젝트가 얼마나 자주 빨간 줄을 내느냐에 달렸다. (Claude Code Docs — Hooks reference)
