--add-dir로 두 저장소를 한 세션에 끌어다 묶는다

한 줄 요약

Claude Code 세션은 기본적으로 시작한 디렉터리(cwd) 안만 읽고 쓴다. --add-dir로 시작 시점에, 혹은 세션 도중 /add-dir로 다른 폴더를 끼워 넣으면 흩어진 두 저장소를 한 세션에서 동시에 다룬다. 세션을 둘로 띄워 결과를 손으로 옮겨 붙이며 컨텍스트를 두 번 쌓는 동작이 사라진다.

어떤 상황에서 쓰나

블로그 본문 저장소와 빌드·배포 스크립트가 모인 보조 저장소가 따로 있을 때, 두 쪽을 동시에 만지면서 한쪽 변경이 다른 쪽 스크립트와 잘 맞는지 즉시 확인하고 싶을 때가 잦다. 세션을 두 개로 띄우면 컨텍스트가 둘로 갈리고, 한쪽에서 얻은 결론을 다른 쪽으로 옮길 때 늘 어긋난다.

git worktree로 같은 저장소의 두 갈래를 비교할 때도 효과가 크다. 한쪽 트리에서 작업 중인 세션에 다른 트리를 add-dir로 붙이면, 같은 파일의 두 버전을 한 자리에서 비교하고 옮긴다.

실제 사용법

세션을 띄울 때는 한 줄로 끝난다. 경로를 여러 개 한꺼번에 넘긴다.

cd ~/work/sonslab-blog
claude --add-dir ../sonslab-tools ../shared-notes

세션 도중 추가하고 싶다면 슬래시 명령으로 같은 일을 한다.

> /add-dir ../sonslab-tools

추가된 디렉터리도 @-멘션 자동완성에 잡힌다. 본문에서 @sonslab-tools/build.py 식으로 콕 짚으면 그쪽 파일을 곧장 읽는다. 항상 같은 조합을 쓴다면 ~/.claude/settings.json의 permissions.additionalDirectories에 박아두면 플래그 없이도 자동으로 붙는다.

주의/한계

  • --add-dir는 파일 접근만 열어준다. 추가한 디렉터리의 .claude/agents/나 .claude/commands/는 자동 발견되지 않는다. 서브에이전트와 커스텀 슬래시 명령은 cwd 또는 ~/.claude/ 쪽에 있어야 잡힌다. 예외는 .claude/skills/ 한 곳뿐이다.
  • 추가한 디렉터리의 CLAUDE.md도 기본적으로 로드되지 않는다. 필요하면 환경변수 CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1을 켜고 세션을 띄운다.
  • 디렉터리를 늘릴수록 @-자동완성에 잡히는 파일 수가 늘어 초기 응답이 살짝 느려진다. 정말 같이 만질 폴더만 더한다.
  • 작업 중간에 add-dir로 새 경로를 추가하면, 그 이전 메시지는 새 경로의 존재를 모른 채로 답을 짠 상태로 컨텍스트에 남는다. 가능하면 세션 시작 직후 한 번에 정리해 둔다.
