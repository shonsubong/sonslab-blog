/clear는 사실 새 세션이다 — 이름과 실제가 다른 명령

한 줄 요약

/clear는 이름과 달리 현재 세션 안에서 대화만 지우는 게 아니다. 내부적으로 새 세션 UUID를 만들고 그쪽으로 전환한다. 즉 새 터미널에서 claude를 다시 띄우는 것과 거의 같은 효과다. "둘 중 뭐가 더 깨끗할까"를 고민하는 건 거의 의미가 없다.

어떤 상황에서 쓰나

작업 흐름이 끝났고 다음으로 넘어가고 싶을 때. 컨텍스트가 80%를 넘어 응답이 둔해질 때. 이 두 경우 모두 /clear든 새 세션이든 결과는 같다 — 컨텍스트는 비고, CLAUDE.md는 다시 로딩되고, 디스크 파일은 그대로 남는다.

실제로 뭐가 같고 뭐가 다른가

/clear         새로운 conversationId 부여 → 빈 컨텍스트로 시작
새 세션 (claude)   새로운 conversationId 부여 → 빈 컨텍스트로 시작

같은 점:

  • 둘 다 새로운 conversationId를 받는다 (/clear도 마찬가지다 — GitHub 이슈 #37451·#32871 참고)
  • 둘 다 CLAUDE.md·메모리 파일을 다시 읽어 들인다
  • 둘 다 디스크에 만들어 둔 파일은 건드리지 않는다
  • 둘 다 이전 세션은 디스크에 그대로 남아 claude --resume으로 되살릴 수 있다

차이라고 부를 만한 것:

  • /clear는 키 한 번. 새 세션은 새 셸 창을 띄워야 한다.
  • 새 세션은 셸의 cwd·env가 새로 잡힌다. /clear는 셸 상태를 그대로 둔 채 진행한다.
  • 사용자 인터페이스 측면에서 /clear는 "한 흐름 안에서 정리"처럼 보이게 표시되지만, 내부 저장 구조로는 두 동작이 사실상 같다.

주의/한계

  • /clear로 잃은 대화를 되찾으려면 새 세션이 시작되기 직전의 옛 세션을 claude --resume에서 골라야 한다. 같은 세션 안에서 "방금 누른 /clear 취소" 같은 것은 현재 없다.
  • "/clear가 컨텍스트만 비우고 세션은 유지된다"는 흔한 오해다. 그렇게 동작하지 않는다는 점만 알아두면 디버깅 때 헛고생을 안 한다.
  • 화제가 이어지는데 컨텍스트만 다듬고 싶으면 /clear가 아니라 /compact다. /compact는 진짜로 같은 세션 안에서 직전 대화를 요약해 끼워 넣는다.
