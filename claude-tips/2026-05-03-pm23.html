/context와 /usage로 컨텍스트가 차오르는 순간을 눈으로 본다

한 줄 요약

/context는 지금 컨텍스트 윈도우의 어느 항목이 자리를 얼마나 잡아먹는지 분해해 보여주고, /usage는 이 세션이 누적으로 얼마짜리였는지 알려준다. 둘을 번갈아 보면 /compact나 /clear를 언제 눌러야 할지 감이 잡힌다.

어떤 상황에서 쓰나

긴 작업을 이어가다 보면 응답이 슬슬 둔해지는 순간이 온다. 보통 둘 중 하나다. 컨텍스트 윈도우가 가득 차서 새 토큰을 쥐어짤 자리가 없거나, 5시간 한도를 거의 다 써서 모델이 답을 짧게 끊는 거다. 두 원인을 구분 못 하고 일단 /clear부터 누르면 정작 살아 있어야 할 작업 흐름까지 통째로 사라진다.

/context는 컨텍스트 윈도우의 점유율을, /usage는 누적 사용량을 보여준다. 매번 한 번씩 찍어보면 어느 쪽이 한계인지 1초 안에 답이 나온다.

실제 명령

세션 안에서 그냥 입력한다.

/context

지금 컨텍스트가 무엇으로 채워져 있는지 항목별로 분해해 보여준다. 시스템 프롬프트, MCP 도구 정의, CLAUDE.md, 메시지 히스토리, 도구 결과가 각각 몇 토큰씩 잡고 있는지 한눈에 들어온다. MCP 서버 하나가 토큰 5만을 그냥 깔고 앉아 있는 식의 사고를 발견하기 좋다.

/usage

이 세션의 누적 토큰 소비, 추정 달러 금액, MAX 플랜의 5시간 윈도우 잔량까지 한 화면에 묶어 보여준다. /cost와 /stats는 같은 명령의 별칭이라 어느 쪽을 쳐도 동일한 화면이 뜬다.

판단 기준은 단순하다. /context 점유율이 90%를 넘기면 /compact로 한 번 접는다. /usage의 5시간 잔량이 빨갛게 다 차오르면 잠시 손을 떼고 다음 슬롯을 기다린다. 컨텍스트는 여유 있는데 한도만 빠듯하면 /clear는 오히려 손해다.

주의/한계

  • /usage의 달러 표시는 토큰 수에서 로컬로 추정한 값이다. 실제 청구 금액은 Claude Console — Usage가 정답이다.
  • MAX·Pro 플랜 사용자는 달러 숫자보다 "5시간 윈도우 잔량"이 실질적인 지표다. 정액제라 청구는 어차피 같다.
  • /context는 도구 결과(특히 큰 파일을 통째로 읽었거나 긴 빌드 로그를 받았을 때)가 어디까지 누적됐는지 잘 보여준다. 비대해진 결과 한두 개만 정리하고 싶을 땐 /compact로 전체를 요약하는 것보다 직접 메시지를 잘라내는 편이 정확하다.
  • 명령 이름은 시간이 지나며 통합·재배치되곤 한다. 안 잡히면 /help로 한 번 훑어 현재 세션의 정식 이름을 확인한다.
