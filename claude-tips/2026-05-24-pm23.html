claude -p — 대화창 없이 셸 스크립트 안에서 Claude Code를 돌린다

심야 팁 2026년 05월 24일 (일) · 23:00 · 2분 읽기

매일 똑같은 작업을 Claude Code 대화창에서 손으로 치고 있다면 한 번 멈춰서 짜증을 내볼 만하다. 빌드 로그 요약, PR 변경분 오타 잡기, 블로그 글 다듬기 같은 건 사람이 매번 타이핑할 일이 아니다. -p 플래그 하나만 알면 같은 엔진을 일반 셸 명령처럼 호출하고, 파이프로 입력을 밀어넣고, 결과를 파일로 받을 수 있다.

처음 이 모드가 절실해진 건 매일 밤 도는 블로그 빌드 스크립트에 짧은 요약 단계를 끼우고 싶을 때였다. cron이나 깃 훅 안에서 사람 손 없이 같은 일을 시키려면 대화 모드는 못 쓴다. 그래서 헤드리스가 필요하다.

가장 단순한 모양은 프롬프트를 그대로 인자로 넘기는 것이다.

claude -p "auth 모듈이 하는 일을 요약해줘"

표준입력도 그대로 먹는다. 다른 명령의 출력을 파이프로 흘려보내면 된다.

cat build-error.txt | claude -p '이 빌드 에러의 근본 원인을 짧게 설명해줘' > output.txt

스크립트에서 결과만 깔끔하게 뽑고 싶을 땐 JSON으로 받아 jq로 꺼내는 게 편하다.

claude -p "이 프로젝트 요약" --output-format json | jq -r '.result'

자동화에서 진짜 짜증나는 건 도구 승인 프롬프트다. 한 번이라도 사람 손이 필요해지면 cron이 거기서 멈춘다. --allowedTools로 미리 풀어둔다.

claude -p "테스트 돌리고 실패 고쳐줘" --allowedTools "Bash,Read,Edit"

앞 대화를 이어가야 할 땐 --continue(가장 최근 세션)나 --resume <세션ID>를 붙인다.

여기서 한 가지 함정. 슬래시 명령(/commit 같은 것)과 사용자 스킬은 대화 모드 전용이다. -p로는 못 부르니, 하려는 작업을 그냥 문장으로 풀어 적는다. 파이프 입력은 v2.1.128부터 10MB 상한이 생겨서, 큰 입력은 파일로 저장한 뒤 경로만 프롬프트에 적어 넘기는 편이 안전하다. CI에서 매번 결과가 흔들리는 게 싫다면 --bare를 붙여 로컬 hook·MCP·CLAUDE.md 자동 로딩을 끄고 명시한 플래그만 적용되게 한다.
