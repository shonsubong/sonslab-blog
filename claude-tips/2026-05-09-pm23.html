statusLine 한 줄로 입력창 아래에 내 워크플로 대시보드를 박아둔다

한 줄 요약

Claude Code 입력창 바로 위에는 한 줄짜리 상태 표시줄(statusLine) 슬롯이 있다. settings.json에 짧은 스크립트 한 줄을 등록하면 모델 이름·현재 브랜치·작업 디렉터리 같은, 매번 궁금했던 정보가 매 응답 끝마다 자동으로 갱신된다. /status를 두드리는 동작 자체가 사라진다.

어떤 상황에서 쓰나

세션 도중 "지금 어느 모델로 돌고 있지?", "이 브랜치 맞나?" 같은 질문이 자주 튀어나온다. 그때마다 슬래시 명령을 치면 흐름이 끊긴다. 화면에 늘 보이는 한 줄이 있으면 머리를 입력창에서 떼지 않고 확인할 수 있다.

특히 /model로 모델을 자주 갈아 끼우는 경우 "지금 sonnet인지 opus인지" 헷갈려 비싼 모델로 가벼운 작업을 돌리는 사고를 자주 본다. 한 줄 표시만 있어도 그런 사고가 거의 사라진다. git worktree로 같은 저장소를 두 갈래로 동시에 굴릴 때, 어느 쪽 트리에 붙어 있는지 한눈에 보인다는 점도 의외로 크다.

실제 설정 방법

~/.claude/settings.json(전역) 또는 <repo>/.claude/settings.json(프로젝트)에 다음을 추가한다.

{
  "statusLine": {
    "type": "command",
    "command": "~/bin/claude-status.sh"
  }
}

스크립트는 매 턴 종료 시 호출된다. 표준 입력으로 세션 정보가 JSON으로 들어오고, 표준 출력 한 줄이 그대로 상태 표시줄에 붙는다.

#!/usr/bin/env bash
# ~/bin/claude-status.sh
input=$(cat)
model=$(echo "$input" | jq -r '.model.display_name')
cwd=$(echo "$input"  | jq -r '.workspace.current_dir')
name=$(basename "$cwd")
branch=$(git -C "$cwd" branch --show-current 2>/dev/null)
echo "[$model] $name${branch:+ @$branch}"

실행 권한(chmod +x)을 잊지 말 것. 결과는 입력창 위에 한 줄로 뜬다. 예: [Sonnet 4.6] sonslab-blog @main. 입력 JSON에는 model, workspace, transcript_path, version 같은 필드가 들어있고, 자기 워크플로에 맞춰 어떤 조합이든 한 줄로 만들어두면 된다.

주의/한계

  • 스크립트는 매 턴 끝마다 실행된다. 전체 저장소 grep 같은 무거운 명령은 체감 응답을 늦추니 가볍게 짠다. 100ms 안쪽이 안전선이다.
  • 출력은 한 줄만 사용되고 너무 길면 잘린다. 30~60자가 무난하다.
  • ANSI 색 코드 인식은 터미널·클라이언트 버전에 따라 다르다. 색을 넣는다면 자기 환경에서 한 번 검증한 뒤 박는다.
  • settings.json에 명령 경로를 박으면 다른 머신으로 끌고 갈 때 경로가 깨진다. dotfiles로 같이 관리하거나 $HOME/bin/...처럼 이식 가능한 경로를 쓴다.
  • 사내 토큰·민감 데이터를 표시줄에 노출하지 말 것. 화면 캡처·녹화에 그대로 따라간다.
