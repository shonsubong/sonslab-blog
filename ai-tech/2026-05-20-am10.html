추론 가속의 옆문 — EAGLE-3와 MTP가 만나는 지점

AI 딥다이브 2026년 05월 20일 (수) · 10:00 · 4분 읽기
목차
  • TL;DR
  • 배경 (Why now)
  • 핵심 메커니즘
  • 코드 예시
  • 한계·반론
  • 현직 엔지니어 관점

TL;DR

  • EAGLE-3는 드래프트 헤드 한 개로 LLaMA-3·Vicuna 13B 추론을 4.1~6.5배 끌어올린 2025년 3월 논문.
  • DeepSeek-V3 사전학습에 포함된 MTP 헤드는 추론 시 그대로 드래프트가 돼 SGLang에서 1.8배 처리량.
  • 출력 분포를 안 바꾸지만 배치 32 이상에선 ragged tensor로 가속이 30~40% 깎인다.

배경 (Why now)

양자화·KV 압축이 정점을 찍은 추론 가속의 다음 카드가 Speculative Decoding이다. 작은 드래프트가 토큰 여러 개를 먼저 뽑으면 본 모델이 한 번의 forward로 전체를 검증해, 채택된 만큼 디코딩 step이 준다.

판도가 흔들린 건 두 사건이다. 2025년 3월 EAGLE-3 논문이 1세대가 못 넘던 학습 스케일링 한계를 깼고, DeepSeek-V3의 MTP가 SGLang·TensorRT-LLM의 표준 드래프트로 자리 잡았다. 2026년 3월엔 vLLM도 P-EAGLE 통합으로 B200에서 EAGLE-3 대비 1.05~1.69배 추가 가속을 더했다.

핵심 메커니즘

Target forward 1회 → hidden(저/중/상층)
      ↓
EAGLE-3 Draft Head → 트리 k개 토큰 생성
      ↓
Target forward 1회로 트리 전체 검증
      ↓
채택된 prefix만 commit, 거부 이후 폐기

EAGLE 1세대는 top-layer feature만 받아 다음 feature를 예측했다. EAGLE-3는 feature 대신 토큰을 직접 예측해 학습 스케일링 병목을 풀었고, 저·중·상층 hidden state를 동시에 융합하는 tri-layer fusion을 쓴다. acceptance rate가 EAGLE-2 대비 12~18%포인트 올라가 4~6배 가속의 토대가 된다.

DeepSeek-V3의 MTP는 다음 1~3 토큰을 동시에 예측하는 head를 학습 손실에 끼워 둔다. 추론 시 별도 모델이 필요 없고, acceptance rate 80% 덕에 SGLang+MTP에서 1.8배 처리량이 나온다.

코드 예시

# SGLang에서 EAGLE-3 활성화 (의사코드)
engine = Engine(
    model_path="meta-llama/Llama-3.1-8B-Instruct",
    speculative_algorithm="EAGLE3",
    speculative_draft_model_path="yuhuili/EAGLE3-LLaMA3.1-Instruct-8B",
    speculative_num_steps=5,        # draft 깊이
    speculative_eagle_topk=8,       # 트리 폭
    speculative_num_draft_tokens=64 # 검증할 트리 전체 토큰
)
# 검증은 결정론적 rejection sampling → 출력 분포 불변

추가 비용은 트리 전체 KV cache write뿐이라, acceptance_rate × draft_length가 1을 넘는 순간 wall-clock이 줄어든다.

한계·반론

가속이 깨지는 지점이 분명하다. 배치가 커지면 효과가 죽는다 — SGLang+EAGLE-3는 H100에서 배치 2의 1.81배가 64에서 1.38배로 깎인다. 시퀀스마다 채택 길이가 달라 패딩·재정렬 비용이 배치 32에서 약 40%까지 차오르는 ragged tensor 문제다. draft와 target 분포가 멀어져도 acceptance rate가 무너지고, MTP는 학습에 손실 추가 비용을 치러야 해 오픈 가중치 모델엔 사후 적용이 어렵다.

현직 엔지니어 관점

EAGLE 계열의 부상은 추론 가속의 무게중심이 메모리에서 컴퓨트로 다시 옮겨가는 신호다. 양자화·KV 압축이 HBM 대역폭을 아끼는 카드였다면, EAGLE-3·MTP는 검증 forward에서 트리 전체를 한 번에 처리해 GPU FLOPS 여유분을 태운다. FP4 텐서코어가 폭증한 B200·MI355X에서 더 잘 맞는 그림이다. 반대로 모바일 NPU는 컴퓨트 단가가 비싸 트리 폭을 좁히고 draft length를 짧게 가는 튜닝이 필요하다 — 엣지에선 MTP-1 같은 짧은 드래프트가 훨씬 안정적이다.
