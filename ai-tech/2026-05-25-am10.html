어텐션마다 오차를 증명한다 — KV 캐시 양자화에 '인증서'를 붙이는 법

AI 딥다이브 2026년 05월 25일 (월) · 10:00 · 5분 읽기

TL;DR

  • KV 캐시를 INT8·INT4로 압축하되, 어텐션 한 번마다 오차 상한을 실시간으로 계산해 허용치를 넘으면 FP16 원본으로 정확히 되돌리는 구조가 나왔다 (Calver — Runtime-Certified Bounded-Error Quantized Attention).
  • 핵심은 속도가 아니라 "평균적으로 괜찮다"를 "이번 계산이 한계 안에 있음을 증명한다"로 바꾼 발상이다.
  • 품질 보장이 깐깐하게 요구되는 온디바이스·엣지 추론에서 공격적 압축을 안전하게 켜는 길을 연다.

배경 (Why now)

어제 다룬 NVFP4가 사전학습의 비트 폭을 4비트로 끌어내린 이야기였다면, 이번 5월 20일 arXiv 논문은 정반대 지점, 즉 추론 시점 KV 캐시를 겨냥한다. 롱컨텍스트가 길어질수록 모델 가중치보다 KV 캐시가 메모리와 대역폭을 더 많이 잡아먹는다는 사실은 이제 상식이다. 그래서 KV 양자화는 지난 두 달 사이 가장 붐비는 골목이 됐다. 온디바이스용 토큰별 적응형 양자화(Don't Waste Bits!)도, 캐시를 디스크에 4비트로 영속화하는 시도(Agent Memory Below the Prompt)도 같은 흐름이다.

문제는 검증 방식이었다. 기존 KV 양자화는 PG-19·RULER 같은 벤치마크 평균 점수로만 "쓸 만하다"를 입증해 왔다. 평균이 멀쩡해도 특정 헤드·특정 토큰에서 분포가 무너지는 치명적 실패는 평균에 묻힌다. 이번 논문이 제어이론 분류(eess.SY)를 달고 나온 이유가 여기 있다. 양자화를 "고정된 근사"가 아니라 "런타임에 검증되는 계산"으로 다시 정의한다.

핵심 메커니즘

구조는 3단 메모리다. GPU에는 INT8 키와 INT4 값을 두고, 시스템 RAM에는 FP16 원본을 폴백용으로 남긴다. 어텐션 출력 오차를 두 항으로 분해해 헤드별·스텝별 상한을 온라인으로 계산한다. ① 키 양자화가 점수 분포를 얼마나 비트는가, ② 값 복원이 얼마나 어긋나는가. 둘의 합이 허용치를 넘으면 정밀도를 한 단계 올리고, 그래도 넘으면 RAM의 FP16로 정확히 복구한다.

[디코드 step t]
   Q_t ──► [INT8 Key] (GPU) ──► 점수 s
                 │  오차항 ① : 점수 분포 왜곡 상한
                 ▼
              softmax → p
                 │
   p ──► [INT4 Value] (GPU) ──► 출력 o
                 │  오차항 ② : 값 복원 오차 상한
                 ▼
        ① + ② ≤ τ ?
          ├─ 예    → o 그대로 (압축 유지)
          └─ 아니오 → 정밀도 ↑ → 그래도 초과면
                      [FP16 원본] (시스템 RAM)에서 정확 복구

코드 / 수식 예시

스텝마다 도는 의사코드는 이렇게 단순하다. 핵심은 출력을 내기 전에 "이 출력이 FP16 기준으로 얼마나 벗어날 수 있는가"를 먼저 한계로 못 박는 것이다.

# 디코드 1스텝: 헤드별 '인증된' 어텐션
def certified_attention(q, K_int8, V_int4, V_fp16_ram, tau):
    s     = q @ dequant(K_int8).T        # 저정밀 점수
    e_key = key_score_bound(q, K_int8)   # 오차항 ① 상한
    p     = softmax(s)
    o     = p @ dequant(V_int4)          # 저정밀 출력
    e_val = value_recon_bound(p, V_int4) # 오차항 ② 상한
    if e_key + e_val <= tau:
        return o                         # 인증 통과 → 압축 유지
    return p @ V_fp16_ram                # 폴백: RAM 원본으로 정확 복구

tau를 키우면 압축률이 오르고, 줄이면 품질 보장이 빡빡해진다. 이 한 줄이 곧 운영자가 손에 쥐는 다이얼이다.

한계·반론

인증은 어디까지나 국소적(local)이다. 헤드별·스텝별로 "이 어텐션은 FP16 대비 한계 안"임을 보장할 뿐, 모델 전체 출력의 정답성을 증명하지는 않는다. 둘째, FP16 원본을 RAM에 들고 있어야 하므로 총 메모리는 줄지 않는다. 절약되는 건 GPU 메모리이고, 대신 폴백마다 RAM↔GPU 전송이 끼어든다. 셋째, 짧은 컨텍스트의 값 민감 작업에서는 압축과 충실도가 맞바꿈으로 드러난다. 논문 스스로 "속도 향상이 목표가 아니다"라고 밝힌 만큼, 처리량 이득을 노리고 들어오면 실망할 수 있다.

현직 엔지니어 관점

현장에서 양자화가 막히는 지점은 늘 "평균은 좋은데 드물게 터진다"였다. 안전이 걸린 인지·계측 파이프라인일수록 평균 통과는 근거가 못 된다. 이 논문의 값어치는 압축률이 아니라 건별 보장이라는 계약 형태에 있다. 적응형 양자화 계보 위에 '증명서'를 얹은 셈이다. 반도체 관점에선 INT4 역양자화 비용과 폴백이 유발하는 메모리 트래픽이 눈에 띈다. GPU 메모리는 아꼈는데 통합 메모리·인터커넥트 대역폭으로 비용이 옮겨가면 엣지 SoC에선 오히려 손해일 수 있다. 결국 tau를 칩 메모리 계층에 맞춰 어떻게 잡느냐, 그리고 폴백 빈도가 낮게 유지되는 워크로드인지가 관건이다 — 이 부분은 실제 측정으로 확인이 필요하다.
