로봇 관절각도 토큰이다 — Cosmos 3가 추론탑과 생성탑을 하나로 붙인 방법

AI 딥다이브 2026년 06월 18일 (목) · 10:00 · 6분 읽기
목차

  • 배경 (Why now)
  • 핵심 메커니즘

TL;DR

  • NVIDIA가 6월 1일 공개한 Cosmos 3는 텍스트·이미지·비디오·오디오·행동을 한 모델에서 이해하고 생성하는 옴니 월드모델이다. 자기회귀(AR) 추론탑과 디퓨전 생성탑을 한 백본 안에 묶은 Mixture-of-Transformers(MoT) 구조다.
  • 그동안 인지(Reason)·예측(Predict)·정책(Policy)으로 쪼개 돌리던 모델을 단일 forward pass로 합쳤고, 무엇보다 행동(action)을 하나의 모달리티로 승격시켜 토큰으로 다룬다.
  • Nano는 8B+8B로 워크스테이션급 GPU(RTX PRO 6000)에서 돌아가며, 로봇 관절각·그리퍼 위치·궤적을 직접 생성해 합성 학습 데이터와 정책 학습에 쓴다.

배경 (Why now)

젠슨 황이 COMPUTEX 2026에서 직접 들고 나온 모델이다. 물리 AI(로봇·자율주행) 쪽은 학습 데이터가 늘 모자라고, 시뮬레이션 스택이 파편화돼 있다는 게 오래된 숙제였다. 이전 Cosmos는 세계 생성용 Predict, 조건부 생성용 Transfer, 장면 이해용 Reason, 정책용 Policy로 네 갈래로 나뉘어 있었고, 개발자는 모델과 추론 파이프라인을 갈아끼우며 작업해야 했다 (NVIDIA — Cosmos 3 HF 블로그). 5월 Cosmos Predict 2.5 LoRA 파인튜닝, Nemotron 디퓨전 언어모델 같은 흐름이 깔린 뒤, 6월 1일 오픈웨이트 러시(MiniMax M3 등)와 같은 주에 통합판이 나왔다. 직전 일주일치 딥다이브가 다룬 텍스트 확산이나 인코더프리 멀티모달과는 결이 다른, "행동까지 생성하는 단일 모델"이라는 점이 새롭다.

핵심 메커니즘

핵심은 두 탑(two-tower) 구조다. 입력 시퀀스를 둘로 쪼갠다. 추론·이해를 맡는 AR 서브시퀀스는 causal self-attention으로 다음 토큰을 예측하고, 생성을 맡는 DM 서브시퀀스는 반복 디노이징으로 이미지·비디오·오디오·행동을 만든다. 두 종류 토큰은 각 레이어 안에서 별도 파라미터셋을 쓰되, joint attention으로 서로를 본다. 이 덕분에 모델 한 채가 구조 변경 없이 VLM, 비디오 생성기, 순/역동역학 모델, 로봇 정책으로 모드만 바꿔 동작한다 (NVIDIA — Cosmos 3 기술 보고서). 모달리티별로 인코더가 따로 붙는다. 시각 이해는 ViT, 시각·오디오 생성은 VAE, 행동은 도메인 인식 벡터로 인코딩한 뒤 공유 표현공간으로 사영한다.

[텍스트][이미지][비디오][오디오][행동]
   │  ViT / VAE / 액션벡터 → 공유 표현공간
   ▼
 ┌────────── MoT 레이어 × N ──────────┐
 │  AR 토큰  ─┐                        │
 │ (추론·이해) │  joint attention       │
 │  DM 토큰  ─┘ (파라미터셋은 분리)      │
 │ (생성·디노이징)                       │
 └─────────────────────────────────────┘
   ▼               ▼
 [텍스트 답]   [비디오 / 행동 토큰]

코드 예시

Diffusers에 Cosmos3OmniPipeline으로 통합돼 있어, 생성 쪽은 익숙한 파이프라인 몇 줄로 돌릴 수 있다.

import torch
from diffusers import Cosmos3OmniPipeline

pipe = Cosmos3OmniPipeline.from_pretrained(
    "nvidia/Cosmos3-Nano", torch_dtype=torch.bfloat16, device_map="cuda"
)

# 같은 모델이 입력·출력 조합만 바꾸면 역할이 달라진다
#  (행동 + 이미지 + 텍스트) → 비디오   : 순동역학(forward dynamics)
#  (텍스트 + 비디오)        → 행동토큰 : 역동역학(inverse dynamics)
#  (이미지 + 텍스트)        → 비디오+행동: 로봇 정책(policy)
result = pipe(prompt="로봇 팔이 보라색 물체 왼쪽으로 냄비를 옮긴다",
              num_frames=1, height=720, width=1280)
result.video[0].save("cosmos3.jpg", format="JPEG", quality=85)

한계·반론

"8B"라는 숫자에 속으면 안 된다. Nano는 추론탑 8B와 생성탑 8B를 합친 구조라 HF 카드에는 16B로, Super는 65B로 표기된다. 워크스테이션급에서 돈다지만 실제 메모리 풋프린트는 라벨의 두 배다. 더 큰 문제는 지연이다. 디퓨전 생성은 반복 디노이징이라 수십~수백 Hz로 도는 실시간 로봇 제어 루프에 그대로 끼우기엔 무겁고, 저지연용 Edge 버전은 아직 개발 중이다 (Axios — Nvidia Cosmos 3). 생성된 월드 비디오의 물리적 타당성을 평가할 척도가 빈약하다는 점, 합성 데이터로 학습한 정책이 실제로 전이될 때 생기는 sim2real 격차도 남는다. NVIDIA 스스로 특정 로봇·환경에는 post-training이 필요하다고 못 박았으니, "한 모델로 끝"이라는 그림은 마케팅에 가깝다.

현직 엔지니어 관점

두 탑이 한 칩에서 동시에 도는 그림을 메모리 관점에서 보면 머리가 아프다. 추론탑은 작은 KV 캐시에 causal attention이라 대역폭보다 지연 민감이고, 생성탑은 디노이징 배치라 한 번에 큰 텐서를 굴린다. 두 워크로드의 메모리 접근 패턴이 정반대인데 같은 HBM을 나눠 쓰면 대역폭 스케줄링이 곧 병목이 된다. 온디바이스로 내려보내려면 16B를 워크스테이션이 아니라 로봇 엣지(Jetson급)에 올려야 하는데, 그건 양자화와 Edge 전용 탑 분리 없이는 어렵다. 검사 장비 영상 도메인에서도 "이해와 생성을 한 모델로 묶는다"는 방향은 분명 매력적이지만, 실시간성과 결정론적 재현이 더 중요한 현장에선 디퓨전 생성탑을 그대로 쓰긴 어렵다(이 부분은 실제 적용 시 추가 확인 필요).
