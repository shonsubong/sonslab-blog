가치 모델을 버린 강화학습 — GRPO·RLVR가 추론 모델을 만든 길

AI 딥다이브 2026년 05월 14일 (목) · 10:00 · 5분 읽기
목차

  • 배경 (Why now)

TL;DR

  • GRPO(Group Relative Policy Optimization)는 PPO의 가치 모델을 그룹 내 보상 정규화로 갈아 끼웠다. 가중치를 한 벌 덜고 들어간다.
  • RLVR(검증 가능 보상)은 수학 정답 일치·단위 테스트 통과처럼 결정적 신호만 보상으로 쓴다. 보상 모델 없이 보상 해킹을 막는다.
  • 2025년 1월 DeepSeek-R1 이후 1년 반, Qwen3·Llama4 reasoning 변종·오픈소스 reproduce 라인까지 거의 같은 처방으로 수렴했다. 학습 메모리는 줄었지만 rollout이 새 병목이 됐다.

배경 (Why now)

R1이 공개된 2025년 1월부터 후학습 RL 풍경이 다시 그려졌다. PPO 기반 RLHF 시대엔 정책·가치 모델·보상 모델 세 벌이 메모리에 떠 있었는데, GRPO와 RLVR을 같이 쓰면 그중 둘이 사라진다.

지난 몇 주가 변곡점이었다. 4월 말 Qwen3-Thinking 후속 체크포인트가 공개되며 RLVR 레시피를 한 번 더 굳혔고, 5월 들어 OpenR1·Logic-RL 같은 reproduce 결과가 32B 급에서 R1-distill에 근접한 수치를 냈다. 1년 반 만에 PPO+RM 골격이 사실상 후순위로 밀렸다.

핵심 메커니즘

[PPO 시대]                          [GRPO + RLVR]
policy π_θ ──┐                      policy π_θ ──┐
value  V_φ ──┼─ advantage A_t       group rollout {o_1..o_G}
reward RM_ψ ─┘                      verifier r_i ∈ {0,1}
                                    A_i = (r_i - μ) / σ

PPO의 advantage는 가치 함수 차이로 계산한다. $A_t = r_t + \gamma V(s_{t+1}) - V(s_t)$. 정책과 비슷한 크기의 $V_\phi$가 같이 학습된다. GRPO는 같은 프롬프트 $q$에 대해 정책에서 $G$개 응답 ${o_1, \dots, o_G}$를 뽑은 뒤, 각 응답의 advantage를 그룹 내 정규화로 대체한다.

$$A_i = \frac{r_i - \mathrm{mean}(r_{1..G})}{\mathrm{std}(r_{1..G})}$$

평균을 baseline으로 쓰니 가치 모델이 사라진다. RLVR은 보상 $r_i$ 자체를 RM이 아니라 결정적 검증기가 매긴다. 수학이면 \boxed{...} 안의 답을 정답과 일치 검사하고, 코드면 unit test를 돌려 전부 통과해야 1점이다. RM이 없으니 RM 과적합으로 인한 reward hacking도 같이 사라진다 — 대신 검증기가 있는 도메인으로 적용 범위가 좁아진다.

코드 / 의사코드 예시

# GRPO 한 스텝 (의사코드, KL constraint 포함)
def grpo_step(prompts, policy, ref_policy, verifier, G=16, eps=0.2, beta=0.01):
    loss = 0.0
    for q in prompts:
        # 1) rollout: 같은 프롬프트로 G개 응답 샘플링
        outs   = [policy.generate(q) for _ in range(G)]
        # 2) 결정적 보상 (RLVR)
        rewards = [verifier(q, o) for o in outs]          # ∈ {0, 1}
        # 3) 그룹 정규화 advantage
        mu, sd  = mean(rewards), std(rewards) + 1e-6
        adv     = [(r - mu) / sd for r in rewards]
        # 4) PPO-style clipped surrogate + KL to ref
        for o, A in zip(outs, adv):
            logp_new = policy.logprob(o)
            logp_old = policy.logprob(o, no_grad=True)
            ratio    = exp(logp_new - logp_old)
            surr     = minimum(ratio * A,
                               clip(ratio, 1 - eps, 1 + eps) * A)
            kl       = logp_new - ref_policy.logprob(o, no_grad=True)
            loss    -= (surr - beta * kl).mean()
    return loss / len(prompts)

핵심은 두 줄이다. adv = (r - mu) / sd이 가치 모델을 통째로 대체하고, verifier가 보상 모델을 대체한다. 나머지 PPO 절차(clipped ratio, KL to reference)는 그대로다.

한계·반론

먼저 도메인 한계. 검증기가 있는 영역, 즉 수학·코드·정답 단답형 추론 외엔 RLVR이 그대로 쓰이지 않는다. 글쓰기·창작·요약은 여전히 RM이나 사람 라벨이 필요하다. 둘째, rollout 비용. $G=16{\sim}64$ 샘플링이 학습 한 스텝당 수십 번 추론을 돌리니, 학습 GPU 위에 vLLM·SGLang을 같이 띄우는 구조가 표준이 됐고 학습 효율이 rollout 처리량에 묶인다. 셋째, 길이 폭증과 collapse. KL constraint를 너무 풀면 출력이 수천 토큰으로 폭주하면서 품질이 무너지는 구간이 있다 — 길이 패널티로 막지만 hyperparameter 민감하다. 마지막으로 벤치마크 함정 — AIME·MATH·HumanEval처럼 검증 가능한 벤치마크 점수는 잘 오르지만, 그 분포에 정렬돼 있다는 점을 잊으면 안 된다.

현직 엔지니어 관점 한 문단

가치 모델·보상 모델 두 벌이 빠지면 동일 GPU에서 정책의 batch 크기를 거의 두 배로 잡을 수 있다. 80GB H100·B200 기준으로 32B 모델 RL 학습이 노드 하나 안에서 돌게 된 게 결정적이다. 대신 rollout이 새 비용 항목이 됐다 — 학습 클러스터의 GPU 절반이 추론 엔진을 운영하는 그림이 흔해졌고, KV 캐시 메모리·인터커넥트가 학습보다 추론 쪽 패턴에 가깝게 튜닝된다. 온디바이스 관점에선 검증기만 도메인에 맞게 짜면 작은 모델(1.5B~7B)도 같은 처방으로 분야별 추론 능력을 얹을 수 있다는 점이 매력적이다. NPU에서 돌릴 도메인 특화 코더·정리 도구를 만들 때, 사람 라벨이 아니라 단위 테스트 셋과 정답 셋만 있으면 후학습이 가능해진 셈이다.
