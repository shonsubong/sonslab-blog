생각 토큰을 30% 줄였다 — Kimi K2.7-Code가 '덜 생각하게' 만든 방법

AI 딥다이브 2026년 06월 14일 (일) · 10:00 · 5분 읽기

TL;DR

  • Moonshot AI가 6월 11~12일 공개한 Kimi K2.7-Code는 같은 1조 파라미터 MoE(토큰당 활성 32B)를 쓰면서 "생각 토큰"을 K2.6 대비 약 30% 줄였다.
  • 핵심은 모델을 키운 게 아니라, 추론 사슬의 '과잉 생각(overthinking)'을 길이 보상형 강화학습으로 다듬은 데 있다.
  • 에이전트 코딩처럼 수백~수천 스텝을 도는 작업에서 생각 토큰 감소는 출력 비용과 지연을 함께 줄여준다.

배경 — 왜 지금

지난주는 코딩 모델 발표가 몰린 주였다. Cohere North Mini Code, Moonshot Kimi Work에 이어 11~12일 K2.7-Code가 가중치까지 공개되며 화제를 모았다. K2.7-Code는 K2.6과 동일한 골격(MLA 어텐션, SwiGLU, 384개 전문가 중 토큰당 8개 활성, 256K 컨텍스트)을 그대로 유지한다. 달라진 건 능력치보다 "토큰 효율"을 전면에 내세웠다는 점이다. Moonshot은 자체 벤치 6종에서 K2.6 대비 전 항목 상승(Kimi Code Bench v2 50.9→62.0)을 보고하면서, 동시에 같은 정답을 더 짧은 추론으로 낸다고 주장했다 (MarkTechPost — Kimi K2.7-Code). 추론 토큰이 곧 청구 비용인 시대에 "덜 생각하기"를 세일즈 포인트로 잡은 셈이다.

핵심 메커니즘

요즘 추론 모델의 고질병은 쉬운 문제에도 장황하게 생각을 늘어놓는 과잉 생각이다. 정답률은 그대로인데 토큰만 불어난다. 이를 줄이는 가장 직접적인 방법은 강화학습 보상에 "길이 페널티"를 끼워, 같은 정답이면 짧은 사슬에 더 높은 점수를 주는 것이다.

[질문] → [생각 사슬 생성] → 정답 검증 ┐
                                      ├→ 보상 R = 정답성 − α·길이
        └────── 정책 업데이트 ◀────────┘

여기서 요령은 길이 페널티를 균일하게 주지 않는 것이다. 최근 arXiv 연구들은 쉬운 문제엔 길이 벌점을 강하게, 어려운 문제엔 거의 0으로 두는 "쉬운 건 빠르게, 어려운 건 깊게" 식의 보상 설계를 제안한다 (arXiv:2506.10446 — Powered Length Penalty). K2.7-Code의 30% 감소도 이 계열의 정렬 결과로 읽힌다. 실제로 K2.6이 라이브러리를 감싸 우회하던 패턴을 K2.7-Code는 직접 구현으로 바꿨는데, 불필요한 탐색 사슬이 줄어든 것과 같은 맥락이다.

코드 / 수식 예시

길이 보상형 RL의 뼈대는 의외로 단순하다. 토큰 수 n, 정답 여부 c, 문제 난이도 d일 때 보상은 대략 이렇게 짠다.

def shaped_reward(correct, n_tokens, difficulty):
    # difficulty: 0(쉬움) ~ 1(어려움)
    alpha = 0.001 * (1.0 - difficulty)   # 쉬울수록 길이 벌점 ↑
    base = 1.0 if correct else 0.0
    return base - alpha * n_tokens       # 같은 정답이면 짧을수록 高

쉬운 문제(difficulty≈0)는 alpha가 커져 장황함이 강하게 깎이고, 어려운 문제(difficulty≈1)는 alpha≈0이라 충분히 생각할 여지를 남긴다 (arXiv:2506.08343 — NoWait). K2.7-Code API는 thinking 모드가 강제(비활성화 시 에러)이고 샘플링도 고정(temperature 1.0, top_p 0.95)이라, 사용자가 추론 예산을 직접 끄지 못한다. 효율은 오롯이 모델 내부 정렬로만 확보하는 구조다.

한계·반론

가장 큰 약점은 헤드라인 수치 전부가 자체 벤치라는 점이다. Kimi Code Bench v2·Program Bench·MLS Bench Lite 모두 Moonshot 자가 측정이고, 변별력이 큰 독립 벤치 DeepSWE에는 제출되지 않았다 (VentureBeat — 벤치마크 검증 논란). 한 실무자(Arledge)는 "K2.7은 더 정직해졌지만 더 유능해진 건 아니다"라고 평했다. K2.6이 라이브러리로 때우던 Triton 커널을 K2.7-Code가 직접 작성하긴 했으나, 그중 둘은 자기 버그로 실패했다는 관찰이다. 즉 "생각을 줄였다"가 곧 "더 잘한다"는 아니며, 30% 절감이 독립 환경에서도 유지될지는 확인 필요다.

현직 엔지니어 관점

온디바이스·엣지 관점에서 추론 토큰은 가장 비싼 자원이다. 메모리 대역폭이 한정된 NPU에서 디코딩 스텝 하나하나가 곧 전력이고 지연이다. 모델을 키우지 않고 사슬 길이만 줄이는 접근은, HBM이나 칩을 더 붙이기 어려운 엣지 환경에서 특히 값지다. 다만 K2.7-Code 자체는 595GB·서버급이라 노트북에 올릴 물건은 아니다. 의미 있는 건 "길이 보상형 정렬"이라는 레시피 쪽이다. 이 기법이 소형 온디바이스 모델로 이식되면 같은 칩에서 체감 응답성과 배터리를 동시에 얻을 수 있다. 현장에서 정작 필요한 건 더 큰 모델이 아니라, 같은 정답을 더 적은 스텝으로 내는 모델이다.
