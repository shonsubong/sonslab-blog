KV 캐시를 3비트로 접은 길 — TurboQuant가 폴라 회전과 1비트 잔차로 8배를 뽑아낸 방식

TL;DR

  • TurboQuant는 KV 캐시를 3비트까지 압축하면서도 LongBench·Needle-in-Haystack에서 사실상 무손실을 유지하고, H100에서 어텐션 로짓 계산을 32비트 대비 최대 8배까지 끌어올린다.
  • 1단계 PolarQuant가 랜덤 직교 회전 뒤 좌표 쌍을 (radius, angle)로 펼쳐 스칼라 양자화 친화적인 분포로 바꾸고, 2단계 QJL이 잔차를 1비트 부호만 남겨 어텐션 내적의 편향을 잡는다.
  • 학습·캘리브레이션이 모두 불필요한 training-free 기법이라, MLA처럼 모델 구조를 바꿔야 하는 압축과 달리 기존 체크포인트에 그대로 끼울 수 있다.

배경 (Why now)

3월 24일 Google Research가 TurboQuant를 공개했고, 본 논문은 ICLR 2026, 1단계인 PolarQuant는 AISTATS 2026 발표 예정이다 (Google Research — TurboQuant 블로그). 4월 말 MarkTechPost의 "KV cache 압축 톱10" 정리에서도 TurboQuant·KVQuant·MLA가 큰 축으로 잡혔다 (MarkTechPost 2026-04-29).

200K~1M 토큰을 다루는 추론 워크로드에서 KV 캐시가 메모리의 단일 최대 항목이 됐다. 가중치는 FP4·NVFP4로 이미 4비트까지 내려갔는데(직전 5월 11일 글), KV 캐시는 BF16에서 멈춰 있었다. 가중치보다 캐시가 더 커지는 역전 구간이 시작된 지점에서 TurboQuant가 도착한 셈이다.

핵심 메커니즘

[ d차원 키/값 벡터 v ]
        │
        ▼
[Stage 1 — PolarQuant]
  ① R·v 로 랜덤 직교 회전
  ② 좌표 쌍 → (r, θ) 폴라화 (재귀)
  ③ 스칼라 양자화 ≈ 3 bit
        │ 잔차 e = v − dequant(·)
        ▼
[Stage 2 — QJL]
  ① 가우시안 JL 행렬 G로 사영
  ② sign(Ge) 만 1비트 저장
        │
        ▼
[디코드] 라디우스·각도 복원 → R⁻¹ → 어텐션 로짓
        QJL 부호로 내적 편향 보정

두 단계가 서로 다른 일을 한다. PolarQuant는 본체 정보를 잡는다. 직교 회전으로 좌표 분산을 균일하게 편 뒤 (radius, angle)로 풀면 라디우스는 chi, 각도는 거의 균등 분포가 된다. 분포가 알려져 있으니 블록별 스케일 계수가 따로 필요 없고, 이게 전통 양자화의 "오버헤드 1~2비트"를 0으로 만든다. QJL은 본체가 못 잡은 잔차의 방향만 잡는다. JL 사영 후 부호만 남기면 내적 추정량이 unbiased가 되고, 어텐션 로짓이 본질적으로 내적이므로 이 부호 1비트가 logit drift를 막는다.

코드 예시

import torch

def polar_quant(v, R, bits=3):
    z = R @ v                       # 직교 회전: 좌표 분산 균일화
    pairs = z.view(-1, 2)
    r = pairs.norm(dim=-1)          # 라디우스 (chi 분포)
    theta = torch.atan2(pairs[:, 1], pairs[:, 0])
    r_q = quantize_chi(r, bits=bits)
    t_q = quantize_uniform(theta, bits=bits - 1)
    return r_q, t_q                 # 블록별 스케일 계수 불필요

def qjl_residual(e, G):
    # G: (m, d) 가우시안 JL 행렬, m ≪ d
    return torch.sign(G @ e)        # 잔차 방향만 1비트로 저장

블록 단위 calibration이 빠져 있다. 회전 행렬 R과 JL 행렬 G는 모델·데이터와 무관하게 사전 샘플 후 고정. 추론 시 추가 연산은 R·v와 sign(G·e) 두 번뿐이라 runtime 오버헤드가 거의 없다.

한계·반론

세 가지를 본다. 첫째, 검증된 모델 폭이 좁다. Google 블로그는 Gemma·Mistral·Llama-3.1 8B 위주로 돌렸고, MLA 기반 frontier MoE나 추론 강화 모델에서의 거동은 공개 데이터가 부족하다. 사슬이 길수록 누적 logit drift가 어디서 임계점을 넘는지가 관건. 둘째, MLA와 압축률을 단순 비교하면 오해다. MLA는 아키텍처 수준 압축으로 DeepSeek V2 기준 KV가 93% 줄었다 (HF — MLA 해설). TurboQuant 6배는 BF16 대비 비트 수 기준이라 직접 비교가 아니고, 두 기법은 직교적이라 함께 쓰는 게 합리적이다. 셋째, RoPE 적용 K에 PolarQuant 회전을 거는 순서가 어긋나면 위치 정보가 망가지는데, 이게 커뮤니티 구현에서 가장 자주 보고된 지점이다 (llama.cpp #20969).

현직 엔지니어 관점

온디바이스 추론을 만지는 입장에서 이 기법이 매력적인 이유는 단순하다. 자동차 ECU·로봇 컨트롤러·휴대폰 NPU처럼 HBM이 없는 환경에서는 LPDDR 대역폭이 곧 컨텍스트 길이 상한이다. 가중치를 4비트로 내려도 KV 캐시가 16비트로 남아 있으면 32K 이상에서 메모리 wall에 부딪힌다. TurboQuant가 캐시를 5~6배 줄여주면 같은 8GB LPDDR5X에서 잡을 수 있는 토큰 수가 직선적으로 늘고, training-free라 모델 출시 후 런타임에 곧장 끼울 수 있다. 다만 회전·JL 행렬이 추가 BLAS 호출이라 INT8/INT4 텐서 코어 비중이 낮은 모바일 GPU에서는 ALU 예산을 새로 잡아야 한다. 양자화는 가중치 단독 이슈가 아니라 가중치·활성·KV 세 축을 함께 보는 시스템 문제로 굳어졌다.
