토큰을 4분의 1만 쓴다 — Grok 4.5가 내세운 효율의 이면

AI 딥다이브 2026년 07월 12일 (일) · 10:00 · 5분 읽기
목차
  • TL;DR
  • 배경 (Why now)
  • 핵심 메커니즘
  • 코드 예시 — 과제당 비용 셈
  • 한계·반론
  • 현직 엔지니어 관점
  • 더 읽을거리

TL;DR

  • xAI(공식 표기는 이제 SpaceXAI)가 7월 8일 Grok 4.5를 공개했다. SWE Bench Pro 과제당 평균 출력 토큰이 15,954개로, Opus 4.8(max)의 67,020개 대비 4.2배 적다.
  • 효율의 출처는 "토큰당 지능"을 명시적 목표로 잡은 대규모 강화학습과 Cursor 실사용 세션 수조 토큰이다.
  • 다만 순위는 하네스를 바꾸면 뒤집힌다. 각 사 하네스(DeepSWE 1.0)에선 Opus 4.8을 앞서고, 통일 하네스(1.1)에선 뒤진다.

배경 (Why now)

이번 주는 발표가 겹쳤다. 7월 8일 Grok 4.5, 7월 10일 GPT-5.6 시리즈. 그 틈에서 xAI가 고른 차별화 축은 성능 1위가 아니라 "지능 대비 비용"이다. 공식 블로그부터 80 TPS 속도, $2/$6(백만 토큰당 입력/출력) 단가, 경쟁 모델의 절반 이하 토큰으로 같은 과제를 푼다는 효율 수치를 앞세운다 (xAI — Introducing Grok 4.5).

또 하나의 배경은 Cursor와의 공동 학습이다. 학습 구성은 Cursor 쪽 발표에 더 구체적으로 적혀 있다 (Cursor — Introducing Grok 4.5). 지난주 다룬 토크나이저 교체(7/5)가 같은 문장을 몇 토큰으로 표현하느냐였다면, 오늘은 같은 과제를 몇 토큰의 사고로 푸느냐다.

핵심 메커니즘

1.5조 매개변수 V9 MoE라는 관측이 유력하지만 공식 확인은 아직 없다 (@tetsuoai 정리 thread). 공식 확인된 것은 학습 파이프라인이다.

[Cursor 실사용 세션 로그 수조 토큰]        [고난도 RL 환경 수십만 개]
  (멀티파일 수정·디버깅·중간 실패 포함)      (에이전트 무리가 자동 생성·검증)
              │                                  │
              ▼                                  ▼
[사전학습: GB300 수만 장] ───▶ [비동기 RL: 롤아웃 수 시간씩 지속]
                                     │ 목표 = 해결률과 함께 "토큰당 지능"
                                     ▼
                      [과제당 출력 ~16k 토큰으로 수렴]

포인트는 두 가지. 첫째, 학습 데이터가 완성된 코드가 아니라 개발자가 헤매는 과정 자체다. 파일을 오가고, 틀리고, 고치는 세션 로그는 짧은 경로로 문제를 푸는 법을 가르치기 좋은 재료다. 둘째, 보상 설계에 효율 압력이 있다. xAI 표현으로는 "per-token intelligence에 집중해 RL을 확장했다".

코드 예시 — 과제당 비용 셈

발표 수치를 그대로 넣어 과제당 비용을 계산해 보면 이렇다.

PRICE_IN, PRICE_OUT = 2.0, 6.0          # $ / 1M tokens

def task_cost(in_tok, out_tok):
    return in_tok / 1e6 * PRICE_IN + out_tok / 1e6 * PRICE_OUT

grok_out, opus_out = 15_954, 67_020     # SWE Bench Pro 과제당 출력(xAI 발표)
print(task_cost(0, grok_out))           # 출력분만 보면 $0.10

# 에이전트 루프의 실제 지배 항은 입력(컨텍스트 반복 전송)이다.
# Artificial Analysis 실측: Grok Build에서 과제당 총 ~1.9M 토큰
print(task_cost(1_900_000, grok_out))   # 정가 기준 ≈ $3.9

정가로 셈하면 $3.9인데 Artificial Analysis 실측은 $2.49다. 차이는 캐시 할인. 같은 측정에서 Claude Code의 Fable 5는 $11.80, Codex의 GPT-5.5는 $5.07이었다 (@ArtificialAnlys thread). 짧은 출력이 다음 턴의 입력 누적까지 줄이므로 총비용 격차는 단가 격차보다 크게 벌어진다.

한계·반론

가장 큰 반론은 순위의 하네스 종속이다. 각 사 하네스로 돌린 DeepSWE 1.0에선 Grok 4.5가 62.0%로 Opus 4.8(55.75%)을 앞서지만, mini-swe-agent로 통일한 1.1에선 53%로 Opus 4.8(59%), Fable 5(70%)에 뒤진다. 두 수치를 공식 페이지에 나란히 실었으니 숨긴 건 아니지만, "모델 성능"이 아니라 "모델+하네스 결합 상품"을 사는 셈이라는 해석은 피하기 어렵다.

오염 이슈도 있다. Cursor 코드베이스 옛 스냅샷이 학습에 잘못 포함되어 자체 벤치마크에서 유리했다는 각주를 Cursor가 직접 달아 두었다. 세션 데이터 학습이 평가 오염과 얼마나 가까운지 보여주는 사례다.

마지막은 토큰 효율 지표 자체의 함정. 짧게 푸는 것에 보상을 주면 검증을 생략하는 보상 해킹과 종이 한 장 차이다. 공교롭게 Cursor 연구팀이 2주 전 같은 경고를 냈다 (Cursor — Reward hacking). 16k 토큰짜리 답이 67k 토큰짜리만큼 검증을 거쳤는지는 점수로 알 수 없다.

현직 엔지니어 관점

출력 토큰이 4분의 1이면 디코드 단계의 HBM 대역폭 부담도 거의 그만큼 준다. 서버는 같은 GPU로 더 많은 동시 사용자를 받고, 온디바이스는 같은 전력·메모리 예산으로 더 긴 에이전트 작업이 가능해지니 효율 경쟁은 하드웨어 쪽에서 반가운 방향이다. 다만 하네스에 따라 순위가 흔들리는 모델은 이식성이 걱정이다. 온디바이스 배포는 결국 하네스를 새로 짜는 일이라, 특정 실행 환경에 최적화된 효율이 어디까지 따라올지 확인이 필요하다. Claude Code를 매일 쓰는 입장에서 과제당 $2.49와 $11.80의 차이는 체감되는 숫자지만, 도구를 바꾸는 결정은 평균 비용이 아니라 최악의 날 재작업 비용으로 하는 것이라 당분간 지켜볼 생각이다.
