확산 언어모델이 자기회귀를 흔든다 — LLaDA·Mercury가 연 옆문

AI 딥다이브 2026년 05월 12일 (화) · 10:00 · 4분 읽기
목차
  • TL;DR
  • 배경 (Why now)
  • 핵심 메커니즘
  • 코드 / 의사코드 예시

  • 현직 엔지니어 관점 한 문단

TL;DR

  • 확산 언어모델은 텍스트를 한꺼번에 마스킹·복원하는 방식으로, 토큰을 좌에서 우로 한 개씩 뽑던 자기회귀(AR) 골격과 직각으로 부딪힌다.
  • 2025년 LLaDA 8B와 Mercury Coder가 동급 AR에 근접한 벤치마크를 찍은 뒤, 2026년 들어 BD3LM(블록 확산)과 멀티모달 후속작이 줄지어 나왔다.
  • long output에서 지연이 토큰 수에 비례하지 않고, KV 캐시가 누적되지 않아 메모리 곡선이 다르다. step 수 트레이드오프와 long-form 일관성은 여전히 과제.

배경 (Why now)

직전 2주에 분기점이 몰렸다. 4월 마지막 주 Inception Labs가 Mercury Coder 후속을 공개하며 동급 AR 코더 대비 수 배의 토큰/초를 주장했고, 5월 첫째 주에는 BD3LM 후속 논문이 arXiv에 추가됐다. Renmin University의 LLaDA-V는 시각 입력을 붙여 멀티모달 결과를 더했고, @karpathy는 X에서 "확산 텍스트가 더 이상 호기심거리가 아니다"라는 thread를 올렸다.

확산은 AR의 두 가지 빈틈을 노린다. 디코드 지연이 토큰 수 $N$이 아니라 step 수 $T$에 비례하고, 시퀀스가 길어도 KV 캐시처럼 메모리가 누적되지 않는다.

핵심 메커니즘

골격은 이미지 확산과 같은 forward-reverse 두 단계지만, 픽셀 노이즈 대신 이산 마스킹을 쓴다.

[원문] x0 = "확산 모델이 마스크를 푼다"
        ↓ forward (점진 masking, α_t로 베르누이)
[t=T] xT = "[M] [M] [M] [M] [M] [M]"
        ↑ reverse (denoiser θ가 다수 토큰을 병렬 예측)
[t=0] x_hat = "확산 모델이 마스크를 푼다"

forward $q(x_t \mid x_0)$는 각 토큰을 독립적으로 $\alpha_t$ 확률로 마스킹한다. 디노이저 $p_\theta(x_{t-1} \mid x_t)$는 한 step에서 마스크 자리를 한꺼번에 예측하고, 신뢰도가 낮은 토큰만 다시 마스킹해 다음 step으로 넘긴다(confidence-based remasking). AR은 길이 $N$에 대해 $N$번 forward, 확산은 step 수 $T$에 대해 $T$번. 출력이 길수록 $T \ll N$ 영역이 열린다.

코드 / 의사코드 예시

# LLaDA 스타일 mask-predict 샘플링 (의사코드)
def diffusion_sample(prompt, denoiser, length=256, T=32):
    x = prompt + [MASK] * length
    mask_idx = list(range(len(prompt), len(x)))
    for t in range(T, 0, -1):
        logits = denoiser(x)                       # (L, V)
        pred   = logits.argmax(-1)
        conf   = logits.softmax(-1).gather(-1, pred[..., None])
        keep   = max(1, len(mask_idx) // t)        # 이번 step에서 확정할 수
        topk   = sorted(mask_idx, key=lambda i: -conf[i])[:keep]
        for i in topk:
            x[i] = pred[i]; mask_idx.remove(i)
    return x

T=32, length=256이면 32번의 forward로 256토큰을 만든다. 단, 각 forward는 시퀀스 전체를 다시 본다 — AR의 증분 KV 갱신 대비 단일 forward 연산량은 더 크다. "토큰/초" 게인은 시퀀스 길이·step 수·하드웨어 활용률의 함수다.

한계·반론

먼저 품질 격차. LLaDA 8B는 MMLU·HumanEval에서 동급 Llama3 계열에 살짝 못 미치고, 수학·논리 추론에서는 격차가 더 벌어진다. Mercury Coder는 코드에서 AR과 동급을 주장하지만 일반 능력은 자기회귀의 두께를 따라잡지 못한다. 둘째, 하드웨어 친화성. 플래시 어텐션·KV 캐시 최적화·투기 디코드처럼 AR 위에 쌓인 인프라가 확산에는 그대로 옮겨오지 않는다. 셋째, long-form 일관성. 256토큰을 넘어가면 step 수를 늘려도 장거리 의존성을 잡지 못한다는 관찰이 있고, BD3LM은 블록 안은 AR, 블록 간은 확산으로 가는 절충안을 든다. 마지막으로 벤치마크 함정 — "토큰/초"는 동일 품질을 고정하지 않으면 의미가 약하다.

현직 엔지니어 관점 한 문단

온디바이스에서 KV 캐시는 NPU SRAM 곡선을 결정하는 가장 큰 변수다. 확산이 매력적인 이유는 시퀀스 길이가 늘어도 메모리 풋프린트가 누적되지 않아 작은 메모리에서도 long output을 뽑기 쉽다는 점이다. 대신 매 step마다 전체 시퀀스를 다시 본다는 점은 컴퓨트 부담이라, dense FMA 활용률이 높은 워크로드(음성 합성, 코드 자동완성, 고정 길이 캡션)에는 유리하지만 컨텍스트·응답이 모두 짧은 챗에서는 AR 대비 우위가 빠르게 사라진다. AR을 대체하기보다, 좁은 도메인에서 자리를 잡고 BD3LM처럼 AR과 섞이는 형태로 옆문을 여는 시나리오가 현실적이다.
