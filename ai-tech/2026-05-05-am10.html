GPU 한 장이 둘로 갈린다 — 추론 서빙이 프리필·디코드를 분리하는 이유

AI 딥다이브 2026년 05월 05일 (화) · 10:00 · 4분 읽기
목차

  • 배경 (Why now)
  • 핵심 메커니즘
  • 코드 / 수식 예시
  • 한계·반론
  • 현직 엔지니어 관점

TL;DR

  • 한 장의 GPU 안에서 프리필(프롬프트 처리)과 디코드(토큰 생성)는 자원 특성이 정반대다 — 전자는 컴퓨트 한계, 후자는 메모리 대역폭 한계.
  • 두 단계를 별도 GPU 풀로 쪼개는 P/D 분리(Disaggregation)는 동일 자원으로 처리량을 수 배까지 끌어올린다.
  • vLLM v1, NVIDIA Dynamo, Mooncake가 모두 이 구조를 1차 시민으로 채택하면서 2026년 추론 서빙의 표준이 됐다.

배경 (Why now)

DistServe가 OSDI 2024에서 동일 SLO 안에서 7.4배 처리량을 보고한 이후 2년 만에, 4월 말 vLLM v0.11이 disaggregated prefill을 stable로 승격했다 (vLLM 공식문서). 같은 시기 Moonshot AI는 Kimi K2를 H200 128장에 분리 배치해 프리필 224k tok/s, 디코드 288k tok/s를 공개했고 (Mooncake), NVIDIA Dynamo 1.0은 두 워커를 1차 객체로 둔다 (Dynamo). 결정타는 KV 전송 표준 NIXL — vLLM과 Dynamo가 같은 전송 계층을 공유하면서 분리는 더 이상 실험이 아니다.

핵심 메커니즘

[기존: 혼재 풀]
요청 → [Prefill+Decode 한 GPU] → 응답
         (두 단계가 같은 SM·HBM을 두고 경쟁 → 서로를 굶긴다)

[분리: P/D 풀]
요청 → [Prefill 풀]  ── KV 캐시 ──▶  [Decode 풀] → 응답
        대형 배치             RDMA/NVLink         낮은 latency
        컴퓨트 한계                                 대역폭 한계

비대칭의 본질은 단순하다. 프리필은 시퀀스 길이 N에 대해 어텐션이 $O(N^2)$로 늘어 SM·MFU가 자원이고, 디코드는 토큰마다 KV 전체를 읽어 HBM 대역폭이 자원이다. 한 풀에서 둘을 섞으면 큰 프롬프트 하나가 작은 디코드 수십 건을 stall 시킨다. 분리하면 풀별로 배치 크기·텐서 병렬도·정밀도까지 따로 잡을 수 있다.

코드 / 수식 예시

KV 캐시 한 토큰의 메모리 비용:

mem_per_tok = 2 × layers × kv_heads × head_dim × dtype_bytes

Llama-3 70B(80 layer, GQA 8 head, head_dim 128, fp16)는 토큰당 약 320KB, 컨텍스트 32k 한 시퀀스가 약 10GB다. 디코드 GPU의 HBM 절반 이상이 KV 보관용이라는 뜻이다. vLLM의 분리 실행은 같은 모델을 두 프로세스로 띄우고 KV 커넥터로 묶는다.

# Prefill 워커 (큰 배치, 컴퓨트 풀)
vllm serve meta-llama/Llama-3-70B \
  --kv-transfer-config '{"kv_role":"kv_producer","kv_connector":"NixlConnector"}'

# Decode 워커 (HBM 대역폭 풀)
vllm serve meta-llama/Llama-3-70B \
  --kv-transfer-config '{"kv_role":"kv_consumer","kv_connector":"NixlConnector"}'

Dynamo는 위 두 풀을 라우팅 계층 아래에 두고 prefix 캐시 hit율까지 함께 최적화한다.

한계·반론

KV 전송이 NVLink(900GB/s급)나 RDMA(IB 400Gbps급)에 의존하는 탓에 노드 간으로 넘어가는 순간 TTFT SLO를 잡아먹는다. 짧은 시퀀스(<1k) 위주 워크로드는 분리 오버헤드가 이득을 까먹어 — 코드 보조처럼 짧은 호출은 혼재 풀이 여전히 낫다. prefix 캐시 라우팅이 같이 들어가지 않으면 분리만의 이득은 10~20%대로 떨어진다는 분석도 있다 (Towards Data Science). 결국 분리는 KV 라우팅·청크 프리필·연속 배치와 묶음으로 굴러야 한다.

현직 엔지니어 관점

이 흐름은 HBM 대역폭과 NVLink 토폴로지의 가치를 새로 정의한다. 디코드 풀은 HBM 대역폭이 곧 throughput이고, 프리필 풀은 SM·MFU가 곧 throughput이다. B200에서 NVLink 5세대 1.8TB/s가 핵심 셀링포인트가 된 이유가 여기 있다 — KV를 GPU 사이에서 무손실로 옮길 수 있을 때에만 분리가 의미 있다. 반대로 온디바이스 NPU 한 칩 안에서는 분리 자체가 불가능하니, 양자화·KV 압축·prefix caching이 같은 문제를 푸는 다른 답이 된다. 클라우드는 둘로 쪼개고 엣지는 한 덩어리에서 짜내는 비대칭이 한동안 굳어질 것이다. 분리가 늘수록 메모리·인터커넥트 매출이 컴퓨트 매출보다 빠르게 자라는 그림 — Dynamo가 라우팅을 1차 시민으로 둔 건 우연이 아니다.
