휴머노이드 VLA가 결국 듀얼 시스템으로 수렴한 이유

AI 딥다이브 2026년 05월 08일 (금) · 10:00 · 6분 읽기
목차

TL;DR

  • 4월 14~17일 사이 DeepMind Gemini Robotics-ER 1.6, Physical Intelligence π0.7, NVIDIA GR00T N1.7이 줄지어 공개됐다. 셋 다 듀얼 시스템 구조를 채택했다.
  • 느린 VLM(7~9Hz)이 의도·계획을 만들고, 빠른 비주얼모터 정책(200Hz)이 관절 명령을 뽑는다. Figure Helix 02는 1kHz 저수준 컨트롤러(S0)까지 한 층 더 쌓았다.
  • 단일 forward pass로 일반화와 실시간 제어를 동시에 풀려는 시도가 막히면서, fast/slow 분리가 휴머노이드 VLA의 사실상 표준이 됐다.

배경 — 왜 지금인가

4월 둘째 주는 휴머노이드 VLA 발표가 줄지어 나온 한 주다. 14일 DeepMind가 Gemini Robotics-ER 1.6을 공개했고, 16일 Physical Intelligence가 π0.7 논문을 풀었다. 17일에는 NVIDIA가 Isaac GR00T N1.7 얼리억세스를 발표했다. 무관해 보이는 세 곳이 같은 결론에 도달한 점이 흥미롭다 — 모놀리식 한 개 모델로는 안 된다, 시간 스케일을 나눠야 한다.

ICLR 2026에 제출된 VLA 논문 164편 중에도 듀얼 시스템 또는 계층형 구조가 다수다(Reuss, ICLR'26 VLA 동향). 1년 전 OpenVLA·RT-2 세대가 단일 모델로 throughput과 일반화 사이에서 한쪽을 포기하던 것과 명확히 대비된다.

핵심 메커니즘 — 두 개의 비동기 루프

[카메라 / 명령어] ──► System 2 (VLM, 2~7B 파라미터)
                        │  의도·고수준 계획, 7~9Hz
                        ▼
                  [latent vector]
                        │
                        ▼
[관절 상태] ──────────► System 1 (visuomotor policy)
                        │  연속 trajectory, 200Hz
                        ▼
                  [관절 토크 / 위치 명령]
                        │  (Helix 02만 추가)
                        ▼
                  System 0 (저수준 컨트롤러, 1kHz)
                        │  접촉·균형·전신 조율
                        ▼
                       모터

핵심은 시간 스케일 분리다. VLM은 100~140ms 주기로 "냉장고를 열고 우유를 꺼내라"는 latent를 갱신한다. 정책은 그 latent를 받은 채 5ms 주기로 모터 명령을 뽑는다. latent가 한 동안 그대로여도, 손목 미세 조정 같은 빠른 보정은 정책이 자체적으로 한다(Figure Helix).

코드 예시 — 비동기 듀얼 루프

import asyncio

async def slow_loop(vlm, sensors, shared):
    while True:
        obs = sensors.snapshot()        # 이미지 + 자연어 명령
        latent = await vlm.run(obs)     # 100~140ms
        shared["latent"] = latent       # 공유 메모리에 덮어쓰기
        await asyncio.sleep(0)          # ~7Hz

async def fast_loop(policy, sensors, robot, shared):
    while True:
        proprio = sensors.proprio()     # 관절 위치·속도
        latent = shared.get("latent")
        if latent is not None:
            action = policy(proprio, latent)  # ~5ms
            robot.apply(action)
        await asyncio.sleep(0.005)      # 200Hz

shared["latent"]는 VLM이 다음으로 갱신할 때까지 그대로 재사용된다. 정책이 VLM 결과를 동기로 기다리면 200Hz가 무너진다 — 분리의 본질은 이 비동기 채널이다.

한계·반론

데이터 욕심은 끝이 없다. NVIDIA EgoScale 결과는 1천 시간에서 2만 시간으로 늘리면 평균 task 성공률이 두 배 이상 오른다고 보고하지만, 그 이상 가서도 같은 기울기가 유지될지는 아무도 모른다. π0.7 자체도 emergent 능력을 "early sign"·"initial demonstration"으로 수위를 낮춰 표현한다.

분리 자체에도 비용이 있다. latent 갱신 주기가 길수록 환경 변화에 대한 반응 lag이 생긴다. 잡고 있던 컵이 미끄러지는 순간 같은 빠른 외란은 정책 단에서 잡아야 하는데, 정책이 보는 latent는 이미 100ms 전 상황 기준이다. Helix 02가 1kHz S0 층을 따로 둔 이유도 이 lag을 보정하기 위해서다. 그래도 latent 자체가 잘못 계획되면 정책 보정만으론 못 막는다 — 결국 VLM 품질이 천장이다.

현직 엔지니어 관점

반도체 fab 자동화 관점에서 "느린 추론 + 빠른 제어" 패턴은 완전히 새롭지 않다. 광학 검사 장비도 머신비전 추론은 수십~수백ms, 스테이지 모션은 kHz 수준 PID로 분리해 돌린다. VLA의 신선함은 "느린" 쪽이 자연어를 받는 다목적 VLM이라는 점이다.

온디바이스 적용은 아직 멀다. Gemini Robotics-ER 1.6이나 GR00T N1.7의 VLM은 2~3B 파라미터다. 자동차급 SoC NPU(20~50 TOPS)에 INT8로 올려도 100ms 안쪽 latency를 잡으려면 빠듯하다. 정밀 어셈블리·고밀도 검사처럼 자연어 인터랙션이 별로 필요 없는 영역에서는, 작은 specialist 정책 + 외부 PC의 VLM 옵션 가지치기가 더 현실적이다. 휴머노이드 발표가 화려해도, 산업 현장에 들어오는 건 이런 하이브리드 형태가 1~2년 먼저일 가능성이 크다.
