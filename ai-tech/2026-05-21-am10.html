메모리가 반쯤 커스텀 칩이 된 순간 — HBM4가 베이스 다이를 파운드리로 보낸 이유

AI 딥다이브 2026년 05월 21일 (목) · 10:00 · 7분 읽기
목차
  • TL;DR
  • 배경 (Why now)
  • 핵심 메커니즘
  • 코드 / 수식 예시
  • 한계·반론
  • 현직 엔지니어 관점

TL;DR

  • 무엇 — HBM4부터 메모리 스택 맨 아래의 베이스 다이가 DRAM 공정이 아니라 파운드리 로직 공정(삼성 4nm, SK하이닉스·Micron은 TSMC 3nm 계열)에서 만들어진다.
  • 왜 중요 — 베이스 다이가 단순 배선층에서 "고객 맞춤 로직"으로 바뀌며, 메모리가 표준 부품에서 반쯤 커스텀 실리콘으로 넘어간다.
  • 어떻게 쓰나 — 인터페이스가 1024비트에서 2048비트로 두 배가 되어 스택당 2 TB/s를 넘기고, LLM 디코드 추론의 대역폭 상한을 직접 끌어올린다.

배경 (Why now)

2026년 2분기가 HBM4 양산 인증의 분수령이다. 삼성전자가 NVIDIA 품질 테스트를 통과하며 양산 출하를 시작했고, SK하이닉스는 전력효율 40% 개선·10Gbps급 HBM4 개발 완료를 알렸다 (SK하이닉스 뉴스룸 — 차세대 AI 메모리). Micron도 핵심 고객사에 HBM4를 출하했다 (Micron — HBM4 출하 보도자료).

무엇보다 지금 이 시점이 중요하다. 삼성·SK·Micron 세 곳의 커스텀 HBM4E 베이스 다이 설계가 올해 5~6월에 걸쳐 동시에 마무리되는 국면이고, NVIDIA Rubin이 HBM4를 처음으로 전면 채택한다. "메모리와 로직이 한 패키지 안에서 합쳐지는" 변곡점이 정확히 이번 분기에 걸쳐 있는 셈이다. 직전까지 이 블로그가 다룬 주제가 양자화·추론 스케줄러 같은 소프트웨어 쪽이었다면, 오늘은 그 소프트웨어가 결국 부딪히는 물리적 벽, 메모리 하드웨어 쪽을 본다.

핵심 메커니즘

HBM 한 스택은 DRAM 다이 여러 장을 TSV(실리콘 관통 전극)로 수직 적층하고, 맨 아래 베이스 다이가 호스트(GPU·ASIC)와의 입출력을 책임지는 구조다. HBM3까지 이 베이스 다이는 DRAM 공정으로 찍은, 거의 수동적인 배선층이었다. HBM4의 결정적 변화는 이 베이스 다이를 파운드리 로직 공정으로 옮긴 것이다.

   [ DRAM die ]  ┐
   [ DRAM die ]  │  4~16단 수직 적층 (TSV)
   [ DRAM die ]  │
   [ DRAM die ]  ┘
 ┌──────────────────────────┐
 │   베이스 다이 (Base Die)   │
 │  HBM3: DRAM 공정 · 1024-bit · 수동 배선 │
 │  HBM4: 로직 공정(4/3nm) · 2048-bit · 커스텀 회로 │
 └──────────────────────────┘
        │ 인터포저 │
   [   GPU / ASIC   ]

로직 공정은 트랜지스터 밀도와 금속 배선층이 DRAM 공정보다 훨씬 풍부하다. 덕분에 더 빠른 PHY를 넣고, 인터페이스 폭을 2048비트로 두 배 넓히며, 테스트·리페어 회로나 고객별 맞춤 로직까지 베이스 다이에 집어넣을 수 있다. "커스텀 HBM"이란 바로 이 베이스 다이를 고객 회로 사양에 맞춰 설계한다는 뜻이다 (Counterpoint — HBM4 Inflection: 로직 베이스 다이와 커스텀 메모리).

코드 / 수식 예시

디코드(토큰 생성) 단계는 배치 크기가 작을 때 연산이 아니라 메모리 대역폭에 묶인다. 토큰 한 개를 만들 때마다 모델 가중치를 통째로 한 번씩 읽어야 하기 때문이다.

def decode_tok_per_s(params_b, bytes_per_param, bw_tbps):
    model_bytes = params_b * 1e9 * bytes_per_param   # 가중치 총 바이트
    return bw_tbps * 1e12 / model_bytes              # batch=1 디코드 상한

# 70B 모델, FP8(파라미터당 1바이트) 기준
decode_tok_per_s(70, 1,  8.0)   # HBM3e급 ~8 TB/s   -> 약 114 tok/s
decode_tok_per_s(70, 1, 13.0)   # HBM4급  >13 TB/s  -> 약 186 tok/s

가속기 한 장의 가용 대역폭이 8에서 13 TB/s로 늘면, 같은 모델의 디코드 상한이 약 114에서 186 tok/s로 60% 넘게 오른다. HBM4가 2048비트로 노리는 지점이 정확히 이 대역폭 천장이다. 스택 하나만 봐도 2048비트 × 8Gb/s면 약 2 TB/s, SK하이닉스가 말한 10Gbps면 약 2.56 TB/s로, HBM3e 스택(약 1.2 TB/s)의 두 배 안팎이다.

한계·반론

좋게만 볼 일은 아니다. 베이스 다이를 첨단 로직 공정으로 옮기면 다이 원가와 수율 부담이 함께 올라간다. 실제로 양산 인증 과정에서 NVIDIA가 수율·캐파 한계 탓에 HBM4 사양을 일부 완화하는 안을 검토했다는 관측도 나왔다 (TrendForce — NVIDIA, HBM4 스펙 완화 검토 보도). 커스텀 HBM은 표준화의 반대편이라, 고객별 설계가 늘수록 물량이 쪼개지고 공급은 경직되며 검증 부담도 커진다. 기술적으로도 대역폭만으로 다 풀리지 않는다. 배치를 키운 추론에서는 병목이 다시 연산으로 넘어가 메모리월 논리가 그대로 적용되지 않는다. 로직 베이스 다이가 스택 맨 아래에서 열을 내뿜고, 그 위에 쌓인 DRAM의 냉각 난도가 같이 올라가는 점도 남은 숙제다 (SemiAnalysis — Scaling the Memory Wall).

현직 엔지니어 관점

현장에서 보면 이번 변화의 본질은 "메모리·파운드리·설계의 경계가 흐려진다"는 데 있다. 베이스 다이가 로직 공정으로 가는 순간, 메모리 회사도 파운드리 설계 룰과 EDA 흐름을 본격적으로 다뤄야 하고, 시스템 회사는 메모리 안쪽 회로 사양까지 직접 정하게 된다. 다만 이 흐름이 곧장 온디바이스로 내려온다고 보기는 어렵다. 엣지·온디바이스는 여전히 LPDDR과 좁은 대역폭 위에서 돌아가고, HBM의 전력·면적·원가를 감당하지 못한다. 그래도 "연산을 메모리 가까이로 당긴다"는 발상 자체가 베이스 다이에서 검증되면, 언젠가 엣지 추론 칩의 메모리 서브시스템 설계에도 단서를 줄 수 있다. 어느 시점에 어떤 형태로 내려올지는 아직 확인이 필요한 영역으로 남겨 둔다.
