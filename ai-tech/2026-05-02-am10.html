확산형 언어 모델이 자기회귀의 직렬성을 깨뜨리는 법

TL;DR

  • 확산형 언어 모델(Diffusion LLM)은 토큰을 좌→우로 한 개씩 뽑지 않고, 마스킹된 시퀀스 전체를 몇 step에 걸쳐 동시에 정제한다.
  • Inception Labs의 Mercury Coder가 H100 한 장에서 1000 tok/s 이상을 보고하면서, 자기회귀의 HBM 대역폭 천장을 다른 방향으로 우회하는 길이 처음으로 양산 가능해졌다.
  • 코드·구조화 출력 같은 좁은 도메인부터 들어오고 있고, 자유 서술·긴 추론에서는 아직 자기회귀가 우위다.

배경 — 왜 지금 다시 확산인가

확산 언어 모델 자체는 새 아이디어가 아니다. D3PM(2021), SEDD(2023) 시절부터 학계에 있었지만, 자기회귀 Transformer의 품질을 따라잡지 못해 꺼져 있었다. 흐름이 바뀐 직접 트리거는 두 개다. LLaDA 8B가 공개 가중치로 동급 자기회귀 모델과 비슷한 MMLU·GSM8K 점수를 내면서 "확산도 스케일이 통한다"는 증거가 나왔고 (LLaDA 논문, arXiv:2502.09992), Inception Labs가 Mercury·Mercury Coder를 상용 API로 풀면서 throughput이 자기회귀 대비 5~10배라고 공시했다 (Inception Labs Mercury 발표). 학계 호기심에서 production 후보로 올라선 것이 직전 분기의 일이다.

자기회귀 추론은 step당 1토큰만 추가하면서 KV 캐시를 매번 read+write — HBM 대역폭이 곧 천장이다. 추측 디코딩으로 들어올렸지만 한 시퀀스 안에서는 여전히 직렬이다. 확산형은 그 직렬성을 깬다.

핵심 메커니즘 — 마스크에서 거꾸로 풀어가는 구조

[자기회귀]
t1 → t2 → t3 → t4 → ... → tN              (N step, 직렬)

[확산형]
[?, ?, ?, ?, ?, ?, ?]   step 0  (전부 mask)
[the, ?, fox, ?, ?, ?]  step 1  (확신 높은 자리부터 unmask)
[the, ?, fox, ?, lazy, dog]  step 2
[the, quick, fox, jumps, lazy, dog]  step T
                         (T << N, 매 step 다수 자리 동시 결정)

LLaDA 계열은 시퀀스 전체에 풀 어텐션을 한 번 걸어 마스크 자리의 logit을 동시에 예측한 뒤, 신뢰도 top-k 자리를 골라 확정한다. T(예: 64)가 N(예: 1024)보다 훨씬 작으면 wall-clock이 줄어든다. 본질은 메모리 접근 패턴의 트레이드오프다 — 자기회귀는 "짧은 시퀀스 × 많은 step", 확산형은 "긴 시퀀스 × 적은 step"이다.

코드 — 확산 샘플링 루프 의사코드

def diffusion_sample(model, prompt, length=512, T=64):
    seq = mask_tokens(prompt, length)         # prompt + [MASK]*remaining
    for t in range(T):
        logits = model(seq)                   # 전 시퀀스 1회 forward
        probs = softmax(logits)
        k = remaining_masks(seq) // (T - t)
        positions = topk_confidence(probs, seq, k)
        seq = unmask_at(seq, positions, probs)
    return seq

step 수가 시퀀스 길이가 아니라 T로 결정되는 게 핵심이다. T=N/16이면 메모리 round-trip이 16배 줄고, 어텐션 FLOPS는 늘지만 추론 GPU는 메모리 bandwidth가 먼저 천장이라 wall-clock이 잡힌다.

한계·반론

낙관론을 그대로 받기엔 아직 위험이 많다. 첫째, Mercury 1000 tok/s는 코드처럼 구조 강한 도메인 측정치다. 자유 서술·긴 추론 체인에서 step 수를 줄이면 품질이 무너진다는 보고가 여러 곳에서 나온다 (Simon Willison — Mercury 사용기). 둘째, 확산형은 KV 캐시 재사용이 안 된다 — 자기회귀 추론 인프라가 쌓아온 캐시 최적화 혜택이 사라진다. 셋째, RLHF·DPO가 자기회귀 가정에 묶여 있어 확산형 전용 alignment 레시피가 미성숙하다 (Nathan Lambert — Diffusion LLMs 정리). "더 빠르다"를 받기 전에 어떤 도메인·디코딩 budget인지 한 번 더 봐야 한다.

현직 엔지니어 관점

반도체 입장에서 보면 확산형은 자기회귀의 정반대 부담을 만든다. 자기회귀는 HBM 대역폭이 천장이라 HBM3E·HBM4 세대 경쟁이 곧 throughput이었다. 확산형은 매 step 풀 어텐션이라 부담이 compute 쪽으로 옮겨간다 — Blackwell처럼 sparse·structured compute가 강한 칩이 유리하고, 메모리 대역폭 단독 우위는 약해진다. 온디바이스 NPU 시각에서는 step 수가 16~64로 한정되면 결정적 latency 예측이 가능해져 실시간 UX 설계가 쉬워진다 — 자기회귀의 가변 출력 길이가 만들던 latency 분산이 사라진다. 산업용 vision pipeline·로봇 제어처럼 응답 시간 boundary가 강한 워크로드가 첫 후보다. 다만 범용 챗봇까지 단정하지는 말자 — 현재 입증된 우위는 코드·구조화 출력이라는 좁은 띠뿐이다.
