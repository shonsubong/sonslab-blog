150M 비전 인코더를 매트릭스 한 줄로 — Gemma 4 12B가 인코더를 통째로 뺀 방법

AI 딥다이브 2026년 06월 11일 (목) · 10:00 · 6분 읽기
목차

  • 배경 (Why now)
  • 핵심 메커니즘

TL;DR

  • 6/3 Google DeepMind이 공개한 Gemma 4 12B Unified는 별도의 비전·오디오 인코더를 통째로 빼고, 입력을 LLM 본체 임베딩 공간에 바로 사영한다 (Google Blog — Introducing Gemma 4 12B).
  • 비전은 48×48 픽셀 패치를 매트릭스 한 번으로 hidden dim에 던지고, X·Y 좌표 임베딩 두 개를 더해 위치를 끼워 넣는다. 비전 모듈 전체가 35M 파라미터로, 같은 중형의 550M 인코더 대비 1/15 수준이다 (Google Developers — Gemma 4 12B Developer Guide).
  • 16GB VRAM 노트북에서 256K 컨텍스트·이미지·오디오를 한 번에 다룬다. 인코더가 빠지면서 멀티모달 LoRA 한 번에 텍스트·이미지·오디오 가중치가 같이 움직인다.

배경 (Why now)

이번 주 온디바이스 멀티모달이 다시 뜨거운 건 6/8 WWDC26 Apple AFM 3 Core Advanced(NAND offload MoE) 발표 직전인 6/3에 DeepMind이 Gemma 4 12B를 끼워 넣었기 때문이다. 두 회사가 같은 주에 "노트북·폰에서 도는 멀티모달"을 들고 나왔지만 줄이는 지점이 정반대다.

Apple은 가중치 자체를 NAND에 눕히고 DRAM 대역폭을 아낀다. Gemma는 모달리티 인코더를 제거한다. 기존 중형 Gemma 4는 비전에 550M, 오디오에 300M짜리 별도 인코더를 끼고 다녔다. 12B는 비전 35M + 오디오 wave projection 한 장으로 압축했고, 그 자리에 31B Dense와 같은 디코더 본체를 그대로 넣었다 (Gemma 4 model card).

핵심 메커니즘

[이미지]
  └─ 48×48 패치 ─┐
                 ├─ [W_proj × 1] ──┐
  └─ (x,y) 좌표 ─┘                 │
       └─ X 행렬[x] + Y 행렬[y]    │
                                   ├─→ [LLM hidden dim 토큰]
[오디오 16kHz]                     │
  └─ 40ms 프레임(640 float) ──────┘
       └─ 선형 사영
[텍스트] ──────────── 토크나이저 ──┘
                                       ↓
              [디코더 Transformer — 31B Dense 구조 재사용]
              local sliding(1024) × N → global × M (final layer global)
              global: K=V 공유, p-RoPE

비전 인코더가 27개 transformer 층이었다면 12B Unified는 한 번의 matmul로 끝낸다. 패치마다 어텐션 없이 독립 사영하고, 학습된 X·Y 행렬에서 좌표를 룩업해 더한다. "Factorized coordinate lookup"인데 2D 위치 임베딩을 두 개의 1D 룩업으로 쪼개 파라미터를 한 자리 수 줄였다.

본체 어텐션은 sliding window 1024 토큰 로컬과 full global을 교차하고, 마지막 층은 무조건 global이다. Global 층에서는 V 사영을 없애고 K 텐서를 그대로 V로 재사용한다. KV 헤드도 16에서 4로 줄였다. 마지막에 p-RoPE(Proportional RoPE) — dimension의 25%만 회전시키고 나머지는 위치 정보를 빼는 — 가 들어가는데, 옥스퍼드/DeepMind이 작년에 정리한 "저주파 채널은 의미 정보, 고주파는 위치"라는 관찰을 그대로 따랐다. 256K까지 끌고 가도 멀리 있는 토큰의 positional drift를 줄이려는 장치다.

코드 예시

vLLM 0.10에서 prefill이 큰 입력을 받으면 interleaved attention + p-RoPE 구현이 충돌해 엔진이 멈춘다는 이슈가 6/5에 올라왔다 (vllm-project/vllm #39914). 우회는 단순하다.

# llama.cpp + litert-lm 로컬 서버 (Apple Silicon · 16GB)
# blog.google/.../bringing-gemma-4-12b-to-your-laptop 의 권장 방식
from litert_lm import serve

serve.run(
    model="litert-community/gemma-4-12B-it-litert-lm",
    backend="metal",          # Apple Silicon GPU
    max_context=131072,        # 우선 128K로 잡고
    sliding_window=1024,
    kv_share_global=True,      # K=V 공유 — 메모리 ~18% 절약
    prope_fraction=0.25,       # p-RoPE 회전 비율
    prefix_cache="stateless",  # 멀티턴 prefill 우회
)
# OpenAI 호환: http://localhost:8080/v1/chat/completions

sliding_window=1024 · kv_share_global=True 두 줄이 12B의 본질 — 멀티턴에서 KV 캐시가 GB 단위로 안 부풀고 노트북 unified memory 안에 머무는 이유다.

한계·반론

벤치마크는 좁은 폭으로 갈린다. MMLU Pro 12B는 모델카드에 미공개지만, 26B A4B MoE가 82.6%, 31B Dense가 85.2%다. 발표 글에서 "26B에 근접"이라고 한 부분은 표 상으로 검증되지 않은 영역이다. 12B 구체 수치를 안 낸 점은 reviewer 사이에서 작은 논쟁거리다 (MarkTechPost — Gemma 4 12B 분석).

인코더를 빼면서 멀티모달 사전학습 비용은 도리어 늘었다는 게 발표 글에서 인정한 트레이드오프다. 비전 토큰이 디코더 본체 어텐션을 다 쓰기 때문에, 같은 이미지 한 장에 들어가는 FLOPs가 인코더 분리형보다 약 1.4배라는 게 발표 후 X에서 도는 추정치다 (@lilting_ai — 35M vs 150M 분해). prefill이 비싸진다는 뜻이다. p-RoPE 25% 회전도 회의적인 평이 있다. 0.25라는 비율 자체는 ablation이 한정적이고, 다른 비율과의 비교표가 빠져 있다.

현직 엔지니어 관점

반도체 검사 라인에서 보면 "인코더 제거"는 메모리 계층보다 튜닝 흐름을 단순화한다는 의미가 크다. 우리 쪽에서 멀티모달 모델을 다룰 때 가장 귀찮은 게 frozen 비전 인코더와 LLM 본체의 학습률·옵티마이저가 따로 노는 부분이다. 인코더가 없어지면 LoRA 어댑터 한 장으로 텍스트·이미지·오디오 분기가 동시에 움직인다. 라인 도메인 적응이 한 단계 줄어드는 것이다.

다만 prefill FLOPs가 1.4배라는 부분은 엣지 시나리오에서 그대로 발목을 잡는다. AFM 3가 NAND에서 가중치를 끌어와 DRAM 대역폭을 아끼는 방향이라면 Gemma 12B는 가중치는 작지만 활성화가 두꺼워진다. Apple Silicon unified memory에서 16GB가 마지노선이 되는 이유고, 같은 12B를 PC급 16GB DRAM + 외장 GPU 조합에 던지면 PCIe 왕복이 다시 보일 수 있다. 검증은 본인이 직접 돌려보고 다음 주 발행에 수치 정리 예정이다.
