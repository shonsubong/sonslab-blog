한 블록으로 N층을 흉내내는 길 — Mixture of Recursions와 토큰별 깊이

AI 딥다이브 2026년 05월 27일 (수) · 10:00 · 4분 읽기
목차

  • 배경
  • 핵심 메커니즘

TL;DR

  • Mixture of Recursions(MoR)는 Transformer 블록 한 묶음을 토큰마다 다른 횟수로 재귀 적용해 같은 파라미터로 더 깊은 효과를 끌어낸다 (MoR, arXiv 2507.10524).
  • 135M~1.7B 규모에서 학습 시간 19%↓, 정점 메모리 25%↓, 추론 처리량 약 2배까지 보고된다.
  • 추론 시점 컴퓨트가 새 축으로 떠오른 흐름에서 "고정 깊이 dense 스택"이 정답인지 다시 묻는 발상이다.

배경

같은 가중치를 반복 적용하는 아이디어 자체는 새롭지 않다. Universal Transformer(2018), ALBERT(2019), Looped Transformer(2023)로 이어진 계보가 있다. 본궤도에 오르지 못한 이유는 둘이었다. 토큰마다 깊이를 바꾸면 배치가 동기화를 잃었고, 재귀 단계마다 KV 캐시를 어떻게 다룰지가 모호했다.

2024년 Mixture of Depths가 토큰별 컴퓨트 게이팅을 다시 꺼냈고, 2025년 7월 KAIST·Google DeepMind·Mila 공동 연구진의 MoR이 두 한계를 한꺼번에 풀었다 (Hugging Face). NeurIPS 2025 채택 이후 2026년 들어 커뮤니티 구현이 안착하면서, "조건부 컴퓨트 + 파라미터 공유"의 결합이 다시 진지하게 다뤄지는 중이다.

핵심 메커니즘

모델을 재귀 블록 한 묶음으로 만들고, 그 블록 안의 가중치는 재귀 단계 사이에 공유한다. 토큰마다 가벼운 라우터가 몇 번 돌릴지를 결정한다.

[입력 토큰]
     ↓
  [라우터]  → 토큰별 재귀 깊이 d_i (예: 1~4)
     ↓
  ┌── 공유 블록 W ──┐
  │       ↑        │
  │   (d_i 회)      │
  └────────────────┘
     ↓
   [출력]

라우팅은 두 갈래다. 전문가 선택형(expert-choice)은 매 단계에서 상위 k개 토큰만 통과시킨다. 부하 균형이 자연스럽지만 미래 정보 누설 우려가 있다. 토큰 선택형(token-choice)은 토큰이 시작할 때 자기 깊이를 정해 끝까지 간다. 인과성은 지키지만 라우터 학습이 까다롭다. KV 캐시는 단계별로 그 깊이까지 도달한 토큰의 키·값만 저장한다. 평균 깊이가 얕을수록 메모리 절감이 커지는 구조다.

코드 / 수식

라우터와 재귀 루프만 떼어내면 그림이 단순해진다.

import torch, torch.nn as nn

class MoRStack(nn.Module):
    def __init__(self, dim, max_r=4):
        super().__init__()
        self.shared = TransformerBlock(dim)   # 단일 가중치
        self.router = nn.Linear(dim, max_r)
        self.max_r  = max_r

    def forward(self, x):
        depth = self.router(x.detach()).argmax(-1) + 1   # [B,T], 1..max_r
        out = x
        for step in range(self.max_r):
            alive   = (depth > step).unsqueeze(-1)
            updated = self.shared(out)
            out     = torch.where(alive, updated, out)   # 깊이 남은 토큰만 갱신
        return out

실제 구현은 Gumbel-softmax나 straight-through 추정으로 라우터를 미분 가능하게 만들고, 재귀별 KV 캐시까지 함께 관리한다. 공식 구현은 GitHub raymin0223/mixture_of_recursions에 공개돼 있다 (저장소).

한계·반론

좋아 보이는 수치 뒤에 그늘이 있다. 토큰별 가변 깊이는 SIMT 동기화를 깨뜨려, 이론 FLOPs와 측정 처리량의 간극이 크다. 보고된 2배 처리량은 프리필 단계의 라우팅 비용을 잘 숨긴 조건이고, 짧은 컨텍스트·작은 배치에서는 라우터 오버헤드가 오히려 손해다.

학습 안정성도 따로 본다. 같은 블록을 4회 이상 반복하면 유효 기울기 경로가 길어진다. 1.7B까지는 안정적으로 학습됐다고 보고됐지만, 70B 규모에서도 그럴지는 공개된 결과가 없다.

재귀별 KV 캐시 역시 토큰 평균 깊이가 작아야 이득이다. 코드·수학처럼 대부분 토큰이 최대 깊이까지 가는 워크로드에선 메모리 절감 효과가 거의 사라진다.

현직 엔지니어 관점

반도체·온디바이스 시각에서 흥미로운 지점은 가중치 W가 하나라는 것이다. 32층 dense는 매 토큰마다 HBM에서 가중치를 끌어와야 하지만, MoR은 같은 블록을 재사용하니 온칩 SRAM 상주와 L2 캐시 히트율 양쪽에서 유리하다. 메모리 한계를 정공법이 아니라 우회로 푸는 방식이다.

모바일 NPU에서도 4층 블록으로 유효 깊이 16~32를 흉내내 DRAM 트래픽이 한 자릿수로 줄어든다. 다만 가변 분기는 NPU 정적 그래프 컴파일과 충돌한다. 양산에서는 고정 깊이와 적응 깊이를 같은 가중치로 전환하는 하이브리드가 현실적이다. 클라우드에선 적응 모드의 처리량을, 디바이스에선 고정 모드의 예측 가능성을. 한 모델로 두 시장을 노릴 수 있다는 점이 진짜 매력이다.
