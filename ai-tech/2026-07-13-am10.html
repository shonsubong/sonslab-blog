Wait'에서 시작되는 무한 반복 — 토큰 하나를 다시 가르쳐 멈춘다

AI 딥다이브 2026년 07월 13일 (월) · 10:00 · 6분 읽기
목차

  • 배경 (Why now)
  • 핵심 메커니즘

TL;DR

  • Liquid AI가 7월 7일 Antidoom을 공개했다. 추론 모델이 "Wait, let me reconsider…" 같은 구절을 컨텍스트가 바닥날 때까지 되풀이하는 무한 반복(doom loop)을, 루프가 시작되는 토큰 하나만 재학습해 없앤다 (Liquid AI — Reducing Doom Loops with FTPO).
  • 효과는 뚜렷하다. Qwen3.5-4B의 루프 발생률이 22.9%에서 1%로, LFM2.5-2.6B 초기 체크포인트는 10.2%에서 1.4%로 떨어졌고, 수학·코딩 점수는 전반적으로 올랐다.
  • 코드·데이터셋·학습 파이프라인이 Apache 2.0으로 전부 공개됐다. 생성 단계를 빼면 GPU 한 장으로 한두 시간이면 학습이 끝난다.

배경 (Why now)

소형 추론 모델을 써 본 사람이라면 이 증상을 안다. 어려운 문제를 만나면 "Wait", "So", "Alternatively"를 반복하다가 컨텍스트 한도를 다 채우고 끝난다. 답은 없고 토큰만 사라진다. 파라미터가 4B 이하인 모델일수록, 사고 과정이 길수록 심하다.

지금까지의 대응은 추론 시점에 repetition_penalty로 출력 분포를 눌러 두는 것이었는데, Liquid AI 표현대로 이건 반창고다. 반복만 억제하는 게 아니라 정상적인 재언급까지 깎아서 성능이 같이 내려간다. 강화학습으로 고칠 수도 있지만 보상 설계와 온라인 롤아웃 비용이 크다.

7월 7일 공개된 Antidoom이 화제가 된 건 접근이 극단적으로 좁아서다. 문제가 되는 토큰 위치 하나만 겨냥한다. "올해의 흐름은 더 큰 모델이 아니라 실패 모드의 체계적 제거"라는 반응이 나온 것도 이 맥락이다 (@LiorOnAI thread). 온디바이스 추론 모델(LFM2.5-1.2B-Thinking 같은 1GB 미만급)을 미는 회사가 이 문제를 먼저 정리한 것도 우연이 아니다. 작은 모델일수록 루프가 잦으니까.

핵심 메커니즘

루프는 세 가지 힘이 겹칠 때 생긴다. 첫째, 과학습된 토큰. 합성 추론 데이터를 많이 먹은 모델은 "Wait" 같은 담화 표지의 사전 확률이 높고, 막힌 순간 이 토큰들이 기본값처럼 튀어나온다. 실제로 LFM2.5-2.6B 초기 체크포인트에서 루프 시작 토큰 1위는 ' the'(11.4%), 그 뒤가 ' So', 'Alternatively', 'Wait'였다. 둘째, 자기강화. 한 번 나온 구절은 문맥 때문에 다시 나올 확률이 커지고, 반복될수록 각 토큰의 확률이 1로 수렴한다. 셋째, 저온 샘플링. 추론 모델은 재현성 때문에 온도를 낮게 두는데, 확률이 1 근처로 굳은 루프는 온도를 올려도 못 빠져나온다.

Antidoom 파이프라인은 이렇다.

[루프 유발 프롬프트 모음] → [저온 생성] → 반복 감지
                                  │  (60자 이상 구간이 4회 이상 반복)
                                  ▼
              첫 반복의 첫 토큰 = rejected  (예: ' Wait')
              같은 위치 top-k 대안 최대 20개 = chosen
                                  ▼
        [FTPO 학습: 이 위치의 logit만 움직이고,
         나머지 어휘는 기준 모델에 가깝게 묶어 둔다]

학습 알고리즘 FTPO(Final Token Preference Optimization)는 DPO의 변형인데 네 가지가 다르다. 생성 도중의 마지막 토큰 하나만 학습하고, chosen을 여러 개 두어 확률이 특정 대체 토큰 하나로 쏠리지 않게 하며, softmax를 거치지 않고 logit 공간에서 기준 모델과의 발산을 계산해 무관한 토큰에 그래디언트가 튀는 걸 막고, 학습 대상 logit과 나머지 어휘에 서로 다른 강도의 정규화를 건다. LoRA rank 128~256으로 1 에폭이면 되고, chosen_win(chosen이 rejected를 이기는 비율)이 0.35쯤 됐을 때 조기 종료하는 게 요령이라고 한다.

코드 예시

공개된 파이프라인은 명령 한 줄로 생성부터 학습·병합까지 돈다 (GitHub — Liquid4All/antidoom).

uv run antidoom -c configs/default.yaml -r runs/antidoom1 \
  --temp 0.01 \
  --model-name LiquidAI/LFM2.5-1.2B-Base

학습 데이터 한 행은 이렇게 생겼다. 정답 라벨이 없다. "이 위치에서 이 토큰만 고르지 마라"는 국소 선호만 가르친다.

{
  "context_with_chat_template": "... 루프 직전까지의 문맥 ...",
  "rejected_decoded": " Wait",
  "multi_chosen_decoded": [" Therefore", " The"],
  "repetition": {"repeat_start_char": 1526, "rejected_token_index": 342}
}

수학이나 코딩 지식을 새로 넣는 게 아니라, 원래 풀 수 있던 답에 도달하지 못하게 막던 장애물만 치우는 구조다. 점수 상승이 전부 루프 감소에서 왔다는 설명과 일치한다.

한계·반론

가장 큰 함정은 과학습이다. 조금만 오래 돌리면 모델이 망가지면서 오히려 새 루프가 생긴다고 저자들이 직접 적어 두었다. 한 라운드로 끝나지 않는 경우도 있다. 기존 루프를 막으면 다른 토큰이 새 루프의 시작점으로 떠올라 추가 라운드가 필요하다. 억제 대상인 "Wait"가 원래는 유용한 전략 전환·검증 신호라는 점도 긴장 요소다. 정규화로 완화한다지만, 억제가 과하면 추론 자체가 손상된다.

근본 치료가 아니라는 지적도 가능하다. 순환 추론을 분석한 Duan 등의 연구는 같은 말이 반복되기 전에 같은 생각의 반복이 먼저 온다고 본다 (arXiv — Circular Reasoning). Antidoom은 그중 텍스트 단계만 차단하는 셈이다. 흥미로운 부산물도 있다. 루프를 없애고 나니 온도 1.0에서 점수가 오히려 낮아졌는데, "추론 모델엔 높은 온도가 좋다"던 통념이 사실은 루프 회피 효과와 뒤섞인 착시였을 수 있다는 얘기다.

현직 엔지니어 관점

온디바이스에서 무한 반복은 품질 문제이기 전에 전력 문제다. 컨텍스트 끝까지 도는 루프는 최대 길이 디코드와 같은 말이라, NPU 점유·발열·배터리 소모가 전부 최악 조건으로 간다. 런타임 디코더에 반복 페널티 로직을 얹는 것보다 가중치 단계에서 실패 모드를 제거하고 배포하는 쪽이 펌웨어 관리 면에서도 깔끔하다. 생성 한 시간, 학습 한두 시간이면 도는 파이프라인이니 소형 모델을 파인튜닝할 때마다 마지막 후처리 공정으로 넣을 만하다. 집 PC에서 로컬 모델을 돌리다 이 증상에 토큰을 날려 본 입장에서는, 모델 교체 없이 어댑터 하나로 고칠 수 있다는 점이 제일 반갑다. 다만 여러 라운드가 필요한 경우의 검증 비용은 직접 돌려 보고 확인이 필요하다.
