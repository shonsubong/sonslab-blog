Transformer가 SSM과 7대 1로 손잡은 이유 — 하이브리드 백본이 롱컨텍스트 표준이 된 길

AI 딥다이브 2026년 05월 16일 (토) · 10:00 · 4분 읽기
목차

TL;DR

  • 2025~2026 롱컨텍스트 백본이 풀-어텐션도 풀-SSM도 아닌, Mamba 계열 SSM 7~9개에 어텐션 1개를 끼우는 비율로 수렴했다. Jamba 1.5·Samba·Zamba2·Hymba·Falcon-Mamba가 같은 처방이다.
  • SSM 단독은 in-context recall이 약하고, 어텐션 단독은 KV 캐시가 컨텍스트와 함께 폭발한다. 한 줌의 어텐션이 retrieval을 살리고, 다수의 SSM이 KV 폭발을 죽인다.
  • 256k 컨텍스트에서 KV 메모리가 6~10배 줄고 디코딩이 사실상 일정 메모리로 흐른다. 가중치 양자화 다음 큰 한 수가 온디바이스 쪽에서 그려진다.

배경 (Why now)

5월 첫째 주 Liquid AI가 LFM2 6.7B의 백본을 "단변 컨볼루션 + sliding-window 어텐션 1/8" 비율로 공식화했고 (Liquid AI — LFM2 blog), 같은 주 NVIDIA Research가 Hymba 후속을 NeurIPS 2026 사전공개로 풀었다. 4월 말 IBM Granite 4.0(Mamba+Transformer)이 Apache-2.0으로 풀린 것도 같은 흐름이다 (IBM — Granite 4).

거슬러 올라가면 Jamba 1.5가 첫 양산형 하이브리드였고, Microsoft Samba, Falcon Mamba 7B, Zamba2, Hymba가 같은 해 줄지어 같은 처방을 들고 나왔다. 더 이상 "Mamba 대 Transformer"가 아니라 "둘을 어떤 비율로 섞는가"가 토론 주제다.

핵심 메커니즘

[입력] → SSM SSM SSM SSM SSM SSM SSM [Attn] SSM SSM SSM SSM SSM SSM SSM [Attn] ... → [출력]
         └─── O(N) 메모리, state h만 운반 ───┘     └─ KV 캐시는 1/8 레이어에만 ─┘

SSM 레이어는 토큰을 압축된 상태 h_t로 흘려보낸다. 컨텍스트가 늘어도 메모리가 N에 비례해 부풀지 않는다. 어텐션 레이어는 KV 캐시를 들고 있되 전체 N층 중 1/8만 깐다. SSM의 약한 in-context 정확도(Needle-in-Haystack 미스 등)는 끼워 넣은 어텐션이 보정한다. Hymba 논문은 SSM이 "요약자", 어텐션이 "정확 인용자" 역할을 한다고 정리한다.

코드 / 수식 예시

import torch.nn as nn

class HybridBackbone(nn.Module):
    """SSM 7 + Attention 1 비율 (Samba/Granite-4 풍 단순화)."""
    def __init__(self, d_model, n_layers=64, attn_every=8, win=2048):
        super().__init__()
        self.layers = nn.ModuleList()
        for i in range(n_layers):
            if (i + 1) % attn_every == 0:
                self.layers.append(SlidingWindowAttn(d_model, window=win))
            else:
                self.layers.append(Mamba2Block(d_model))

    def forward(self, x):
        for layer in self.layers:
            x = x + layer(x)        # residual
        return x

Mamba SSM의 상태 전이는 h_t = A·h_{t-1} + B·x_t, 출력은 y_t = C·h_t. 핵심은 A·B·C가 입력 의존(selective)하게 매 스텝 달라진다는 점이고, 이게 단순 RNN과 Mamba를 가른다. 어텐션 레이어는 sliding-window 어텐션을 쓰는 경우가 많아 KV가 win 토큰만큼만 살아남는다.

한계·반론

  • in-context recall: 풀-어텐션 대비 100k 이상에서 정밀 needle 검색이 떨어진다는 보고가 RULER·BABILong에서 일관되게 나온다. 어텐션 비율을 1/8에서 1/4로 올리면 회복되지만 KV 절감 효과도 그만큼 줄어든다.
  • 학습 안정성: SSM의 A 매트릭스 초기화·discretization은 from-scratch에서 까다롭다. Mamba2가 SSD로 단순화했지만 노하우가 어텐션만큼 두텁지 않다.
  • 벤치마크 함정: 합성 long-context 벤치에서 강해도 multi-doc QA처럼 위치 분산된 실제 워크로드에서 깨지는 케이스가 있다.

현직 엔지니어 관점 한 문단

온디바이스 추론에서 KV 캐시는 가장 큰 적이다. 8B 모델·32k 컨텍스트만 돼도 KV가 모바일 DRAM 예산을 통째로 먹는 일이 흔하다. SSM 7 + Attn 1 비율이면 같은 컨텍스트에서 KV가 한 자릿수 GB로 떨어지고, 디코드 토큰당 메모리가 사실상 상수다. FP4·MoE 다음 큰 한 수가 여기서 나온다고 본다. 다만 NPU 컴파일러가 Mamba2의 selective scan을 효율적으로 매핑하느냐가 관건이고, 가중치 양자화 커널과 달리 scan 커널은 벤더별 격차가 아직 크다.
