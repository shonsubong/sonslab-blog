어텐션이 다음 층을 미리 본다 — SparDA가 PCIe 병목을 우회한 방법

AI 딥다이브 2026년 06월 04일 (목) · 10:00 · 5분 읽기
목차

TL;DR

  • NVIDIA Labs와 MIT Han Lab이 어제(6/3) 공개한 SparDA는 Q/K/V 옆에 네 번째 사영(Forecast)을 끼워 넣어 "다음 층이 어떤 KV 블록을 볼 것인지" 미리 추정한다 (arXiv 2606.04511).
  • 이 사전 추정으로 CPU→GPU PCIe 전송을 현재 층 연산과 오버랩하고, 희소 선택의 O(T²) 비용도 GQA 그룹당 1개 헤드로 줄였다.
  • 8B 희소-사전학습 모델 두 개에서 정확도는 보존하면서 prefill 1.25배·decode 1.7배, 배치를 키우면 비오프로드 대비 decode 처리량 5.3배가 나왔다.

배경 (Why now)

지난주(5/28~) Opus 4.8가 1M 컨텍스트를 디폴트로 켰고, 그 다음날 NVIDIA는 6칩 코디자인 Rubin 플랫폼이 "Blackwell 대비 추론 토큰 비용 10배 감소"를 표방한다고 다시 강조했다 (NVIDIA — Rubin platform). 두 흐름이 만나는 곳이 정확히 SparDA가 다루는 문제다. 1M 토큰을 다루려면 단일 GPU의 HBM만으로는 KV 캐시가 안 들어가 호스트 DRAM으로 내려야 하고, PCIe 대역폭이 어텐션 지연을 잡아먹는다. 5/25에 다룬 KV 캐시 양자화가 "캐시를 작게 만든다"는 축이었다면, SparDA는 "캐시는 그대로 두되 옮기는 일을 숨긴다"는 축이다.

핵심 메커니즘

기존 희소 어텐션은 현재 층 Q로 KV 블록을 골라 GPU로 끌어오는데, 이 작업이 직렬이라 PCIe 전송이 끝날 때까지 SM이 놀았다. SparDA는 한 발 앞서 본다.

[Layer N 실행 중]
  ├─ Q_N, K_N, V_N  : 현재 층 어텐션
  └─ Forecast_N      : "Layer N+1이 볼 KV 블록"을 추정
                       │
                       ▼
                [CPU→GPU prefetch 시작]
                       │
[Layer N+1 시작 시점에는 KV가 이미 GPU 도착]
  ├─ Q_(N+1), K_(N+1), V_(N+1)
  └─ Forecast_(N+1)  : N+2를 또 예고

Forecast는 어텐션 Q와 독립이라 GQA 그룹당 하나만 두면 충분하고, 추가 파라미터는 전체의 0.5% 미만이다. 학습은 본체를 동결한 채 Forecast만 원래 선택기의 어텐션 분포에 매칭시키는 식으로 끝난다.

코드 / 의사코드

논문 본문 알고리즘을 GQA 기준으로 압축하면 다음과 같다.

# 본 모델은 동결. forecast head만 학습.
# n_groups = GQA 그룹 수, B = KV 블록 크기
class ForecastHead(nn.Module):
    def __init__(self, d_model, n_groups, d_head):
        super().__init__()
        self.proj = nn.Linear(d_model, n_groups * d_head, bias=False)

    def forward(self, x):              # x: [batch, seq, d_model]
        return self.proj(x)            # [batch, seq, n_groups*d_head]

# 한 층의 forward
f_logits = forecast_head(hidden_N)     # 다음 층의 KV 블록 점수
topk_blocks = topk(f_logits, k=K)      # 블록 단위 선택
launch_prefetch(layer_N1_kv_cpu, topk_blocks)  # 비동기 PCIe DMA

# 현재 층은 평소대로 진행 — 전송과 SM 연산이 같은 시간축에서 흐름
out_N = sparse_attention(Q_N, K_N, V_N, current_topk)

# 학습 손실: distillation
loss = KL(softmax(orig_selector(Q_N1, K_N1)), softmax(f_logits))

핵심은 Forecast가 Q에 의존하지 않는다는 점이다. 그래서 Layer N의 hidden state만 있으면 N+1의 선택이 가능하고, 그 사이에 PCIe DMA가 끝난다.

한계·반론

먼저 SparDA는 "희소 어텐션으로 사전학습된 모델" 위에 얹는 사후 처리다. 밀집 어텐션으로 학습한 기존 8B/70B 체크포인트에 바로 끼우면 정확도가 보존되리라는 보장은 논문 범위 밖이고, 다른 baseline에서 검증할 부분이 남는다. 둘째로 Forecast의 KV 블록 추정이 어긋나면 prefetch한 블록이 버려지고 PCIe 트래픽이 헛돈다. 논문은 평균치만 보고하므로 worst-case latency 분산은 후속 평가가 필요하다. 셋째, 결국 PCIe Gen5의 물리적 대역폭(~64GB/s)이 천장이라, 컨텍스트가 더 커지면 prefetch overlap만으로는 풀리지 않는다. Rubin 세대의 CX9 NIC·NVLink 6 같은 패브릭 진화가 같이 와야 하는 이유다 (VideoCardz — Vera Rubin NVL72).

현직 엔지니어 관점

이 구조는 데이터센터에만 갇히지 않는다. 온디바이스 NPU에서도 LPDDR↔SRAM 전송이 정확히 같은 모양의 병목이다. 모바일은 PCIe 대신 UFS·LPDDR5X가 있고, 단일 칩 안에서도 SLC L3↔NPU 로컬 메모리 사이 DMA가 어텐션 지연의 절반 이상을 잡아먹는다. Forecast 같은 "다음 층 사전 예고" 사영은 NPU 컴파일러 입장에선 어차피 정적 스케줄링으로 풀어야 하는 문제라, 모델 측에서 명시적 신호를 주면 컴파일러 부담이 크게 줄어든다. 현장 적용은 빨라야 내년이지만, 8B 모델·0.5% 추가 파라미터로 1.7배 디코드 가속을 본 결과는 온디바이스 1M 컨텍스트 데모가 더 빨리 가능하다는 신호로 읽힌다. 다만 sparse pretraining부터 다시 해야 한다는 전제는 양산 입장에선 무거운 짐이다 — Forecast를 LoRA처럼 사후 부착할 수 있는지가 다음 반년의 관건이다.
