다리에 트랜지스터를 심었다 — TSMC가 칩 사이 배선을 능동회로로 바꾼 이유

AI 딥다이브 2026년 06월 19일 (금) · 10:00 · 5분 읽기
목차

  • 배경 (Why now)

  • 코드 / 수식 예시

TL;DR

  • ISSCC 2026에서 TSMC가 칩과 칩을 잇는 실리콘 다리(LSI)에 트랜지스터를 넣은 Active LSI(aLSI)를 공개했다. 수동 금속 배선을 능동 송수신 회로로 바꿨다.
  • 다리에 ETT(Edge-Triggered Transceiver)를 두니 윗칩 PHY 깊이가 1043µm에서 850µm로 줄고, 비트당 에너지는 0.36pJ에 머문다.
  • AMD MI450급으로 보이는 테스트 패키지에서 HBM4 스택 2개가 다리 하나를 공유하는 구성까지 나왔다. 다이 면적을 연산으로 되돌리려는 신호다.

배경 (Why now)

2026년 2월 ISSCC에서 메모리·패키징 발표가 쏟아졌다. 삼성은 36GB·12단 HBM4를 2048핀·3.3TB/s로 시연했고, 핀당 13Gb/s까지 끌어올렸다 (wccftech — ISSCC 2026 Samsung 36GB HBM4). 대역폭이 이렇게 올라가면 병목은 메모리 셀이 아니라 칩과 칩을 잇는 다이 간 배선으로 옮겨간다. HBM4부터 베이스 다이를 로직 공정(삼성 SF4)으로 분리한 것도 같은 맥락이다. 직전 분석에서도 SemiAnalysis가 ISSCC 패키징 세션을 정리하며 aLSI를 "다음 세대 가속기엔 불가피한 전환"으로 짚었다 (SemiAnalysis — ISSCC 2026 CPO·HBM4·Active LSI).

핵심 메커니즘

기존 CoWoS-L이나 EMIB의 다리는 수동 금속 채널이다. 거리가 길어질수록 신호가 무너지므로 윗칩의 송수신 PHY가 큰 드라이버와 증폭기를 떠안는다. aLSI는 이 다리 안에 능동 회로를 심어 신호 조건을 다리 쪽으로 내린다.

[윗칩 A] --TX--+                            +--RX-- [윗칩 B]
               |   [ ETT: Cac → 증폭 → 출력 ]   |
               +------- aLSI 브리지 다이 -------+
                (수동 금속 → 능동 트랜지스터로 교체)

ETT는 드라이버, AC 커플링 커패시터(Cac), 양·음 피드백 증폭기, 출력단으로 구성된다. 신호를 Cac에 통과시키면 전이 구간의 모서리가 도드라지고, 이중 루프 증폭기가 그 모서리를 잡아 전압을 안정화한다. 그래서 "엣지 트리거"라 부른다. 조건 회로가 다리로 내려가니 윗칩은 작은 프리드라이버만 두면 되고, 수신단 증폭도 덜어낼 수 있다.

코드 / 수식 예시

링크 예산을 거칠게 잡아본 개략 모델이다.

# aLSI 단일 레인 개략 모델 (ISSCC 2026 발표값 기반)
v_swing = 0.75          # 동작 전압(V), 이때 32 Gb/s
rate    = 32e9          # 32 Gb/s/lane
e_total = 0.36e-12      # 총 0.36 pJ/b
e_ett   = 0.07e-12      # 다리 ETT가 더하는 몫
e_phy   = e_total - e_ett   # 윗칩 PHY 몫 = 0.29 pJ/b

lanes = 64 + 64         # TX 64 + RX 64
bw    = rate * 64 / 8 / 1e9          # 한 방향 GB/s
pwr   = e_total * rate * lanes * 1e3 # mW
print(round(bw, 1), "GB/s,", round(pwr, 1), "mW")

ETT가 더하는 비용은 0.07pJ/b뿐이다. 그 대가로 PHY 깊이가 1043µm에서 850µm로, 범프 피치가 45µm에서 38.8µm로 줄었다. 64 TX·64 RX 레인이 388µm 쇼어라인, 0.330mm² 면적에 들어간다. 줄인 자리는 연산·메모리·IO로 되돌린다.

한계·반론

화려해 보여도 함정이 있다. 첫째, 다리에 트랜지스터를 넣는 순간 적층 다이 안에 발열원이 하나 더 생긴다. 0.07pJ/b가 작다지만 수천 레인이 모이면 무시하기 어렵다. 둘째, 이 송수신기는 "UCIe 유사"일 뿐 진짜 UCIe가 아니다. 표준은 육각 범프맵을 요구하는데 여기선 맨해튼 격자를 썼다. 표준 호환을 일부 포기하고 면적을 택한 셈이라, 멀티벤더 칩렛 생태계에 그대로 들어맞지는 않는다. 셋째, 시연은 테스트 비히클이다. KGD·KGS·KGP 단계별 검증을 보여줬지만 양산 수율은 별개 문제다.

현직 엔지니어 관점

배선을 수동에서 능동으로 바꾼다는 발상이 흥미롭다. 측정 장비에서 긴 케이블의 신호 열화를 리피터로 복원하는 것과 본질이 같다. 다만 칩 안에서는 그 리피터가 곧 열이고 면적이다. 온디바이스 쪽으로 내려보면 모바일 AP의 칩렛화도 결국 같은 벽에 부딪힌다. 다이 간 대역폭을 키우려고 PHY를 키우면 배터리와 발열이 먼저 손을 든다. aLSI처럼 신호 조건 회로를 중간 다리로 옮기는 접근은, 전력 예산이 빠듯한 엣지에서 오히려 더 매력적일 수 있다. 다만 모바일은 유기 기판·비용 압박이 심해 실리콘 브리지를 그대로 쓰기는 어렵다. 저비용 브리지와 ETT 아이디어를 어떻게 접목하느냐가 관건이라고 본다. (확인 필요: 모바일급 패키지에 aLSI를 적용한 공개 사례는 아직 보이지 않는다.)
