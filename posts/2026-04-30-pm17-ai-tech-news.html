Claude Sonnet 4.5의 1M 컨텍스트 베타가 오늘로 끝난다 — 그리고 Tesla FSD가 한 모델로 합쳐졌다

퇴근 버스. 자리 잡고 X 한 번 쓸어보니까 새벽·점심에 적은 결과 다른 라인이 두 개 보인다. 하나는 오늘 자정에 진짜로 닫히는 Claude의 1M 컨텍스트 베타 라인, 다른 하나는 어제·그제 사이에 와이드 롤아웃이 확정된 Tesla FSD V14.3.2의 "하나의 모델" 라인. 둘 다 "써본 사람이 직접 영향을 받는" 결의 뉴스라 짧게 묶어둔다.

오늘 끝나는 1M 컨텍스트 베타 — 정확히 어디가 닫히고, 어디는 안 닫히는가

Anthropic 공지대로 오늘(4월 30일) 자로 Claude Sonnet 4.5와 Sonnet 4의 context-1m-2025-08-07 베타 헤더가 효력을 잃는다. 이 헤더로 1M 토큰까지 늘려 쓰던 라인이 오늘 자정 이후엔 200K로 다시 잘린다는 뜻이고, 200K를 넘기는 요청은 그대로 에러로 떨어진다. 200K 이하로만 쓰던 케이스는 그대로 굴러간다 — 잘리는 건 "긴 컨텍스트 베타 위에서만 굴러가던 트래픽" 뿐이다. (Pasquale Pillitteri — Anthropic Retires the 1M Context Beta: Migrate Before April 30, 2026)

다만 1M 자체가 사라지는 게 아니라는 게 핵심이다. 3월 13일에 Sonnet 4.6/Opus 4.6에서 1M 컨텍스트가 GA로 풀렸다. 베타 헤더 없이, 표준 가격에서 그대로 1M까지 쓸 수 있다. 4.5/4 베타 시절에 붙어 있던 "input 가격이 두 배" 의 롱컨텍스트 프리미엄이 GA에서는 사라진 게 결의 큰 변화다. 즉 4.6 라인으로 옮기면 더 비싸지지 않고도 1M까지 늘릴 수 있다는 그림.

엔지니어 자리에서 신경 쓰이는 건 두 군데다. 하나는 Claude Code 쪽 자동 라우팅. Claude Code MAX로 매일 굴리는 입장에서 보면, 4.5 위에서 굴러가던 긴 세션을 명시적으로 바꿔준 게 아니라 그냥 "sonnet" 으로 잡고 쓰던 케이스가 많을 텐데, 4.6으로 자동 승격된 환경이라면 오늘 자정 이후에도 그대로 1M이 살아 있다. 4.5에 핀해둔 환경이 있다면 베타 헤더가 죽기 전에 4.6 또는 Opus 4.6으로 옮기는 게 안전하다. 다른 하나는 써드파티 SDK·미들웨어. LangChain·LlamaIndex·LiteLLM 같은 라우팅 레이어가 모델 ID를 기존 claude-sonnet-4-5 로 하드코딩해놓은 케이스가 의외로 많다. "오늘부터 갑자기 200K에서 잘리네" 라는 이슈가 새벽 사이에 X에 깔리기 시작할 가능성이 높다.

개인적인 얘기 한 줄. 이번 주말 집에서 오픈소스 코드 정리할 때 Sonnet 4.6 + 1M으로 한 번 더 굴려봐야겠다. 베타 헤더 안 붙이고도 프리미엄 안 붙는 1M이라는 게 실제 사용감이 어떻게 다른지 — 4.5 베타 때처럼 "긴 컨텍스트 들어가면 답이 흐릿해진다" 라는 결이 정말 줄어드는지 직접 보고 싶다. 회사 자리에서는 어차피 Claude Code 못 쓰니까 이건 집에서만 가능한 실험.

Tesla FSD V14.3.2 — Smart Summon·FSD·Robotaxi가 하나의 모델로 합쳐졌다

다른 라인. 어제(4월 28일) Tesla가 FSD V14.3.2의 와이드 롤아웃을 확정했다. 핵심 한 줄은 "Robotaxi에 들어가 있던 모델 = Smart Summon 모델 = 일반 FSD 모델" 이 됐다는 것. 그동안은 같은 회사가 만들었어도 코덱이 분기되어 있던 라인이 단일 foundation 모델로 합쳐졌다.

엔지니어로서 이 통합이 묵직한 이유는 데이터 플라이휠의 모양이 바뀌기 때문이다. 기존엔 Austin·Dallas·Houston의 무감독 Robotaxi에서 쌓인 엣지케이스가 일반 FSD 라인으로 직접 흘러들지 않았다. 이번 V14.3.2부터는 "Robotaxi 한 대에서 한 번 풀린 까다로운 상황의 학습이 다음 OTA에서 일반 차량에도 그대로 들어오는" 구조가 된다. 반대 방향도 같다 — 수십만 대 일반 차량에서 잡힌 코너케이스가 Robotaxi 라인의 폴리시도 같이 끌어올린다. 한 모델이 양방향으로 데이터를 빨아들이는 그림이다. (Tesla Oracle — Tesla rolls out FSD v14.3.2 (2026.2.9.8))

성능 디테일도 같이 풀렸다. AI 컴파일러와 런타임이 MLIR로 다시 쓰여서 반응 속도가 20% 빨라졌다. Smart Summon을 호출하면 차가 "체감상 명확히 더 빨리 움직인다" 는 첫 사용기들이 X에 같이 도는데, @WholeMarsBlog가 올린 영상에서 보면 "앱 누른 직후 0.5초 안에 차가 움직이기 시작한다" 는 톤이다. MLIR로 갈아탄 게 단순 컴파일 시간 단축이 아니라 런타임 inference latency에 직접 닿았다는 게 결의 핵심.

Tesla 투자자 관점에서 보면, 이번 통합은 4월 초 Q1 어닝콜에서 푼 "한 모델로 합치겠다" 라인의 첫 매출 신호에 가깝다. Robotaxi 확장(현재 Austin + Dallas + Houston)이 일반 FSD 사용자 데이터로 가속되는 구조가 됐으니까, 다음 분기에 "Robotaxi 도시 추가 속도" 가 한 단계 빨라질 가능성이 있다. 다만 이건 어디까지나 모델 통합이 깔아준 기술적 가능성이고, 실제 도시 확장은 규제·보험 라인이 같이 풀려야 한다는 단서가 같이 붙는다.

짧게 — 애플 iOS 27 사진 AI가 Bloomberg에 새고 있다

오늘 밤 미국 AMC에 애플 어닝이 풀린다. 그 직전에 Mark Gurman이 한 번 더 깐 iOS 27 디테일이 결을 잡아준다 — Extend, Enhance, Reframe 세 개의 AI 사진 편집 기능이 들어가는데, 모두 온디바이스 inference로 돈다. Apple Silicon M4·A18 Pro 라인 위에서 이미지 생성형 모델을 직접 굴린다는 얘기. 아직 정식 발표 전이라 디테일은 루머 단계고 WWDC 2026(6월 8일)에서 공식 발표가 나올 거란 게 일반적인 관측이다.

새벽에 정리한 알파벳·메타·마이크로소프트 capex 그림에서 "AI 매출이 어디로 잡히는가" 가 핵심이었는데, 애플은 정확히 그 반대편 결에 서 있다. capex가 동급 회사 대비 1/10 수준인데도 "디바이스에서 도는 AI" 라는 다른 카드를 들고 들어온다. 오늘 밤 콜에서 capex 가이던스보다 iPhone 17 사이클의 Apple Intelligence 어태치율이 어떤 톤으로 풀리는지가 더 묵직한 한 줄이 될 가능성이 높다.

퇴근 버스에서 한 줄

오늘 자정 1M 베타가 닫히는 라인이랑, 한 모델로 합쳐진 FSD 라인이 우연히 같은 날에 겹친 게 아니다 — 둘 다 "베타로 갈라져 있던 라인이 GA로 한 갈래로 모이는" 결의 이벤트다. 모델 컨텍스트도, 자율주행 폴리시도, 한 분기 안에 "여러 라인을 동시에 굴리던 시즌이 끝나가는" 신호가 같이 잡히는 중이다. 다음 라운드는 각자가 깔아둔 단일 라인을 얼마나 멀리 끌고 가는가가 평가의 결이 될 거 같다. 집 도착하면 4.6 + 1M으로 주말 코드 한 번 돌려볼 예정.
