Anthropic이 Claude 에이전트에 잠을 재웠다 — dreaming·outcomes·orchestration이 한 자리에 묶였다

토요일 밤. 새벽에 백악관 EO 라인을 짚고, 점심에 Kimi K2.6 결을 풀고, 오후에 DeepSeek V4-Flash까지 한 번 굴려보고 나니 책상 위에 진한 커피 한 잔만 남았다. 4건째 글이라 어깨가 무거워질 자리인데, 오히려 결이 가벼워지는 라인 하나가 X 타임라인에서 묵직하게 돌고 있다 — Anthropic Managed Agents에 풀린 dreaming·outcomes·multi-agent orchestration 셋이다. 5월 6일 Code with Claude 자리에서 키노트로 깔린 결이긴 한데, 이번 주 내내 Code Review·Remote Agents 라인이 헤드라인을 다 가져가는 동안, 정작 에이전트 자리의 학습 루프를 한 번에 다시 그린 이 셋이 한 단 뒤로 밀려 있었다. 주말 밤 자리에서 한 번 정리해두는 게 맞다.

dreaming — 세션이 끝나도 에이전트가 안 자게 만든 결

먼저 VentureBeat 라인이 풀어둔 톤. dreaming은 세션과 세션 사이에 도는 스케줄 프로세스다. 과거 세션 트랜스크립트를 한 번 훑고, 반복 패턴을 잡고, 에이전트의 메모리 스토어를 정돈하는 결. 원본 세션 데이터는 안 건드리고, 메모리 자리만 큐레이팅하는 톤이다. The New Stack 라인이 짚어둔 한 줄이 더 또렷하다 — "에이전트가 자기 세션을 다시 보고, 자기가 놓친 자리를 직접 수정한다."

핵심 결은 메모리와의 관계다. 기존 memory 자리는 세션 안에서 정보를 붙드는 결이고, dreaming 자리는 세션 사이에 그 메모리를 정리·개선하는 결이다. 두 자리가 분리되어 있다는 톤이 중요하다. 사람으로 치면 작업 기억과 수면 중 강화 자리를 따로 잡은 그림. SiliconANGLE 라인이 풀어둔 톤대로 — 자동 업데이트 라인과 사람이 검토 후 반영 라인 양쪽을 다 풀어놨다. 엔터프라이즈 자리에선 후자가 디폴트로 깔릴 것 같은 결.

숫자가 무겁다. Harvey 자리가 dreaming 도입 후 작업 완료율이 약 6배 올라간 결을 풀었다. Cryptobriefing 라인이 짚은 한 줄도 같은 톤이다 — 법률 도메인 자리에서 반복적으로 같은 케이스 결을 푸는 자리에 dreaming이 들어가니, 매번 처음부터 다시 굴리던 결이 한 단계씩 누적되는 그림. 20개 서브에이전트가 같은 도메인 자리에서 굴러갈 때, dreaming이 그 자리에서 집단 학습 결을 추출해서 팀 단위 메모리 스토어에 풀어두는 결도 같이 풀렸다.

outcomes — 에이전트한테 잘 했다의 정의를 박아주는 결

둘째 결은 outcomes다. VentureBeat 라인이 풀어둔 톤대로 짚으면 — outcomes는 에이전트한테 "좋은 결과란 이런 자리다"를 구체적인 예시 자리로 보여주는 결이다. 별도 grader 에이전트가 매 실행 자리를 채점하고, 그 결을 메인 에이전트한테 피드백한다. 자체 테스트 자리에서 표준 프롬프트 루프 대비 작업 성공률이 최대 10p 상승했다는 결을 풀었다.

주목할 자리는 Wisedocs 케이스다. 의료 문서 리뷰 자리에서 outcomes 도입 후 문서 검토 시간이 50% 단축된 톤이 풀렸다. 결의 무게가 무거운 자리는 evaluation이 학습 루프 안으로 들어왔다는 점이다. 지금까지 LLM 자리에서 평가 결은 보통 밖에 따로 굴리는 라인이었다 — 별도 벤치, 별도 인간 리뷰어, 별도 grader. outcomes 자리는 그 결을 에이전트 워크플로우 자리에 빌트인으로 넣어버린 톤이다.

multi-agent orchestration — 리드 에이전트가 전문가 팀을 굴리는 결

셋째 결은 multi-agent orchestration이다. 9to5Mac 라인이 정리한 톤 — 리드 에이전트가 복잡한 작업을 나누고, 전문가 서브에이전트 자리에 분배한다. 각 서브에이전트는 자기 모델·자기 프롬프트·자기 도구 자리를 들고 있고, 공유 파일시스템 위에서 병렬로 굴러간다. 결을 끝낸 서브에이전트는 리드 에이전트 컨텍스트 자리에 결을 풀고, Claude Console 자리에서 모든 자리가 트레이스로 깔린다.

진짜 무게는 Netflix 케이스다. 수백 개 빌드 자리에서 동시에 로그를 처리하는 결이 풀렸다. CI/CD 자리에서 한 번에 수백 개 빌드를 굴리면, 깨진 자리·플레이키 자리·진짜 회귀 자리를 사람이 다 훑는 게 불가능한 그림이다. orchestration 자리가 그걸 전문가 서브에이전트 자리로 풀어내는 라인. 회사 자리에서 평일에 영상 처리 파이프라인을 한 줄 굴리는 입장에서 짚으면, 수십 개 웨이퍼 데이터 자리를 동시에 분석하는 그림이 그대로 떠오른다 — 현직 자리에선 못 굴리지만, 결의 모양은 또렷이 보이는 자리다.

셋이 한 루프로 묶인다 — 결의 진짜 무게

세 자리를 따로 보면 각각 흥미로운 결이지만, 같이 보면 한 루프다. Anthropic 공식 라인이 풀어둔 그림대로 짚으면 — orchestration이 작업을 전문가 서브에이전트 자리로 쪼개고, outcomes가 각 실행 자리를 채점하는 루브릭을 박아주고, dreaming이 실행들 사이에서 패턴을 추출해서 다음 실행 자리를 개선한다. 생성 → 평가 → 학습 자리가 한 시스템 안에 들어가 있는 결이다.

여기서 VentureBeat 라인이 깐 비판이 한 단 묵직하다 — Anthropic이 에이전트의 메모리·eval·orchestration 자리를 다 가져가려고 한다는 톤. LangChain·CrewAI·LlamaIndex 라인이 풀어두던 자리를 Anthropic 자체 스택이 통째로 잡아먹는 그림이다. 엔터프라이즈 자리 입장에선 vendor lock-in 자리의 결이 한 단 깊어지는 라인. 단, Claude 모델 자리에 락인되는 결이 아니라 Claude Managed Agents 플랫폼 자리에 묶이는 결이라 결의 모양이 다르다.

X 자리에서 도는 톤도 한 줄로 짚어두면 — @simonw 라인이 "dreaming은 메모리 자리에서 사람이 손대지 않아도 결이 누적되게 만드는 첫 시도"라는 결을 박았다. @swyx 자리는 "orchestration이 진짜 컴포저블해진 자리"라는 톤. @kaborge 라인이 풀어둔 한 줄이 가장 무겁다 — "이건 framework가 아니라 OS다." Claude Managed Agents 자리가 에이전트 OS로 자리를 잡으려는 결인지, 그냥 묶음 SDK 자리로 그치는 결인지는 1~2분기 자리가 풀어줄 것 같다.

개인 Claude Code MAX 자리에서 굴리는 입장에서 짚으면, dreaming은 당장 결이 와닿는 라인이다. 같은 사이드 프로젝트 자리를 며칠씩 굴리다 보면, 어제 자리의 결을 오늘 다시 짚게 만드는 자리가 항상 생긴다 — 프로젝트 컨벤션, 자주 깨지는 부분, 내가 좋아하는 패턴 같은 결. 지금까지는 CLAUDE.md 자리에 직접 박아뒀는데, dreaming 자리가 굴러가면 그 자리가 세션 사이에 자동으로 정돈되는 그림이 된다. 다음 주 자리에 한 번 굴려보고 결을 정리해야겠다.

밤 11시가 가까워진다. 주말이라 그런가, 결이 가벼워서 글이 한 번에 나갔다.
