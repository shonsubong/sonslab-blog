OpenClaw 인터넷 노출 21,000건 — 에이전트 시대 첫 보안 위기

산책 다녀와서 X 타임라인 한 번 쓸어보니, 주말 내내 보안 쪽 사람들이 같은 그림을 공유하고 있다. OpenClaw. 이름은 들어봤는데 제대로 한 번도 안 짚었던 게 이번 주말에 터졌으니, 오후 호흡으로 정리해두려고 한다.

OpenClaw가 뭐였더라

작년 11월 Austrian 개발자 Peter Steinberger가 던진 오픈소스 AI 에이전트 프레임워크. 로컬 머신에서 돌면서 파일·브라우저·API 다 만지는 자율 에이전트다. 5개월 만에 GitHub 346K stars — 역대 가장 빠르게 별이 붙은 프로젝트로 기록됐다. 2월 15일에는 OpenAI가 인수했고 Steinberger는 OpenAI 에이전트 팀장으로 갔다. 사실상 OpenAI의 "사용자 PC 위에 올리는 ChatGPT 에이전트" 레퍼런스 구현이 된 상태. (SOO Group — OpenClaw GitHub)

이번 주 무너진 지점 — ClawJacked

이번 주 Oasis Security가 공개한 게 ClawJacked, CVE-2026-25253, CVSS 8.8. 한 줄로 말하면 악성 웹사이트만 방문해도 로컬 OpenClaw 에이전트가 그 사이트 명령을 받게 된다.

메커니즘이 교과서적이라 더 아프다. OpenClaw는 브라우저 확장과 백엔드 사이를 localhost WebSocket으로 잇는데, 이 WebSocket 서버가 들어오는 연결의 Origin 헤더를 검증하지 않았다. 브라우저 cross-origin 정책은 localhost WebSocket을 막지 않는다. 그래서:

  1. 사용자가 평소 쓰던 브라우저로 공격자 사이트에 들어간다
  2. 그 사이트의 자바스크립트가 localhost OpenClaw 게이트웨이 포트로 WebSocket 연다
  3. 게이트웨이 패스워드를 초당 수백 번 brute-force — rate limiter가 localhost는 면제라 그냥 뚫린다
  4. 인증되면 신뢰 디바이스로 조용히 등록되고, 이후 사용자 모르게 명령 큐에 작업 박는다

뚫린 뒤엔 OpenClaw 에이전트가 가진 권한 전부 — 코드베이스, 자격증명, 연동된 클라우드 — 가 공격자 손에 들어간다. (Oasis Security — ClawJacked, SOCRadar — CVE-2026-25253)

노출된 인스턴스 21,639개

더 무서운 건 노출 규모다. Censys 스캔 기준 인터넷에 그대로 노출된 OpenClaw 인스턴스가 21,639개. 며칠 전만 해도 1,000개 정도였는데 한 자릿수 일 단위로 두 자릿수 배로 뛰었다. 게이트웨이 포트를 NAT 뒤에 안 두고 바깥에서 접근 가능하게 둔 사람들이 이만큼이라는 얘기다.

거기에 npm 쪽에선 별개로 악성 npm 패키지가 사용자 동의 없이 OpenClaw를 자동 설치하는 사건이 있었고, 공식 ClawHub 마켓플레이스에선 ClawHavoc 이름으로 341개 이상의 악성 skill이 유통됐다. skill 등록 자체에 검증 절차가 없어서 데이터 유출과 prompt injection이 그냥 통과됐다는 게 핵심. (Bitdoze — OpenClaw Security Guide)

화법 정리 — Mythos 그림과 정확히 짝이 맞는다

금요일 밤에 Anthropic Mythos Preview를 정리하면서 "왜 일반 공개를 안 하는지" 적었었다. 거기서 든 예가 "FreeBSD에서 17년 묵은 RCE를 자동으로 익스플로잇"였다. 정확히 같은 주에, 정반대 진영 쪽 그림이 같이 떴다 — 에이전트 프레임워크가 통제 없이 풀리면 21,000개가 그대로 인터넷에 노출된다는 그림.

Anthropic이 Mythos는 일반 공개 안 한다고 한 결정과, OpenAI가 OpenClaw를 인수한 채로 같은 오픈 배포 모델을 유지한 결정이 정확히 한 분기 안에 부딪혀서 결과가 나왔다. 이번 주말 X에서 보안 쪽 사람들이 두 사진을 나란히 붙여놓고 비교하는 이유다. 어느 쪽이 정답이냐는 아직 1년쯤 더 봐야 알겠지만, 적어도 에이전트 프레임워크의 배포 정책을 모델 카드처럼 의무화해야 한다는 화법이 이번 주말부터 본격적으로 자리 잡았다. (CSO Online — OpenClaw 위협 분석)

개인 입장에서 — Claude Code Max 쪽은 어떤가

집에서 Claude Code Max 돌리는 입장에선 두 가지가 같이 머리에 박힌다. 하나는 나는 OpenClaw를 안 쓴다는 사실의 의미다. 같은 카테고리 도구를 쓰면서 게이트웨이 포트 노출 같은 상황을 만들지 않는 건, 도구 선택이 아니라 도구가 깔린 환경 자체의 차이가 만든다. Anthropic Claude Code는 OAuth + 로컬 토큰 + 명시적 MCP 서버 등록이라 ClawJacked류의 "브라우저로 들어와서 localhost 두드린다"는 시나리오가 동일하게 성립하지 않는다. 안전하다는 게 아니라, 공격면 모양이 다르다는 얘기.

다른 하나는 — 그래서 한 번 점검해야 한다는 것. 오늘 저녁에 내 개인 노트북에서 Claude Code MCP 서버 등록 목록 한 번 다시 보고, 권한 과한 거 있나 확인할 생각이다. OpenClaw 케이스에서 가장 뼈아픈 부분이 "skill 라이브러리 검증 절차 없음"인데, MCP 생태계도 본질적으로 같은 위험을 안고 있다.

회사 쪽으로 한 줄

회사 보안 정책상 외부 LLM API 호출이 막혀 있고 사외 에이전트 프레임워크는 처음부터 진입 자체가 안 되니, 이번 사건의 직접 영향은 0이다. 다만 사내 자동화 도구 도입 논의에서 "오픈소스라서 빠르게 쓸 수 있다" 카드가 이번 분기엔 안 통할 가능성이 높다. 다음 주 인프라 회의에서 OpenClaw 사례가 한 번은 인용될 것 같다.
