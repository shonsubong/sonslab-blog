본문 구조 (1500~2500자)

각 글은 아래 6개 블록을 이 순서로 가진다. 헤딩 레벨은 H2부터.

  1. TL;DR — 3줄 bullet. "무엇 / 왜 중요 / 어떻게 쓰나"
  2. 배경 (Why now) — 이 주제가 지금 다뤄질 이유. 직전 1~2주 안의 트리거 사건 명시.
  3. 핵심 메커니즘 — 도식 또는 mermaid 다이어그램 1개. "어떻게 동작하는가"의 기술 본질.
  4. 코드 / 수식 예시 — 실제 돌려본 코드(또는 의사코드) 또는 핵심 수식. 5~30줄.
  5. 한계·반론 — 회의적 시각, 알려진 실패 케이스, 벤치마크 함정.
  6. 현직 엔지니어 관점 한 문단 — 반도체 수석 엔지니어로서 현장 적용 가능성·온디바이스 시사점.

부록(선택): 추가 읽을거리 3~5개 링크.

도식 / 코드 가이드

  • mermaid: GitHub Pages가 mermaid를 자동 렌더하지 않으므로 build.py에서 처리하거나, ASCII 도식을 우선 사용.
  • ASCII 도식 예: [입력] → [임베딩] → [Self-Attn ×N] → [출력]
  • 코드 블록: 언어 명시 (```python, ```bash). highlight.js가 codehilite로 처리.
  • 수식: 인라인은 $O(n^2)$, 블록은 별도 표기. MathJax는 미설치이므로 단순 표기 우선.

소스 인용 규칙

  1. 1차 출처 우선: arXiv 논문, 공식 블로그(Anthropic/OpenAI/DeepMind/Meta AI), GitHub README, 공식 docs
  2. 보조 출처: X 인플루언서(@karpathy, @ylecun, @DrJimFan, @swyx, @simonw, @dylan522p 등), 주요 테크 매체(Sequoia, Stratechery, SemiAnalysis)
  3. 인용 형식: ([저자/매체 — 제목](URL)) 한 줄 인용. 본문 끝이 아닌 해당 문장 직후.
  4. 금지: 트위터(Twitter) 표기 — 반드시 X. 출처 없는 추측을 단정형으로 쓰지 말 것.

톤 / 한국어 사용

  • 메모리 규칙: 영어 남용 금지. "임베딩"은 한국어, "Transformer"는 그대로 두는 식으로 자연스럽게.
  • 데일리보다 더 차분하고 길게. 데일리는 현장감, 딥다이브는 정리·해설.
  • "~합니다"체 금지. 데일리와 동일하게 "~한다"체.
  • 자기 자랑·과장 금지. 모르는 것은 "확인 필요"로 남긴다.
