DeepSeek V4-Flash가 13B 활성으로 같은 자리를 잡았다 — 백만 토큰 자리에 KV 캐시는 V3.2의 7%

토요일 오후. 점심 자리에 Kimi K2.6 INT4 빌드를 한 번 띄워보고, 바람도 한 번 쐬고 들어와서 다시 책상. 점심 글 끝줄에 짚어둔 DeepSeek V4-Flash를 진짜 한 번 굴려볼 자리다. K2.6이 오픈웨이트 코딩 자리의 윗줄을 잡은 결이라면, V4-Flash는 비용·컨텍스트·지연시간의 결을 한 단 더 깎은 자리다. 두 모델 모두 MIT 라이선스 자리에 풀려서, 같은 한 주에 오픈웨이트 라인의 결이 두 갈래로 가팔라진 톤이다.

284B MoE · 13B 활성 · 1M 컨텍스트 — 숫자부터 짚어두기

Hugging Face 자리에 풀린 결을 한 줄로 묶으면 — 총 284B 파라미터·활성 13B·컨텍스트 1M·MIT 라이선스. V4-Pro 자리가 671B 총 / 37B 활성이었으니, Flash 라인은 활성 자리만 보면 1/3 수준까지 깎인 그림이다. DeepSeek API 문서 라인이 풀어둔 가격 결도 또렷하다 — 입력 $0.14 / 출력 $0.28 (백만 토큰). 같은 자리의 Pro가 입력 $0.42 / 출력 $1.10이라, Flash는 Pro의 약 1/4 자리다.

핵심 결은 하이브리드 어텐션 라인이다. Simon Willison이 풀어둔 정리와 Codersera 라인을 같이 깔아두면 톤이 모인다 — Compressed Sparse Attention (CSA)과 Heavily Compressed Attention (HCA)을 같이 박은 결. 1M 토큰 자리에서 토큰당 FLOPs는 V3.2의 10%, KV 캐시는 7%까지 깎였다. 컨텍스트가 길어질수록 결의 무게가 더 가벼워지는 톤이다. long-horizon 자리에서 한 단 큰 결.

Artificial Analysis 라인이 풀어둔 벤치 결도 같이 짚어두면 — MMLU 86.4 · GPQA 71.2 · LiveCodeBench 64.8 · SWE-Bench Verified 67.3. 오픈웨이트 자리에서 13B 활성만 굴려서 잡은 결이 묵직하다. Verified 자리의 K2.6 80.2% 라인보단 한 단 헐겁지만, 활성 파라미터 자리당 효율로 보면 결이 다른 톤이다. 13B 활성이라 160GB 자리에 들어간다. 2x H100 FP8이나 1x H200 한 자리만으로 풀린다는 결.

얇은 활성 라인이 의미하는 것 — 추론 지연시간 자리

엔지니어 시각에서 한 단 더 짚어두면, 진짜 무게는 벤치 숫자가 아니라 지연시간 결에 박혀 있다. V4-Pro가 37B 활성이고 Flash가 13B 활성이니, 같은 H100 자리에서 토큰당 디코드 지연시간이 대략 3분의 1 수준까지 떨어진다. Runpod 라인이 풀어둔 벤치마크 결을 보면 — Flash가 H200 한 장 자리에서 80~90 t/s, Pro가 같은 자리에서 28~32 t/s 정도. 결이 정직하게 박힌다.

여기서 Cloudflare 1,100명 정리 라인과 결을 한 자리에 깔아두면 그림이 또렷해진다. 새벽 자리에 짚어둔 agentic AI-first의 결이 추론 비용·지연시간 자리에 의존한다면, V4-Flash 같은 얇은 활성 오픈웨이트 라인이야말로 대규모 에이전트 라인을 자체 인프라에 박는 결의 톤이다. 외부 API 자리에 묶이지 않고, 자체 H100·H200 자리에 풀린 결로 300개 sub-agent을 한 번에 굴리는 톤. K2.6은 코딩 자리의 윗줄을 잡았고, V4-Flash는 대량 에이전트 자리의 비용 라인을 깎은 결이다. 두 결이 같은 한 주에 같이 박혔다는 게 결의 무게다.

직접 굴려본 결 — 1M 컨텍스트가 진짜 풀리는지

집 PC 자리는 160GB 자리가 안 들어가서 Together.ai 자리의 V4-Flash 엔드포인트로 한 번 굴려봤다. 토큰 자리당 70 t/s 안팎. 정직하게 짚으면 Pro 자리보단 출력 결의 매끄러움이 한 단 헐겁다. 같은 코드 리팩토링 프롬프트 자리에 V4-Pro·V4-Flash·Kimi K2.6을 같이 넣어봤는데, Pro가 한 번에 잡는 자리를 Flash는 두 번에 잡는 결이 잡혔다. 다만 지연시간과 비용을 같이 묶으면, 대량으로 굴리는 자리에선 결의 무게추가 Flash 쪽으로 옮겨간다.

진짜 묵직한 결은 1M 토큰 컨텍스트 자리다. 평소 만지는 오픈소스 마크다운 뷰어의 전체 코드베이스(약 12만 토큰)와 최근 6개월 GitHub Issue 자리를 한 번에 같이 넣고 "이 라이브러리에서 가장 자주 깨지는 결을 추적해 패턴을 정리해라" 결로 던져봤다. 32K·128K 자리에선 결이 헐거웠는데, 800K 토큰 자리에 한 번에 넣어보니 세 가지 패턴을 묶어서 풀어주는 결이 또렷했다. long-horizon 코드 라인과 이슈 텍스트 라인을 같이 보고 추론하는 자리는, 짧은 컨텍스트 모델에선 잘 풀리지 않는 결이다. CSA·HCA가 박힌 자리의 진짜 효과는 여기서 잡힌다.

X 자리에서 도는 톤도 같이 깔아두면 — @simonw 라인이 "V4-Flash는 frontier 자리에 거의 닿은 결을, 가격의 한 자리수 아래로 깎아낸 톤"을 박았고, @kaborge 자리는 "K2.6이 코딩 자리의 윗줄을 잡았다면, V4-Flash는 자체 인프라 라인의 비용 결을 깎은 자리"라는 톤을 깔았다. @_philschmid 라인이 짚은 한 줄이 더 무겁다 — "1M 컨텍스트에서 KV 캐시 7% 자리는, frontier 모델 자리가 다 따라잡아야 하는 결". CSA·HCA 같은 어텐션 결의 톤이 오픈 라인 자리에서 먼저 깔린 그림이 또렷해진다.

결을 정직하게 — Flash는 frontier 자리의 대체가 아니다

같은 자리에서 한 단 정직하게 짚어두면, V4-Flash는 frontier 라인의 대체가 아니다. Opus 4.7·GPT-5.5·Gemini 3.1 Pro 자리의 복잡한 다단 도구 사용·long-horizon 디버깅·미묘한 추론 결은 한 단 위. Flash 라인은 "오픈웨이트 자리에서 비용·지연시간을 한 단 깎고 싶을 때"의 결이지, "frontier 자리를 대체할 라인"은 아닌 톤. 지금 자리에서 정직한 그림은 두 갈래다 — frontier 자리는 Opus·GPT·Gemini 라인에 맡기고, 대량 자리·민감한 자리·자체 인프라 라인은 V4-Flash·K2.6 자리로 푸는 결.

FSD V14.3.2 누적 결 — 한 줄만 짚어둔다

점심 글에 짚어둔 FSD V14.3.2도 한 단만 보고 가자. Tesla Oracle 라인이 정리한 자리에선 Smart Summon·FSD·Robotaxi 자리의 AI 모델이 한 라인으로 통합된 결이 큰 자리다. 다만 Tesla Hubs 라인이 풀어둔 톤대로 — 대규모 Robotaxi 확장 자리는 V15 라인까지 보류. 결을 정직하게 잡으면 2026년 말~2027년 초 자리까지의 그림이다. V14 라인은 통합 자리가 결의 무게고, 상업 확장 라인은 V15 자리에 묶여 있다는 톤. 어제 아침 자리에 짚어둔 FSD V14.3.2 누적 마일 라인은 다음 자리에 다시 한 번 묶어볼 결.

한 줄로 묶으면

같은 한 주 자리에 Kimi K2.6이 코딩 윗줄을 잡고, DeepSeek V4-Flash가 비용·지연시간·컨텍스트 자리를 깎은 결이 또렷하다. 새벽에 짚어둔 백악관 EO가 frontier 라인에 묶일 가능성이 도는 자리에서, 오픈웨이트 라인은 정반대로 결을 가파르게 푸는 톤. 다음 자리는 Google I/O 키노트(5월 19일) — Gemini 3.x 자리가 오픈웨이트 라인의 결을 어떻게 받아치는지가 큰 분기점이다. 밤 자리에 Anthropic Claude Code 자리나 X 인플루언서 결이 풀리는 톤이 잡히면 한 번 더 정리한다.
