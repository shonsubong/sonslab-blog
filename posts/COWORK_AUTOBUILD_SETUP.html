Cowork 스케줄 작업 후 자동 빌드 셋업 가이드

배경

Cowork의 scheduled task 샌드박스는 보안상 .py / .bat / .exe / .jpg 같은 파일 타입을 읽거나 실행할 수 없다. 따라서 build.py나 auto-deploy.bat를 샌드박스 안에서 호출하는 건 구조적으로 불가능하다.

해결책: Windows 측에 FileSystemWatcher를 띄워서 posts/**/*.md 파일이 새로 생성되는 순간을 감지하고 자동으로 auto-deploy.bat를 실행시키는 것. Cowork 스케줄이 새 .md 파일을 Drop하자마자 Windows가 빌드를 넘겨받는 구조.

이 가이드대로 한 번만 설치하면 이후 모든 스케줄 실행에서 자동 빌드가 보장된다.

1단계 — PowerShell 워처 스크립트 저장

아래 내용을 X:\Work_Agent\sonslab-blog\watch_and_build.ps1 파일로 저장:

# watch_and_build.ps1
# posts/ 폴더의 새 .md 파일 생성을 감지해서 auto-deploy.bat를 실행

$BlogRoot   = "X:\Work_Agent\sonslab-blog"
$WatchPath  = Join-Path $BlogRoot "posts"
$DeployBat  = Join-Path $BlogRoot "auto-deploy.bat"
$LogFile    = Join-Path $BlogRoot "watcher.log"
$DebounceMs = 5000   # 5초 내 여러 파일이 들어오면 한 번만 빌드

# 로그 함수
function Write-Log($msg) {
    $stamp = Get-Date -Format "yyyy-MM-dd HH:mm:ss"
    Add-Content -Path $LogFile -Value "[$stamp] $msg"
}

Write-Log "Watcher started. Monitoring $WatchPath"

# FileSystemWatcher 구성
$watcher = New-Object System.IO.FileSystemWatcher
$watcher.Path = $WatchPath
$watcher.Filter = "*.md"
$watcher.IncludeSubdirectories = $true
$watcher.EnableRaisingEvents = $true

# 디바운스용 타이머
$script:pending = $false
$script:lastEvent = Get-Date

$action = {
    $script:pending = $true
    $script:lastEvent = Get-Date
    $path = $Event.SourceEventArgs.FullPath
    Write-Log "Detected change: $path"
}

Register-ObjectEvent $watcher Created -Action $action | Out-Null
Register-ObjectEvent $watcher Changed -Action $action | Out-Null

# 디바운스 루프
while ($true) {
    Start-Sleep -Milliseconds 1000
    if ($script:pending) {
        $elapsed = (New-TimeSpan -Start $script:lastEvent -End (Get-Date)).TotalMilliseconds
        if ($elapsed -ge $DebounceMs) {
            $script:pending = $false
            Write-Log "Debounce elapsed. Running auto-deploy.bat..."
            try {
                Push-Location $BlogRoot
                $output = cmd /c $DeployBat 2>&1
                $output | ForEach-Object { Write-Log "OUT: $_" }
                Write-Log "auto-deploy.bat finished (exit=$LASTEXITCODE)"
            } catch {
                Write-Log "ERROR: $_"
            } finally {
                Pop-Location
            }
        }
    }
}

핵심 동작: - posts/ 하위 어디든 .md 파일이 생기면 감지 - 5초 디바운스(여러 파일 동시 생성 대비) - auto-deploy.bat 실행 - 모든 실행 로그를 watcher.log에 남김

2단계 — Task Scheduler에 등록 (Windows 부팅 시 자동 시작)

관리자 권한 PowerShell에서 한 번만 실행:

$Action = New-ScheduledTaskAction `
    -Execute "powershell.exe" `
    -Argument "-NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File `"X:\Work_Agent\sonslab-blog\watch_and_build.ps1`""

$Trigger = New-ScheduledTaskTrigger -AtStartup

$Principal = New-ScheduledTaskPrincipal `
    -UserId "$env:USERDOMAIN\$env:USERNAME" `
    -LogonType Interactive `
    -RunLevel Highest

$Settings = New-ScheduledTaskSettingsSet `
    -AllowStartIfOnBatteries `
    -DontStopIfGoingOnBatteries `
    -RestartCount 3 `
    -RestartInterval (New-TimeSpan -Minutes 1)

Register-ScheduledTask `
    -TaskName "SONSLAB_Blog_AutoBuild_Watcher" `
    -Action $Action `
    -Trigger $Trigger `
    -Principal $Principal `
    -Settings $Settings `
    -Description "Cowork가 새 .md를 저장하면 auto-deploy.bat 자동 실행"

등록 확인:

Get-ScheduledTask -TaskName "SONSLAB_Blog_AutoBuild_Watcher"

3단계 — 즉시 시작 (재부팅 안 하고)

Start-ScheduledTask -TaskName "SONSLAB_Blog_AutoBuild_Watcher"

몇 초 뒤 watcher.log에 "Watcher started." 라인이 찍히면 정상 동작.

4단계 — 테스트

샌드박스에서 새 .md가 posts/에 저장되는 것을 시뮬레이션하려면:

"test" | Out-File "X:\Work_Agent\sonslab-blog\posts\2026-04\_test.md"
Remove-Item "X:\Work_Agent\sonslab-blog\posts\2026-04\_test.md"

5초 뒤 watcher.log에서 auto-deploy.bat finished (exit=0) 확인.

디버깅 팁

watcher.log를 실시간으로 모니터링:

Get-Content X:\Work_Agent\sonslab-blog\watcher.log -Tail 20 -Wait

워처 수동 중단:

Stop-ScheduledTask -TaskName "SONSLAB_Blog_AutoBuild_Watcher"

auto-deploy.bat 자체가 실패하면 먼저 워처 없이 수동 실행으로 원인을 잡아야 한다. watcher.log의 OUT: 라인에 bat 출력이 그대로 찍히니 거기서 에러 확인 가능.

주의 사항

  1. X:\ 드라이브 경로가 맞는지 확인. 다르면 스크립트 상단 $BlogRoot 수정.
  2. PowerShell 실행 정책: 회사 PC에서 RemoteSigned 이상이면 위 설정(ExecutionPolicy Bypass)으로 통과. 그래도 막히면 IT 팀 문의.
  3. Git push가 auto-deploy.bat에 포함된다면: watcher는 interactive 세션에서 돌기 때문에 credential manager에 이미 저장된 자격증명을 그대로 쓴다. 별도 설정 불필요.
  4. 워처 프로세스 확인: powershell Get-Process powershell | Where-Object { $_.MainWindowTitle -eq "" -and $_.StartTime -gt (Get-Date).AddHours(-24) }

요약

셋업 완료 후 흐름:

Cowork 스케줄 (06/12/17/22시)
  └─ 내가 .md 파일 작성 → posts/2026-04/ 에 저장
       │
       └─ Windows FileSystemWatcher 감지 (5초 후)
            └─ auto-deploy.bat 실행
                 └─ build.py 호출 → site/ 갱신
                      └─ (auto-deploy.bat에 git push 있다면) 배포까지 자동

한 번 셋업하면 Cowork 쪽에서는 아무것도 안 고쳐도 되고, build.py나 auto-deploy.bat 내용도 그대로 써도 된다.
