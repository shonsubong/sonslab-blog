Cowork 스케줄 작업 후 자동 빌드 셋업 가이드

배경

Cowork의 scheduled task 샌드박스는 보안상 .py / .bat / .exe / .jpg 같은 파일 타입을 읽거나 실행할 수 없다. 따라서 build.py나 auto-deploy.bat를 샌드박스 안에서 호출하는 건 구조적으로 불가능하다.

해결책: Windows 측에 FileSystemWatcher를 띄워서 posts/**/*.md 파일이 새로 생성되는 순간을 감지하고 자동으로 auto-deploy.bat를 실행시키는 것. Cowork 스케줄이 새 .md 파일을 Drop하자마자 Windows가 빌드를 넘겨받는 구조.

이 가이드대로 한 번만 설치하면 이후 모든 스케줄 실행에서 자동 빌드가 보장된다.

1단계 — PowerShell 워처 스크립트 저장

아래 내용을 X:\Work_Agent\sonslab-blog\watch_and_build.ps1 파일로 저장 (v3.1, 2026-04-19 최종, ASCII-only).

주의 — 이 스크립트는 반드시 ASCII 문자만 써야 합니다. 한글 주석이나 em-dash(—) 같은 멀티바이트 문자를 넣으면 한글 Windows의 PowerShell 5.1이 BOM 없는 UTF-8을 CP949로 오인해 파싱 에러를 냅니다 (v3에서 실제로 겪은 문제). 한글 설명은 이 문서에만 두고 스크립트 본문은 건드리지 말 것.

# watch_and_build.ps1 (v3.1 - ASCII-only, inline action, file-based cooldown)
#
# History:
#   v1 : -Action block used $script: flag -> main loop never saw it (scope bug).
#   v2 : -Action removed + Wait-Event polling -> events never queued (no -Action).
#   v3 : inline -Action + file-based cooldown; had Korean comments that broke
#        PowerShell 5.1 parsing on non-BOM UTF-8 / CP949 Korean Windows.
#   v3.1: same logic as v3, but pure ASCII script so encoding cannot break it.
#         (Korean explanation lives in COWORK_AUTOBUILD_SETUP.md, not here.)

$BlogRoot      = "X:\Work_Agent\sonslab-blog"
$WatchPath     = Join-Path $BlogRoot "posts"
$DeployBat     = Join-Path $BlogRoot "auto-deploy.bat"
$LogFile       = Join-Path $BlogRoot "watcher.log"
$CooldownFlag  = Join-Path $BlogRoot ".watcher_cooldown"
$CooldownSec   = 5

function Write-Log($msg) {
    $stamp = Get-Date -Format "yyyy-MM-dd HH:mm:ss"
    Add-Content -Path $LogFile -Value "[$stamp] $msg"
}

Write-Log "Watcher started (v3.1 inline mode). Monitoring $WatchPath"

$watcher = New-Object System.IO.FileSystemWatcher
$watcher.Path = $WatchPath
$watcher.Filter = "*.md"
$watcher.IncludeSubdirectories = $true
$watcher.EnableRaisingEvents = $true

# Action block: all work happens here. Outer variables are read via closure;
# mutable state is stored only in the $CooldownFlag file.
$action = {
    $now   = Get-Date
    $stamp = $now.ToString("yyyy-MM-dd HH:mm:ss")
    $path  = $Event.SourceEventArgs.FullPath
    Add-Content -Path $LogFile -Value "[$stamp] Detected change: $path"

    # Cooldown: if the flag file was touched within CooldownSec, skip this event.
    if (Test-Path $CooldownFlag) {
        $last  = (Get-Item $CooldownFlag).LastWriteTime
        $since = [math]::Round(($now - $last).TotalSeconds, 1)
        if ($since -lt $CooldownSec) {
            Add-Content -Path $LogFile -Value "[$stamp] (skipped, $since s since last build)"
            return
        }
    }

    # Touch flag with current time to block concurrent events during the build.
    Set-Content -Path $CooldownFlag -Value $now.ToString("o") -Force
    Add-Content -Path $LogFile -Value "[$stamp] Running auto-deploy.bat..."

    Push-Location $BlogRoot
    try {
        $output = & cmd.exe /c $DeployBat 2>&1
        foreach ($line in $output) {
            $s = Get-Date -Format "yyyy-MM-dd HH:mm:ss"
            Add-Content -Path $LogFile -Value "[$s] OUT: $line"
        }
        $done = Get-Date -Format "yyyy-MM-dd HH:mm:ss"
        Add-Content -Path $LogFile -Value "[$done] auto-deploy.bat finished (exit=$LASTEXITCODE)"
    }
    catch {
        $e = Get-Date -Format "yyyy-MM-dd HH:mm:ss"
        Add-Content -Path $LogFile -Value "[$e] ERROR: $_"
    }
    finally {
        Pop-Location
        # Refresh flag at build end so the next CooldownSec also block re-entry.
        Set-Content -Path $CooldownFlag -Value (Get-Date).ToString("o") -Force
    }
}

Register-ObjectEvent -InputObject $watcher -EventName Created -Action $action -SourceIdentifier "MdCreated" | Out-Null
Register-ObjectEvent -InputObject $watcher -EventName Changed -Action $action -SourceIdentifier "MdChanged" | Out-Null

# Keep the host process alive. Real work runs inside $action.
try {
    while ($true) { Start-Sleep -Seconds 60 }
}
finally {
    Unregister-Event -SourceIdentifier "MdCreated" -ErrorAction SilentlyContinue
    Unregister-Event -SourceIdentifier "MdChanged" -ErrorAction SilentlyContinue
    $watcher.EnableRaisingEvents = $false
    $watcher.Dispose()
}

핵심 동작: - posts/ 하위 어디든 .md 파일이 생기면 감지 - 첫 이벤트에서 즉시 auto-deploy.bat 실행 - 파일 기반 쿨다운(.watcher_cooldown) — 빌드 시작/종료 시점을 touch해서 N초 내 재진입 차단 - 모든 실행 로그를 watcher.log에 남김 - 크로스-스코프 변수 공유가 없어 PowerShell 이벤트 스코프 이슈 원천 차단 - 스크립트 본문이 ASCII-only라 PowerShell 5.1 인코딩 함정도 차단

2단계 — Task Scheduler에 등록 (Windows 부팅 시 자동 시작)

관리자 권한 PowerShell에서 한 번만 실행:

$Action = New-ScheduledTaskAction `
    -Execute "powershell.exe" `
    -Argument "-NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File `"X:\Work_Agent\sonslab-blog\watch_and_build.ps1`""

$Trigger = New-ScheduledTaskTrigger -AtStartup

$Principal = New-ScheduledTaskPrincipal `
    -UserId "$env:USERDOMAIN\$env:USERNAME" `
    -LogonType Interactive `
    -RunLevel Highest

$Settings = New-ScheduledTaskSettingsSet `
    -AllowStartIfOnBatteries `
    -DontStopIfGoingOnBatteries `
    -RestartCount 3 `
    -RestartInterval (New-TimeSpan -Minutes 1)

Register-ScheduledTask `
    -TaskName "SONSLAB_Blog_AutoBuild_Watcher" `
    -Action $Action `
    -Trigger $Trigger `
    -Principal $Principal `
    -Settings $Settings `
    -Description "Cowork가 새 .md를 저장하면 auto-deploy.bat 자동 실행"

등록 확인:

Get-ScheduledTask -TaskName "SONSLAB_Blog_AutoBuild_Watcher"

3단계 — 즉시 시작 (재부팅 안 하고)

Start-ScheduledTask -TaskName "SONSLAB_Blog_AutoBuild_Watcher"

몇 초 뒤 watcher.log에 "Watcher started." 라인이 찍히면 정상 동작.

4단계 — 테스트

샌드박스에서 새 .md가 posts/에 저장되는 것을 시뮬레이션하려면:

"test" | Out-File "X:\Work_Agent\sonslab-blog\posts\2026-04\_test.md"
Remove-Item "X:\Work_Agent\sonslab-blog\posts\2026-04\_test.md"

5초 뒤 watcher.log에서 auto-deploy.bat finished (exit=0) 확인.

디버깅 팁

watcher.log를 실시간으로 모니터링:

Get-Content X:\Work_Agent\sonslab-blog\watcher.log -Tail 20 -Wait

워처 수동 중단:

Stop-ScheduledTask -TaskName "SONSLAB_Blog_AutoBuild_Watcher"

auto-deploy.bat 자체가 실패하면 먼저 워처 없이 수동 실행으로 원인을 잡아야 한다. watcher.log의 OUT: 라인에 bat 출력이 그대로 찍히니 거기서 에러 확인 가능.

v3 검증 포인트 — 증상별로 원인 구분이 가능하다:

watcher.log 에 찍히는 것 판정
"Watcher started"만 찍히고 아무 것도 없음 이벤트가 감지되지 않음. EnableRaisingEvents / IncludeSubdirectories 또는 워처 프로세스 종료 의심. Get-ScheduledTask -TaskName "SONSLAB_Blog_AutoBuild_Watcher" \| Select-Object State 로 Running인지 확인.
"Detected change"까지만 찍히고 "Running auto-deploy.bat..."이 안 찍힘 액션 블록이 쿨다운에서 걸렸거나 예외로 죽음. .watcher_cooldown 파일 mtime 확인 후 삭제하고 재시도.
"Running auto-deploy.bat..."은 있는데 "finished"가 없음 auto-deploy.bat 자체가 멈춰있거나 무한 루프. cmd 창에서 직접 실행해 원인 확인.
"finished (exit=0)" 정상인데 사이트가 갱신 안 됨 auto-deploy.bat 내부의 git push 단계가 실패했을 가능성. OUT: 라인 쪽을 위로 스크롤해서 확인.

과거 버전 회귀 증상 (참고): - v1 회귀: "Detected change"만 반복되고 "Debounce elapsed"가 안 찍힘. $script: 스코프 버그. - v2 회귀: "Watcher started"만 찍히고 "Detected change"조차 없음. -Action 없는 ObjectEvent는 기본 이벤트 큐로 안 올라옴. - v3 회귀: Task 상태가 Ready로 빠지고 로그에 startup 라인조차 안 찍힘. 수동 실행 시 ParserError: UnexpectedToken → 스크립트 본문에 한글/em-dash 포함. PowerShell 5.1이 BOM 없는 UTF-8을 CP949로 읽어 바이트 시퀀스가 파싱 기호로 오인됨. 스크립트는 반드시 ASCII-only(v3.1) 유지.

배포 경로 이중화 유의 — scripts/cowork_deploy.py는 샌드박스에서 직접 gh-pages로 푸시를 시도하지만, 샌드박스에 GitHub 자격증명이 없으면 push 단계에서 실패한다. 현재 신뢰 가능한 배포 경로는 이 Windows 워처 → auto-deploy.bat 체인이다. 워처가 멎으면 gh-pages가 갱신되지 않으므로, 새 포스트가 올라왔는데 사이트가 그대로면 가장 먼저 이 워처의 watcher.log부터 확인한다.

주의 사항

  1. X:\ 드라이브 경로가 맞는지 확인. 다르면 스크립트 상단 $BlogRoot 수정.
  2. PowerShell 실행 정책: 회사 PC에서 RemoteSigned 이상이면 위 설정(ExecutionPolicy Bypass)으로 통과. 그래도 막히면 IT 팀 문의.
  3. Git push가 auto-deploy.bat에 포함된다면: watcher는 interactive 세션에서 돌기 때문에 credential manager에 이미 저장된 자격증명을 그대로 쓴다. 별도 설정 불필요.
  4. 워처 프로세스 확인: powershell Get-Process powershell | Where-Object { $_.MainWindowTitle -eq "" -and $_.StartTime -gt (Get-Date).AddHours(-24) }

요약

셋업 완료 후 흐름:

Cowork 스케줄 (06/12/17/22시)
  └─ 내가 .md 파일 작성 → posts/2026-04/ 에 저장
       │
       └─ Windows FileSystemWatcher 감지 (5초 후)
            └─ auto-deploy.bat 실행
                 └─ build.py 호출 → site/ 갱신
                      └─ (auto-deploy.bat에 git push 있다면) 배포까지 자동

한 번 셋업하면 Cowork 쪽에서는 아무것도 안 고쳐도 되고, build.py나 auto-deploy.bat 내용도 그대로 써도 된다.
