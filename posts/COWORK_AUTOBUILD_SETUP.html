Cowork 스케줄 작업 후 자동 빌드 셋업 가이드

배경

Cowork의 scheduled task 샌드박스는 보안상 .py / .bat / .exe / .jpg 같은 파일 타입을 읽거나 실행할 수 없다. 따라서 build.py나 auto-deploy.bat를 샌드박스 안에서 호출하는 건 구조적으로 불가능하다.

해결책: Windows 측에 FileSystemWatcher를 띄워서 posts/**/*.md 파일이 새로 생성되는 순간을 감지하고 자동으로 auto-deploy.bat를 실행시키는 것. Cowork 스케줄이 새 .md 파일을 Drop하자마자 Windows가 빌드를 넘겨받는 구조.

이 가이드대로 한 번만 설치하면 이후 모든 스케줄 실행에서 자동 빌드가 보장된다.

1단계 — PowerShell 워처 스크립트 저장

아래 내용을 X:\Work_Agent\sonslab-blog\watch_and_build.ps1 파일로 저장 (v3.3, 2026-04-19 최종, ASCII-only).

v3.3부터는 auto-deploy.bat로 gh-pages를 배포한 뒤, 같은 워처에서 X:\Work_Agent 상위 레포의 main 브랜치에도 sonslab-blog/posts/ 범위로 소스 커밋+푸시를 수행한다 (옵션 C — front-matter title:로 한글 커밋 메시지, git commit -F로 CP949 변조 회피).

주의 — 이 스크립트는 반드시 ASCII 문자만 써야 합니다. 한글 주석이나 em-dash(—) 같은 멀티바이트 문자를 넣으면 한글 Windows의 PowerShell 5.1이 BOM 없는 UTF-8을 CP949로 오인해 파싱 에러를 냅니다 (v3에서 실제로 겪은 문제). 한글 설명은 이 문서에만 두고 스크립트 본문은 건드리지 말 것.

# watch_and_build.ps1 (v3.3 - adds Work_Agent/main source commit + push)
#
# History:
#   v1 : -Action used $script: flag -> main loop never saw it (scope bug).
#   v2 : -Action removed + Wait-Event polling -> events never queued.
#   v3 : inline -Action + file cooldown; Korean comments broke PS 5.1 parsing
#        on non-BOM UTF-8 / CP949 Korean Windows.
#   v3.1: same logic, pure ASCII script body.
#   v3.2: force UTF-8 console + Add-Content encoding so Korean output of
#         auto-deploy.bat (chcp 65001) is not mojibaked in watcher.log.
#   v3.3: after auto-deploy.bat succeeds, commit & push the triggering .md
#         (and any sonslab-blog/posts/ changes) to X:\Work_Agent on main.
#         Commit message follows Option C:
#             blog: YYYY-MM-DD <slot> - <title from front-matter>
#         Korean titles are safe: message is written to a UTF-8 (no BOM) temp
#         file and applied via `git commit -F <file>` so PS 5.1 + CP949 cannot
#         corrupt the bytes. The Work_Agent git push reuses the user's
#         already-configured Windows credentials (credential helper / HTTPS).

# --- UTF-8 for console I/O and file writes from the main script scope ---
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
[Console]::InputEncoding  = [System.Text.Encoding]::UTF8
$OutputEncoding           = [System.Text.Encoding]::UTF8
$PSDefaultParameterValues['Add-Content:Encoding'] = 'utf8'
$PSDefaultParameterValues['Set-Content:Encoding'] = 'utf8'
$PSDefaultParameterValues['Out-File:Encoding']    = 'utf8'

# --- Paths and config ---
$BlogRoot        = "X:\Work_Agent\sonslab-blog"
$WorkAgentRoot   = "X:\Work_Agent"
$WorkAgentBranch = "main"
$PostsRelPath    = "sonslab-blog/posts"
$WatchPath       = Join-Path $BlogRoot "posts"
$DeployBat       = Join-Path $BlogRoot "auto-deploy.bat"
$LogFile         = Join-Path $BlogRoot "watcher.log"
$CooldownFlag    = Join-Path $BlogRoot ".watcher_cooldown"
$TmpDir          = Join-Path $BlogRoot "tmp"
$CooldownSec     = 5

function Write-Log($msg) {
    # Seed log with UTF-8 BOM on first write so PS 5.1 Get-Content decodes
    # Korean output correctly.
    if (-not (Test-Path $LogFile)) {
        [System.IO.File]::WriteAllBytes($LogFile, [byte[]](0xEF, 0xBB, 0xBF))
    }
    $stamp = Get-Date -Format "yyyy-MM-dd HH:mm:ss"
    Add-Content -Path $LogFile -Value "[$stamp] $msg"
}

Write-Log "Watcher started (v3.3 inline mode, Work_Agent commit+push). Monitoring $WatchPath"

# --- FileSystemWatcher ---
$watcher = New-Object System.IO.FileSystemWatcher
$watcher.Path = $WatchPath
$watcher.Filter = "*.md"
$watcher.IncludeSubdirectories = $true
$watcher.EnableRaisingEvents = $true

# Action runs in a separate runspace. Outer variables work via closure. All
# mutable state must live in files (the $CooldownFlag).
$action = {
    # Re-apply UTF-8 inside the event runspace (it does not inherit console
    # encoding from the main script scope).
    [Console]::OutputEncoding = [System.Text.Encoding]::UTF8
    [Console]::InputEncoding  = [System.Text.Encoding]::UTF8
    $OutputEncoding           = [System.Text.Encoding]::UTF8
    $PSDefaultParameterValues = @{
        'Add-Content:Encoding' = 'utf8'
        'Set-Content:Encoding' = 'utf8'
    }

    $now   = Get-Date
    $stamp = $now.ToString("yyyy-MM-dd HH:mm:ss")
    $path  = $Event.SourceEventArgs.FullPath
    Add-Content -Path $LogFile -Value "[$stamp] Detected change: $path"

    # --- Cooldown guard ---
    if (Test-Path $CooldownFlag) {
        $last  = (Get-Item $CooldownFlag).LastWriteTime
        $since = [math]::Round(($now - $last).TotalSeconds, 1)
        if ($since -lt $CooldownSec) {
            Add-Content -Path $LogFile -Value "[$stamp] (skipped, $since s since last build)"
            return
        }
    }
    Set-Content -Path $CooldownFlag -Value $now.ToString("o") -Force

    $leafName = Split-Path -Leaf $path

    # --- Run auto-deploy.bat (builds site/ and pushes gh-pages) ---
    Add-Content -Path $LogFile -Value "[$stamp] Running auto-deploy.bat..."
    $batOutput = & cmd.exe /c "chcp 65001 >NUL && `"$DeployBat`"" 2>&1
    foreach ($line in $batOutput) {
        Add-Content -Path $LogFile -Value "[$stamp] OUT: $line"
    }
    $batExit = $LASTEXITCODE
    Add-Content -Path $LogFile -Value "[$stamp] auto-deploy.bat finished (exit=$batExit)"

    if ($batExit -ne 0) {
        Add-Content -Path $LogFile -Value "[$stamp] Skipping Work_Agent commit: build failed."
        return
    }

    # --- Work_Agent/main source commit+push (Option C) ---
    # Skip test files (underscore-prefixed) so they do not pollute main history.
    if ($leafName.StartsWith("_")) {
        Add-Content -Path $LogFile -Value "[$stamp] Skipping Work_Agent commit: test file ($leafName)"
        return
    }

    try {
        $stamp2 = (Get-Date).ToString("yyyy-MM-dd HH:mm:ss")
        Add-Content -Path $LogFile -Value "[$stamp2] Starting Work_Agent source commit..."

        # Parse date + slot from filename:
        #   YYYY-MM-DD-<slot>-ai-tech-news.md   ->  date=YYYY-MM-DD, slot=<slot>
        #   YYYY-MM-DD-ai-tech-news.md          ->  slot=post
        $nameNoExt = [System.IO.Path]::GetFileNameWithoutExtension($leafName)
        $dateStr = ""
        $slotStr = "post"
        if ($nameNoExt -match '^(\d{4}-\d{2}-\d{2})-([a-zA-Z0-9]+)-') {
            $dateStr = $Matches[1]
            $slotStr = $Matches[2]
        } elseif ($nameNoExt -match '^(\d{4}-\d{2}-\d{2})') {
            $dateStr = $Matches[1]
        } else {
            $dateStr = (Get-Date).ToString("yyyy-MM-dd")
        }

        # Extract title from YAML front-matter (first ~20 lines).
        $title = ""
        try {
            $head = Get-Content -Path $path -TotalCount 20 -Encoding UTF8 -ErrorAction Stop
            foreach ($ln in $head) {
                if ($ln -match '^\s*title\s*:\s*(.+?)\s*$') {
                    $raw = $Matches[1].Trim()
                    if ($raw.Length -ge 2 -and $raw.StartsWith('"') -and $raw.EndsWith('"')) {
                        $raw = $raw.Substring(1, $raw.Length - 2)
                    } elseif ($raw.Length -ge 2 -and $raw.StartsWith("'") -and $raw.EndsWith("'")) {
                        $raw = $raw.Substring(1, $raw.Length - 2)
                    }
                    $title = $raw
                    break
                }
            }
        } catch {
            Add-Content -Path $LogFile -Value "[$stamp2] Front-matter read failed: $($_.Exception.Message)"
        }
        if ([string]::IsNullOrWhiteSpace($title)) { $title = $leafName }

        $commitMsg = "blog: $dateStr $slotStr - $title"
        Add-Content -Path $LogFile -Value "[$stamp2] Commit message: $commitMsg"

        # Write commit message to UTF-8 (no BOM) temp file. Korean-safe path:
        # `git commit -F <file>` reads the file bytes directly, bypassing
        # PowerShell 5.1's CP949 string-to-process encoding that -m would hit.
        if (-not (Test-Path $TmpDir)) {
            New-Item -ItemType Directory -Path $TmpDir -Force | Out-Null
        }
        $msgFile = Join-Path $TmpDir ".commit_msg.tmp"
        $utf8NoBom = New-Object System.Text.UTF8Encoding($false)
        [System.IO.File]::WriteAllText($msgFile, $commitMsg, $utf8NoBom)

        # Run git from Work_Agent root.
        Push-Location $WorkAgentRoot
        try {
            # Stage only sonslab-blog/posts/.
            $addOut = & git add -- "$PostsRelPath" 2>&1
            foreach ($l in $addOut) { Add-Content -Path $LogFile -Value "[$stamp2] GIT: $l" }

            # Any staged changes in that scope?
            & git diff --cached --quiet -- "$PostsRelPath"
            $stagedCode = $LASTEXITCODE
            if ($stagedCode -eq 0) {
                Add-Content -Path $LogFile -Value "[$stamp2] No source changes in $PostsRelPath to commit. Skipping."
                return
            }

            # Confirm current branch (log-only; we push using explicit ref below).
            $branchRaw = (& git rev-parse --abbrev-ref HEAD 2>&1) | Out-String
            $branch = $branchRaw.Trim()
            Add-Content -Path $LogFile -Value "[$stamp2] Current branch: $branch (target: $WorkAgentBranch)"

            # Commit.
            $commitOut = & git commit -F "$msgFile" 2>&1
            foreach ($l in $commitOut) { Add-Content -Path $LogFile -Value "[$stamp2] GIT: $l" }
            if ($LASTEXITCODE -ne 0) {
                Add-Content -Path $LogFile -Value "[$stamp2] git commit failed (exit=$LASTEXITCODE)."
                return
            }

            # Push. HEAD:main pushes the current branch tip to origin/main, which
            # is what the user wants even if their local branch is not literally
            # named 'main'. If local is already main, this is a plain push.
            $pushOut = & git push origin ("HEAD:" + $WorkAgentBranch) 2>&1
            foreach ($l in $pushOut) { Add-Content -Path $LogFile -Value "[$stamp2] GIT: $l" }
            if ($LASTEXITCODE -eq 0) {
                Add-Content -Path $LogFile -Value "[$stamp2] Work_Agent push to origin/$WorkAgentBranch complete."
            } else {
                Add-Content -Path $LogFile -Value "[$stamp2] git push failed (exit=$LASTEXITCODE)."
            }
        } finally {
            Pop-Location
            if (Test-Path $msgFile) {
                Remove-Item -Path $msgFile -Force -ErrorAction SilentlyContinue
            }
        }
    } catch {
        $stampE = (Get-Date).ToString("yyyy-MM-dd HH:mm:ss")
        Add-Content -Path $LogFile -Value "[$stampE] Work_Agent commit error: $($_.Exception.Message)"
    }
}

# Register both Created and Changed so file drops are caught regardless of
# how the generator writes (new file vs. rewrite).
$regCreated = Register-ObjectEvent -InputObject $watcher -EventName "Created" -Action $action
$regChanged = Register-ObjectEvent -InputObject $watcher -EventName "Changed" -Action $action

# Keep host alive. Task Scheduler runs this script under -WindowStyle Hidden;
# exiting would tear down $watcher and the event subscribers.
try {
    while ($true) {
        Start-Sleep -Seconds 60
    }
} finally {
    Unregister-Event -SourceIdentifier $regCreated.Name -ErrorAction SilentlyContinue
    Unregister-Event -SourceIdentifier $regChanged.Name -ErrorAction SilentlyContinue
    $watcher.Dispose()
}

핵심 동작: - posts/ 하위 어디든 .md 파일이 생기면 감지 - 첫 이벤트에서 즉시 auto-deploy.bat 실행 (빌드 → gh-pages 푸시) - v3.3 추가: auto-deploy.bat가 exit 0으로 성공하면 이어서 X:\Work_Agent 상위 레포에서 sonslab-blog/posts/ 범위로 git add / commit / push origin HEAD:main 수행 (소스 원본도 main에 기록) - 파일 기반 쿨다운(.watcher_cooldown) — 빌드 시작 시점을 touch해서 N초 내 재진입 차단 - 모든 실행 로그를 UTF-8 BOM 포함 으로 watcher.log에 남김 (v3.2) - _-prefix 파일은 build.py에서 draft로 취급되어 사이트 배포 대상에서 제외됨. v3.3에서는 추가로 main 브랜치 커밋 단계도 건너뜀 — 테스트 파일이 상위 레포 히스토리를 오염시키지 않도록 이중 방어. - 크로스-스코프 변수 공유가 없어 PowerShell 이벤트 스코프 이슈 원천 차단 - 스크립트 본문이 ASCII-only라 PowerShell 5.1 인코딩 함정도 차단

v3.3 커밋 메시지 (옵션 C):

포맷: blog: YYYY-MM-DD <slot> - <front-matter title 그대로>

예시:

blog: 2026-04-19 am06 - 일요일 아침, Snap 1,000명과 'AI가 못 이기는 영역' — 두 기사를 나란히 놓고 읽다
  • YYYY-MM-DD / <slot>(am06 / pm12 / pm17 / pm22)는 파일명에서 파싱 (2026-04-19-am06-ai-tech-news.md).
  • title은 포스트 첫 ~20라인의 YAML front-matter title: "..." 라인에서 추출 (앞뒤 따옴표 자동 제거).
  • PowerShell 5.1에서 git commit -m "한글 메시지"를 쓰면 CP949로 re-encode되어 커밋 바이트가 깨진다. 그래서 v3.3은 메시지를 X:\Work_Agent\sonslab-blog\tmp\.commit_msg.tmp에 UTF-8 (no BOM) 로 쓴 뒤 git commit -F <file>로 파일째 넘긴다. 커밋 후 tmp 파일은 지워진다.
  • 푸시는 git push origin HEAD:main — 로컬 브랜치명이 뭐든 현재 tip을 origin/main으로 올린다.

v3.3 커밋 범위:

sonslab-blog/posts/만 staged된다 (git add -- sonslab-blog/posts). 이 범위 밖의 변경(예: sonslab-blog/site/, sonslab-blog/scripts/ 수정, 다른 Work_Agent/*)은 이 훅에서 건드리지 않는다. site/는 자체 .git(gh-pages)를 갖고 있어 상위 Work_Agent/.git과 충돌해선 안 되므로 범위 제한이 중요.

테스트 파일(_*.md)은 sonslab-blog/posts/.gitignore로 git 레벨에서도 추적 제외되어 있다.

2단계 — Task Scheduler에 등록 (Windows 부팅 시 자동 시작)

관리자 권한 PowerShell에서 한 번만 실행. Task Action은 워처 스크립트를 직접이 아니라 launcher 래퍼(scripts/launch_watcher.ps1)를 통해 호출한다. launcher가 워처를 자식 프로세스로 띄우면서 stderr를 watcher_launch.err로 리다이렉트하고, 시작/종료 시점을 watcher.log에 [LAUNCHER] 라인으로 기록해, 파싱 에러·시작 실패·런타임 크래시가 조용히 사라지지 않도록 한다.

$Action = New-ScheduledTaskAction `
    -Execute "powershell.exe" `
    -Argument "-NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File `"X:\Work_Agent\sonslab-blog\scripts\launch_watcher.ps1`""

$Trigger = New-ScheduledTaskTrigger -AtStartup

$Principal = New-ScheduledTaskPrincipal `
    -UserId "$env:USERDOMAIN\$env:USERNAME" `
    -LogonType Interactive `
    -RunLevel Highest

$Settings = New-ScheduledTaskSettingsSet `
    -AllowStartIfOnBatteries `
    -DontStopIfGoingOnBatteries `
    -RestartCount 3 `
    -RestartInterval (New-TimeSpan -Minutes 1)

Register-ScheduledTask `
    -TaskName "SONSLAB_Blog_AutoBuild_Watcher" `
    -Action $Action `
    -Trigger $Trigger `
    -Principal $Principal `
    -Settings $Settings `
    -Description "Cowork가 새 .md를 저장하면 auto-deploy.bat 자동 실행"

등록 확인:

Get-ScheduledTask -TaskName "SONSLAB_Blog_AutoBuild_Watcher"

3단계 — 즉시 시작 (재부팅 안 하고)

Start-ScheduledTask -TaskName "SONSLAB_Blog_AutoBuild_Watcher"

몇 초 뒤 watcher.log에 "Watcher started (v3.3 inline mode, Work_Agent commit+push). Monitoring X:\Work_Agent\sonslab-blog\posts" 라인이 찍히면 정상 동작.

4단계 — 테스트

샌드박스에서 새 .md가 posts/에 저장되는 것을 시뮬레이션하려면:

"test" | Out-File "X:\Work_Agent\sonslab-blog\posts\2026-04\_test.md"
Remove-Item "X:\Work_Agent\sonslab-blog\posts\2026-04\_test.md"

5초 뒤 watcher.log에서 auto-deploy.bat finished (exit=0) 확인.

_-prefix 테스트 파일은 사이트로도, main 브랜치로도 안 나간다: 1. gh-pages: build.py가 _로 시작하는 .md를 draft로 보고 collect_posts()에서 skip → gh-pages push에 포함 X. 2. Work_Agent/main: v3.3 워처가 _*.md 트리거를 감지하면 auto-deploy.bat만 돌리고 소스 커밋 단계는 건너뛴다 (Skipping Work_Agent commit: test file (_xxx.md) 로그 확인). 3. 추가로 sonslab-blog/posts/.gitignore에 _*.md가 등록되어 있어 git add로도 스테이징되지 않는다.

테스트 후 로컬 파일만 Remove-Item으로 치우면 됨.

디버깅 팁

watcher.log를 실시간으로 모니터링 (한글이 깨지지 않게 UTF-8 강제):

[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
Get-Content X:\Work_Agent\sonslab-blog\watcher.log -Encoding UTF8 -Tail 20 -Wait

PowerShell 5.1의 Get-Content는 파일에 UTF-8 BOM이 있어도 콘솔 출력 시 기본 코드 페이지(CP949)로 re-encode하여 한글을 깨뜨린다. 위처럼 [Console]::OutputEncoding을 UTF-8로 바꾸고 -Encoding UTF8을 같이 줘야 정상 출력된다. VSCode로 watcher.log를 직접 열면 BOM이 있어 자동으로 UTF-8로 보인다.

워처 수동 중단:

Stop-ScheduledTask -TaskName "SONSLAB_Blog_AutoBuild_Watcher"

watch_and_build.ps1 수정 후 워처 재시작 (간편 스크립트):

# 터미널
powershell -NoProfile -ExecutionPolicy Bypass -File "X:\Work_Agent\sonslab-blog\scripts\restart_watcher.ps1"

또는 탐색기에서 X:\Work_Agent\sonslab-blog\scripts\restart_watcher.bat 더블클릭.

scripts/restart_watcher.ps1은 다음을 한 번에 처리: 1. Stop-ScheduledTask로 Scheduled Task 정지 2. watch_and_build·launch_watcher 이름이 CommandLine에 포함된 orphan PowerShell 프로세스 강제 종료 3. .watcher_cooldown 플래그 파일 제거(새 이벤트가 쿨다운에 물려 스킵되지 않도록) 4. Start-ScheduledTask로 재기동 5. 10초 이내에 watcher.log가 늘어났는지 + [LAUNCHER] start -> 또는 Watcher started 마커가 새로 찍혔는지 교차 검증. 실패하면 watcher_launch.err 앞부분을 함께 출력하고 exit 1

스크립트 본문 수정을 반영하는 가장 안전한 방법이므로, watch_and_build.ps1 또는 launch_watcher.ps1을 편집했으면 반드시 이 스크립트로 재시작한다. 단순히 Scheduled Task를 재시작만 하면 기존 PowerShell 호스트 프로세스가 살아 있는 경우 구 버전이 그대로 도는 일이 있고, 드물게 Task Scheduler가 자식 종료를 놓쳐 State = Running인 stale 상태로 고착된다(2.2절 참고).

시작 실패를 로그에서 확인하는 법: - watcher.log의 [LAUNCHER] start -> ... 이후 [LAUNCHER] child exited code=N 또는 [LAUNCHER] STDERR: ... 라인이 찍혔다면 워처가 시작 중/직후에 죽은 것. - watcher_launch.err에는 자식 프로세스 stderr가 통째로 남는다(파싱 에러·ExecutionPolicy 거부·경로 오류 등). 문제 해결 후에는 자동으로 다음 재시작 때 파일이 비워진다.

왜 Get-ScheduledTask | State = Running을 믿으면 안 되나: - State는 "Task Scheduler 내부가 이 Task를 실행 중으로 기록하고 있는지"만을 나타낸다. 프로세스 생존을 검증하지 않는다. - 자식 PowerShell 호스트가 외부 Stop-Process, 크래시, 혹은 grandchild만 남기고 exit하는 패턴 등 비정상 경로로 종료되면 Task Scheduler가 종료 핸들러를 놓치고 상태가 stale Running으로 남는다 (Get-ScheduledTaskInfo.LastTaskResult = 267009 / 0x41309 / SCHED_S_TASK_RUNNING). - 정확히 보려면 State 대신 다음을 조합한다: powershell Get-CimInstance Win32_Process -Filter "Name='powershell.exe'" | Where-Object { $_.CommandLine -like '*watch_and_build*' -or $_.CommandLine -like '*launch_watcher*' } | Select-Object ProcessId, CreationDate, CommandLine 그리고 watcher.log의 마지막 [LAUNCHER] start / Watcher started 시각이 현재 시각과 분리돼 있지 않은지 확인한다. restart_watcher.ps1의 5단계 검증이 정확히 이 두 신호를 교차 체크한다.
